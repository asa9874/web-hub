# 아키텍처 설계 원칙

## 기술 스택

| 항목 | 내용 |
|------|------|
| 런타임 | Vite + Vanilla TypeScript |
| 게임 엔진 | Phaser 3 (Phaser.AUTO 렌더러) |
| 캔버스 크기 | 800 × 600 px |
| 에셋 정책 | 외부 이미지 없음 — `add.graphics` · `add.text` 전용 |

---

## 핵심 설계 원칙

### 1. 관심사 분리 (Separation of Concerns)

```
Scene (씬)          GameState (상태)
─────────────       ─────────────────
렌더링              HP 계산
입력 처리           마나 소비
드래그·드롭          카드 효과 실행
UI 텍스트 갱신       패 관리
씬 전환             턴 종료 처리
```

씬은 `GameState`의 상태를 **읽기만** 하고,
변경은 반드시 `GameState`의 메서드(`playCard`, `endTurn`, `reset`)를 통해서만 수행한다.

### 2. 데이터 기반 설계 (Data-Driven Design)

카드 효과는 `onPlay` 함수로 카드 객체 안에 캡슐화된다.
씬이나 `GameState`에 `if (cardId === 'strike')` 같은 분기 로직이 **존재하지 않는다**.

```typescript
// 새 카드 추가 = 이 배열에 객체 하나 추가가 전부
const CARD_LIBRARY: Card[] = [
  {
    id: 'heavy_blow',
    name: '강타',
    cost: 2,
    description: '적에게 14의 피해.',
    onPlay: (_user, target) => applyDamage(target, 14),
  },
  // ...
];
```

### 3. 엄격한 타입 정의 (Strict Typing)

모든 게임 데이터 구조는 `src/types.ts`에 인터페이스로 선언된다.
`any` 사용은 Phaser 이벤트 콜백 파라미터에 한해 `unknown` + 캐스트로 처리한다.

## 파일 구조

```
src/
├── main.ts               Phaser 설정 및 씬 등록 (15줄)
├── types.ts              전체 타입 정의 (인터페이스·유니온)
├── GameState.ts          상태 관리 싱글톤 + 카드 라이브러리
├── data/
│   └── dialogues.ts      대화 스크립트 데이터
└── scenes/
    ├── HubScene.ts       테스트 허브 메뉴
    ├── BattleScene.ts    전투 씬
    └── DialogueScene.ts  비주얼 노벨 대화 씬
```

---

## 의존 관계

```
main.ts
  ├── HubScene
  ├── BattleScene ──── GameState ──── types.ts
  └── DialogueScene ── dialogues.ts ─ types.ts
```

씬끼리는 직접 참조하지 않고 Phaser `scene.start / pause / launch / resume` API로만 통신한다.

---

## 확장 지침

| 추가하고 싶은 것 | 수정할 파일 |
|-----------------|-------------|
| 새 카드 | `GameState.ts` — `CARD_LIBRARY` 배열에 객체 추가 |
| 새 대화 스크립트 | `data/dialogues.ts` — `DIALOGUE_SCRIPTS` 객체에 키-값 추가 |
| 새 씬 | 씬 파일 생성 후 `main.ts` scene 배열에 등록 |
| 새 적 | `types.ts` Entity 확장 후 `GameState`에 초기값 추가 |
