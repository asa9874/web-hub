# 관찰 플레이 UI v0.5

후속 화면 구조: [고정 뷰포트·패널 내부 스크롤](GAMEPLAY_LAYOUT.md). 아래는 최초 연결 당시의 기록이다.

2026-10-24. 첨부의 첫 지시인 **현재 구현된 기능으로 조작 가능한 v0.5**를 우선했다. 뒤에 첨부된 전체 v1의 플레이어 생성·자동 생활·직접 상호작용·학사·전투·아이템을 새로 만들지 않았다.

## 사용과 실제 연결

1. 아카데미 기본 페이지에서 시드·초기 NPC1~20명(기본5명)을 선택해 **새 관찰 플레이 시작**. 기존 기준 플레이어·고정 미리보기·시드 생성 NPC를 사용한다. 정식 캐릭터 생성이나 고정 인물 랜덤 슬롯 확정이 아니다.
2. 제국력427년3월1일08:00에서 시간·실제 이동·현장 NPC·기록을 조회한다. `?view=play`가 일반 화면, 기존 설정집/개발 시뮬레이터 경로는 유지한다.
3. +10분/1시간/6시간/1일/7일은 공통 시계를 진행한다. 일시정지·메뉴 전환·탭 숨김은 남은 진행을 중단한다. 화면이나 메뉴를 여는 것만으로 시간을 진행하지 않는다. 요청량/실제 진행량을 구분한다.
4. 장소를 고르면 기존 경로·출입 API의 예상 시간·경유지를 보고 이동한다. 즉시 도착시키지 않으며 **도착까지 진행**으로 같은 세계 시간을 소비한다. NPC도 그 시간 동안 기존 엔진으로 생활한다.
5. 주변 인물은 같은 직접 장소의 정지 인물만 보여 준다. 자신의 상세는 공통 상태창, NPC는 제한된 관찰 팝업을 사용한다.
6. 공개 설정집은 기존 달력 환산/공식 설정·수치 체계를 재사용한다. 전체 개발 설정집/시뮬레이터는 명시적인 개발 자료 메뉴로 접근한다. 돌아와도 게임 세션은 유지된다.
7. **저장·이어하기**에서 로컬3슬롯에 수동 저장하고 새로고침 후 이어한다. 새 게임은 기존 슬롯을 수정하지 않는다.

## 구조·파일

- `AcademySurvival.tsx`: 타이틀 시작·플레이 경로·복귀와 기존 설정집 경로 연결. 세션이 없을 때는 기존 기준 세계 Provider를 유지한다.
- `components/PlaySessionContext.tsx`, `playSessionHooks.ts`: 플레이 세션 수명·시작/저장/로드. `LiveWorldProviders.tsx`: 단일 런타임의 시계/위치/관계/일과/욕구/AI를 기존 Context에 바인딩한다. 엔진을 두 번 연결하지 않는다.
- `LocationWorldContext.tsx`, `RelationshipContext.tsx`: 기존 공개 API를 유지하면서 이미 연결된 런타임용 Provider 바인딩을 노출했다. 기존 혼합 Context 모듈의 공개 읽기 hook 이름만 Fast Refresh 규칙의 명시적 예외로 등록했다. 전체 규칙/게임 검사는 끄지 않았다.
- `systems/playSession.ts`: 일반 플레이 명령 경계, 중복 진행 잠금, 공통 시간 호출·yield, 저장/로드·인지 기록 보존. 강제 배치/욕구 편집 같은 개발 명령을 일반 UI에 제공하지 않는다.
- `systems/playerViews.ts`: 현재 위치/직접 관찰/나에게 부여된 기억/내 방향성 관계/내 이동만 투영한다. UI가 NPC 원본 모델을 받지 않도록 한다.
- `components/Gameplay.tsx`, `Gameplay.css`: 시작·상태·장소·인물·기록·공개 설정집·저장·시간 패널, 어두운 텍스트 UI·모바일 단일열·간결한 카드/팝업.
- `CalendarCatalog.tsx`: 공개 참조에서 테스트 버튼을 생략할 수 있게 선택적 callback. 기존 개발 설정집의 테스트 버튼은 유지한다.
- `systems/memoryPresentation.ts`: 이미 알려진 세계 사건을 내부 코드 대신 사람이 읽는 명칭으로 표시한다. 기억/사건 생성 규칙은 바꾸지 않았다.
- `scripts/test-academy-play.mjs`, `test-academy-play-browser.mjs`, package 명령, 자동 검증 레지스트리의 play/archive 분류, 기능 노트33시스템/227항목 및 진입/현황 문서를 갱신했다.

새 게임은 개발 시뮬레이터의 상태를 복사하지 않고 기존 `createWorldSimulation`/신규 세계 조합으로 초기화한다. 설정집도 같은 런타임을 소비하며 개발 시뮬레이터만 이 실제 게임 상태를 복제한다. 별도의 UI 시계·NPC·능력치·이동/성공 판정을 만들지 않았다.

## 정보·기록·저장

- NPC의 능력치/성향/비밀 소속/실제 욕구·목표·개인 기억·타인의 감정 수치는 일반 팝업에 전달하지 않는다. 공개 소속/관찰 가능한 활동과 플레이어 자신의 방향성 관계만 표시한다. 멀리 있거나 이동 중인 인물은 현장 목록에 넣지 않는다.
- 장소 이름/설명/출입 정책은 기존 공식 도감의 정적 정보를 사용한다. 미방문 지역의 현재 인원이나 NPC 위치를 보여 주지 않는다. 별도 지도 발견 시스템은 구현하지 않았다.
- 사건 표시는 플레이어에게 **이미 생성된 직접/목격/전달 기억**과 실제 자신의 이동 로그를 쓴다. 플레이어가 모르는 세계 사건을 전역 기록에서 가져오거나, 현재 위치로 과거 목격자를 만들지 않는다. 관찰 가능한 사건이 없으면 빈 상태를 표시한다.
- 엔진의 이동 진단 로그는 원래 저장되지 않는다. 이를 발견해 실제로 인지한 표시용 기록을 최근200건 보존하고 화면에는60건만 표시한다. 조회 중에는 기록이나 세계를 변경하지 않으며 명령/시간 처리 시 수집한다. 로드 세대가 다른 이동 로그 ID를 분리해 충돌을 막고 원래 기록을 소급 생성하지 않는다. 이 기록은 NPC 기억·AI 판단이나 관계 효과를 대신하지 않는다.
- 저장은 `academy-play-v0.5` wrapper에 기존 전체 `world-simulation-v1` 상태·플레이어 참조·인지 기록을 담는다. 기존 `ai-sandbox-v1` 하위 저장 계약은 유지한다. 선택적인 기록 필드가 없는 초기 v0.5 wrapper도 허용한다.
- 키는 `web-hub.academy.play.v0.5.slot.1~3`. 개발 테스트 저장과 공유하지 않는다. 손상/지원하지 않는 저장·잘못된 플레이어·저장소 접근/용량 오류를 표시한다. 로드 실패는 현재 세션을 교체하지 않는다. 저장 시각의 현실 시각은 메타데이터뿐이며 게임 시간/RNG 계산에 쓰지 않는다.
- 시간 처리 중 저장/이동/중복 진행을 거부한다. 오류가 난 부분 세계를 정상 저장으로 만들지 않는다. 자동 저장/클라우드 동기화는 없으며 저장 버튼 이후의 진행은 다시 수동 저장해야 한다.

## UI 응답성

공통 예약 시간 엔진을 짧은 적응형 구간으로 호출한다. 긴 요청은 프레임 사이에 브라우저에 제어권을 반환하며 주요 플레이 화면 갱신을 약250ms 간격으로 제한한다. 메뉴/비가시 탭에서 진행을 계속하지 않는다. 저장 복원으로 시계/난수/예약을 재구성하며 조회 중 AI를 평가하지 않는다. 기존 상단 날짜 읽기는 같은 시계에 연결된다.

이는 엔진 처리량이나100명7일 목표 달성 주장과 다르다. NPC 행동/기억/사건/이동을 비활성화하지 않았다. 소규모 조작 검증을100명 장기 성능으로 확대하지 않는다.

## 이번 검증

- API 계약3명: 고정 시작 시각, 조회/RNG 무변경, 원격/비공개 투영 제외, 실제4분 경로 이동·중복/경로 거부, 전체 JSON 저장/복원 후 동일 이어짐, 슬롯 격리, null/손상/용량 오류, 진행 중 저장/중복 요청 거부, 일시정지.
- 공개 세계 이벤트 fixture: 실제 `overwork` 사건 완료와 실제 플레이어 목격 기억 생성, 그 인지 여부에 맞는 기록 표시를 확인했다. 새로운 사건/확률/정보 전파 규칙을 만들거나 눈치채지 못한 사건을 강제로 알리지 않았다.
- 일시정지 검사에서7일을 **요청**했지만 실제 약31분 후 중단했다. 이를7일 시뮬레이션 검증으로 세지 않는다.
- 실제 브라우저3명: 기본 페이지→새 세션→자기 상태 팝업→1시간→교실까지4분 실제 이동→현장 인물 제한 팝업→6시간→나의 기록→저장→추가10분→슬롯 복원→새로고침/이어하기→기록 유지→공개 달력 환산→전체 설정집의 동일15:04 시계→복귀.
- 이어서 개발 시뮬레이터에서 플레이어를 마계로 강제 배치하고1분 진행한 뒤 종료했다. 실제 게임의 시각/교실 위치는 그대로 유지됐다. 모바일390px 가로 넘침·브라우저 pageerror 없음, 데스크톱/모바일 캡처 확인.
- 이동 불가 지역을 미리 본 뒤 현재 상황으로 돌아왔을 때 선택 목적지를 현재 위치처럼 표시하던 경계를 수정했다. 저장 전 기록이 복원 후 비던 문제는 인지 기록 보존으로 해결했다. JSON의 undefined 키 생략은 의미 없는 차이로 정규화해 검사하며 실제 세계 상태 차이를 무시하지 않는다.
- 추가 기존 계약: 통합 세계/자동 검증/기능 레지스트리의 직접 영향 검사. 통합 세계 계약의10/50/100명은 각각10분 단기이며100명 장기 실행이 아니다.
- 타입 검사·변경 파일 ESLint·Vite 빌드·배포 산출물 참조 검사가 통과했다. 기존500kB 초과 청크 경고와 장기 성능 미달은 별도 미해결 범위다.

명령: `npm run test:academy-play`, `npm run test:academy-play-browser` (`ACADEMY_TEST_URL`에 해당 Vite base 지정). 원본 `test-results/academy-play-{contract,browser,types,lint,features,world-contract,validation,build}.log`, 결과 `test-results/academy-play/contracts.json`, 화면 `test-results/academy-play/{records-desktop,mobile}.png`.

## 미연결·미검증

정식 플레이어 생성·생활 방침/자율 생활·직접 대화/선물/미래 약속·수강신청/성적·동아리 운영·정식 전투·인벤토리/장비·일일/주간 성과 보고·플레이어 중요 선택 중단은 구현하지 않았다. 해당 작동 버튼이나 성공 모형을 넣지 않고 화면의 범위를 설명한다. 기존 NPC 일과/자율 AI/상호작용/성장/관계/기억/세계 사건은 계속 실행된다.

100명 장기·7일 전체 실제 플레이·기존 전체 브라우저 회귀·10년 저장 누적/재미 검증은 새로 수행하지 않았다. 이 결과는 전체 플레이 v1 완성이나 성능 목표 달성을 뜻하지 않는다.
