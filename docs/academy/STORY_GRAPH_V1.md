# 동적 사건·히로인 서사 그래프 v1

## 구현 범위와 진입점

- 일반 플레이 **설정집 → 인물 서사**: 고정15명 선택, 알려진 실제 사건의 서사 그래프/나의 연대기. 캐릭터 상세의 인물 서사에도 같은 컴포넌트를 사용한다.
- 개발자 **시뮬레이션 → 고정 학생·개인 서사**: 선택 인물 또는 아카데미·세계 서사 전체, 설계 그래프/실제 회차 그래프/연대기. 기존 아카데미 사건망의 단순 고정3열 그림을 대체했다.
- 세레나의 기존22사건을 그대로 읽는다. 생산 카탈로그에서는 기존 연계 사건1건도 범위에 들어와23노드가 표시된다. 다른14명은 기존 실제 개인/연계 정의를 표시하며, 새 심화 루트 콘텐츠를 완성한 것이 아니다.

별도 그래프용 사건 데이터·새 확률 엔진·새 저장 도메인은 만들지 않았다. 세계 이벤트 정의/인스턴스/실제 인과관계/후속 기회와 기억이 원본이다. 조회와 그래프 조작은 사건을 실행하거나 RNG·회상·관계·성장을 변경하지 않는다.

## 기존 동적 엔진 재사용

기존 엔진은 이미 조건·실제 참가자·위치/의식·쿨다운/예산을 검증하고, 선언된 평가 기회에서 시드 기반 추첨을 한다. 결과 후보의 조건을 검사하고 가중치를 적용하며, 후속 규칙은 분기·AND/OR 합류·지연·변경·우회·차단을 지원한다. 이번에 확률표를 모든 사건에 덮어쓰거나, 확정 학사 일정/실제 승패를 임의 랜덤 결과로 바꾸지 않았다.

이번 보강은 `WorldEventInstance.branchAudit`다. 실제 결과 판정 시에만 다음을 보존한다.

- 후보별 조건의 당시 통과 여부
- 기본 가중치, 기존 원인 기반 `outcomeWeights` 배율, 최종 유효 가중치
- 기존과 동일한 독립 시드 스트림의 0~1 추첨값과 선택한 결과 ID
- 실제 판정 세계 시각

불가능한 후보는0가중치로 제외한다. 가능한 후보가 없으면 추첨하지 않고 기존 실패 처리를 유지한다. 추첨 선택과 효과/활동 완료는 다르며 UI에서도 구분한다. 저장 시 선택 필드로 보존하고 구형 저장에는 과거 추첨 정보를 꾸며 넣거나 재추첨하지 않는다. 손상된 감사 기록은 실제 상태를 변경하기 전에 거부한다. 공개 인스턴스 투영에서는 감사 기록을 제거한다.

개발자 노드 상세와 기존 세계 이벤트 상세에서 당시 후보별 정규화 확률·가중치·선택을 조회할 수 있다. **미발생한 모든 트리거 기회의 추첨 실패·미충족 이유를 영구 보존하는 새 감사 원장은 추가하지 않았다.** 기존 처리 키·예약·유한 로그와 현재 조건/후속 기회를 구분해서 본다.

입학 상대60/20/10/10 예시는 새 콘텐츠 요구로 강제하지 않았다. 현재 입학은 순수 자질 평가이므로 이를 실제 대련 시험으로 바꾸려면 별도의 학교 규칙·배역·전투 동의 설계가 필요하다. 모든 기존 행사·히로인에 무작위 가지를 대량 증설한 작업도 아니다.

## 그래프 투영

`systems/storyGraph.ts`:

- `storyDefinitions`: 실제 소유 인물/기존 개인 서사 카탈로그/실행 정의로 범위를 구성한다.
- `designStoryEdges`: 참여/트리거/단계/결과/선택 조건의 사건 참조와 후속 규칙·활성 조건·합류 참조를 추출한다. AND/OR/NOT과 enables/blocks/continues/contributes를 표시한다.
- `getDeveloperStoryGraph`: 정의상의 가능 관계 또는 실제 인스턴스/관계/대기·차단·만료된 후속 기회를 투영한다. 상태는 진행 가능·미발생·잠금·연동 보류와 실제 완료/실패/취소 등을 구분한다. 현재 조건은 지정된 인물/상대 문맥의 판정이며 모든 참가자 조건을 전지적으로 충족시켰다는 뜻이 아니다.
- `getPlayerStoryGraph`: 정의 객체를 넘기지 않는 허용 목록 DTO다. 직접 경험·목격·실제로 얻은 정보, 직접 참가 중인 장면과 당사자의 보존된 장면 기록만 허용한다. 미발견 노드 수/제목/조건·미래 경로/추첨/내부 평가는 전달하지 않는다.
- 전해 들은 사건은 정보 습득 시각과 불확실성을 표시하며, 실제 비밀 장소·참가자·결과·선택·대사를 노출하지 않는다. 두 끝을 직접 아는 실제 인과관계만 플레이어 연결선으로 표시한다. 모르는 원인을 유추해 가짜 역사로 연결하지 않는다.
- `layoutStoryGraph`: 정의 ID별 노드 공유, 안정적인 의존 계층 배치와 다중 부모 합류. 같은 계층은 최대3열로 줄바꿈하고 연결선을 노드 사이 여백으로 우회하여 다른 사건을 가로지르지 않도록 했다. 설계의 반복 참조는 제한된 별도 배치로 처리하며 실제 회차의 시간·순번 DAG 검증을 바꾸지 않는다.

## UI

공통 `StoryGraph.tsx`/CSS와 `HeroineGraphCatalog.tsx`, 개발자용 `EventBranchAudit.tsx`를 재사용한다.

- 중요도는 테두리, 장르/히로인 종류는 별도 라벨, 진행 상태는 아이콘/명암/선 종류로 구분한다.
- 확대/축소, 빈 캔버스 포인터 드래그와 스크롤, 키보드 노드 선택, 검색·인물·종류·연도·중요도 필터.
- 선택 노드 상세: 알려진 시각/장소/참가자/실제 결과·선택·대사/보유 기억. 개발자만 전체 조건·후속·선택 규칙과 당시 감사 정보를 확인한다.
- 앞뒤 사건 집중, 후속 경로 접기/펼치기, 연대기에서 동일 실제 노드로 이동.
- 최대80노드씩 부분 표시/이전·다음 묶음. 거대한 전체 기간을 한 번에 렌더링하지 않는다. 접기·선택·확대 같은 화면 취향은 세이브에 추가하지 않고 실제 사건 상태로 재구성한다.
- 기존 양피지 설정집 CSS가 다크 그래프에 침범하는 대비 문제를 실제 화면에서 수정했다.

## 2026-10-27 인과 그래프 UI 재구성

- 세계 이벤트 도감의 카드 목록을 제거하고 첫 화면에 `CausalGraphCanvas`를 표시한다. 정의의 조건·후속 참조에서 추출한 연결만 표시한다. 기본은 연결된 사건 흐름이며 독립 사건 수와 포함 전환을 제공한다. 정의 그래프는 실제 발생 기록과 명시적으로 구분한다.
- 히로인/아카데미 서사와 세계 실제 기록 모두 같은 원형 노드·곡선 화살표 캔버스를 사용한다. 동일 깊이의 형제 노드를 3열로 줄바꿈하지 않고 분기·합류를 그대로 배치한다. 중요도 테두리와 상태 기호를 분리한다.
- 처음에는 너비 맞춤으로 읽을 수 있는 크기를 확보하고 내부 스크롤로 탐색한다. 전체 보기/너비 맞춤·확대/축소·드래그·키보드 선택과 노드 상세를 제공한다. 검색/필터는 접힌 상태이며 실제 기록의 기본 탭도 그래프다.
- 기존 공개 투영·기억·인과관계·저장/RNG는 변경하지 않는다. 80개 서사/최근100개 실제 기록 표시 제한 유지.
- 검증: 기존 서사/개별 지식/분기 감사/저장 검사 및 6분기→단일 합류·원형 SVG 렌더링 검사. 이번 브라우저 시도는 localhost 연결 시간 초과로 화면/입력 확인 미완료. 과거 브라우저 통과 기록과 구분한다. 타입 검사와 전체 빌드 통과(38프로젝트/39메타데이터/182참조). 기존 대형 청크·배경 경로 경고가 남는다. 빌드 결과는 `test-results/academy-graph-redesign-build.log`.
