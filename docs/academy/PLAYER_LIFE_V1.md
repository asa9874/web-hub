# 플레이어 캐릭터·행동 v1 — 구현 및 검증 범위

2026-10-24. 기존 관찰 v0.5 위에 실제 생활 제어를 연결했다. 전체 아이디어 노트의 완전 구현은 아니며 사건별 전용 분기·상세 보고·장기 검증은 아래에 구분한다. 기존 작업 트리의 세계 이벤트/LOD/검증 변경은 되돌리지 않았다.

## 사용

기본 화면에서 이름·성별/외형·능력 성향·세계 시드·NPC 수(생활 모드1~100명)를 입력하고 **새 생활 시작**. 기존 관찰 모드는 접힌 메뉴에서 계속 사용할 수 있고 이전3슬롯도 읽는다. 실제 화면의 **나의 생활**에서 방침·자동/수동·공부/훈련/휴식/취침/식사/대기·공동 활동을 조작한다. 위치/인물 열람은 시간을 소비하지 않는다. 직접 이동은 기존 장소 메뉴를 사용한다.

새 플레이어는 기존 NPC 생성기의 시드·1학년·ordinary·능력 선호 규칙으로 생성한다. 이름/외형과 공통 kind를 바꾸고17세·아카데미 중앙광장·거주지 기숙사로 등록한다. 별도 능력치/숙련도/욕구/성장 공식을 만들지 않는다. 고정 인물의 설정을 바꾸지 않는다. 초기 방침35/35/20/10은 시작 후 편집할 수 있으며, 상세한 생성 전 방침 편집은 제공하지 않는다.

## 설계와 실제 실행

- `playerLife`는 결정 권한 어댑터다. 같은 `worldSimulation.runtime`의 캐릭터·시계·AI·일과·이동·동기·관계·상호작용·효과·기억을 참조한다.
- 기존 AI의 플레이어 제외는 기본으로 유지하고 명시적으로 `setPlayerPolicy`한 플레이어만 공통 AI에 등록한다. NPC 기본 계산에는 방침을 적용하지 않는다. 실제 플레이어는 LOD의 비개별 집계 인구가 아니다.
- 방침은 자유시간 후보에 `(해당 가중치-25)×0.65`를 추가한다. 기존 일과/욕구/목표/이동/위험/유지 비용과 의무·긴급 우선 정책을 유지한다. 같은 출처 중복 가산 규칙은 그대로다. 사교는 실제 같은 장소의 유효한 상대·공통 상호작용 후보로만 제안한다.
- 자동 모드는 기존 예약 AI가 다음 판단을 실행한다. 수동 모드는 그 인물의 AI만 정지하고 기본 일과의 새 자동 선택을 억제한다. 현재 수행 중인 활동은 모드 변경만으로 취소하지 않는다. 선택한 개인 활동을 자동으로 전환해도 종료까지 유지하고 이후 자동 판단을 재개한다.
- 수동 활동도 `startAutonomousActivity` → 실제 경로·도착 시점 출입 → 활동 시작 → 실제 구간 적분 → 정상 완료 효과의 동일 경로다. 장소 용도/상태 차단/잘못된 시간은 오류로 표시한다. 이동 시간은 수행 시간에 추가된다. 주변 살펴보기는 기존 현장 관찰 UI이며 시간 비용을 만들지 않는다.
- 식사/휴식/취침의 욕구 효과는 기존 동기 엔진이 실제 활동 구간만 적분한다. 공부/훈련 성장은 기존 버전별 완료 효과 엔진만 적용한다. AI/플레이어가 별도로 보상하지 않는다.
- 명시적 행동 중단은 공통 일과·이동·상호작용 엔진으로 처리한다. 개인 활동은 남은 분을 보관해 새 수행 구간으로 재개한다. 중단한 구간에는 완료 XP를 지급하지 않고 재개한 잔여 구간만 완료 보상을 받는다. 수업/공동 활동은 임의로 되살리지 않는다. 잠시 세계 시간을 멈추는 것은 활동 중단과 다르다.
- 날짜까지 진행은 기존 절대 분으로 변환하며 미래의 유효한 날짜를 실제로 처리한다. UI 양보는 처리량 개선이 아니다. 중요한 사건/수동 정지에서 요청의 남은 시간은 **남은 요청 진행**으로 이어갈 수 있다. 실제 진행이 적으면 요청 전체를 완료로 기록하지 않는다.

## 중요한 사건과 선택의 범위

기존 공통 시계에 `stopAfterBoundary`를 추가했다. 현재 경계의 엔진 처리 순서를 마친 뒤 미래 시각으로 넘어가지 않는다. `worldSimulation.advance`도 조기 종료한 시간을 실제 반환한다. 시뮬레이터의 배속/구간 진행도 실제 경과량을 사용한다. 일반 NPC 세계는 중단을 요청하지 않으면 기존과 같다.

플레이어 제어 어댑터는 실제 보유 기억과 자기에게 도달한 직접 공동 활동 요청만 확인한다. 기억 중요도/직접 관련 여부/중단 정책, 실제 골절·탈진 상태를 사용한다. 먼 곳의 전역 사건 목록으로 알림을 만들지 않는다. 플레이어 AI의 결정 직전에도 같은 대기 게이트를 검사해 인지한 중요 사건에 자동으로 먼저 응답하지 않도록 한다. 다른 NPC의 예약 처리는 같은 세계 시각에서 계속 일관되게 처리된다.

직접 요청은 실제 상호작용의 proposed 상태에서 **수락/거절**을 기다린다. 동의는 선택적 알림 설정과 별개로 항상 명시적이다. 수락 시 기존 위치·피로·의무·상태를 다시 검사하고 실제 양쪽 활동을 시작한다. 거절 또는 활동 실패는 기존 도메인 사건/재계획으로 반영한다. 기존 이벤트가 해당 상호작용을 기다리는 경우 그 실제 상태/결과를 따른다. 요청 수락이 모든 미래 활동의 영구 동의가 되지는 않는다.

기억 알림은 **확인·기존 행동 계속 / 행동 중단·직접 조작**을 제공한다. 이것만으로 사건 성공/화해/후속 분기를 만들어내지 않는다. 개별 세계 이벤트의 전용 선택지·플레이어 능력 판정·맞춤 결과·임의 사건 개입은 아직 연결하지 않았다. 따라서 기능 노트의 사건별 선택 분기는 **부분 구현**이다. 알림은 최대32건 대기, 최근512키로 중복 방지한다. 동일 위험 상태의 제거 후 재발 알림 세분화도 후속이다.

## 요약·저장·시뮬레이터

- 실제 시간 구간에서 플레이어가 활동 중이었던 분을 누적한다. 진행 요청 전후 능력/숙련도/욕구 변화, 관계가 변했는지, 보유 기억 증감을 요약14건에 남긴다. 이동 중은 수행 시간에서 제외한다. 보유 기억 수 변화는 새 사건 총수와 다르며 망각/보존 한도 영향을 UI에 명시했다.
- 요약은 요청 구간 기준이다. 일자별 분해·만난 인물의 별도 목록·상세 관계 델타·학사 성과/다음 일정까지 갖춘 일일/주간 보고서는 미완료다. 없는 성적/사건을 요약하지 않는다.
- 기존 `academy-play-v0.5`3슬롯 wrapper에 선택적인 `playerLife: player-life-v1`을 추가했다. 공통 AI 저장에는 명시적 플레이어 정책, 일과 실행 저장에는 플레이어 제어, 상호작용 저장에는 동의 대상 ID가 추가된다. 필드 없는 이전 관찰 저장은 기존처럼 읽는다. 새 생활 저장에서 생활 블록이 누락되면 자동 동의 없는 상태로 조용히 진행하지 않고 거부한다.
- 정책/모드/개인 활동·재개 시간/대기 선택/중복 알림 키/누적 활동·요약과 기존 세계·효과 원장·성장·예약·RNG를 같이 복원한다. 잘못된 수치·참조·요약·손상된 생활 저장은 거부한다. JSON의 undefined 생략은 의미상 정규화하여 비교한다.
- 기존 세계 시뮬레이터는 실제 세션을 깊이 복제하고 같은 제어 어댑터를 부착한다. **플레이어 포함 새 세계**, 자동/수동, 학습 요청, 행동 중단, 대기 응답을 지원한다. 실제 게임을 변경하지 않는다. 별도 생활 엔진/시뮬레이터를 복제하지 않았다.

## 이번 검증과 한계

100명 NPC+플레이어1명 초기 등록과101명 공통 AI 등록도 검사했다. 이는100명 장기 시간 진행 검증이 아니다.

검증 로그는 `test-results/academy-player-*.log`, 계약 결과는 `test-results/academy-player/contracts.json`, 화면은 같은 폴더의 `desktop.png`, `mobile.png`다.

- 플레이어 계약: 실제 공통 생성/일과·AI 등록, 방침 합계/후보 점수·조회 무변경, 도서관 실제 이동, 공부 완료 효과, 중단 무보상/잔여 재개, 실제 목격 기억 시각에서 중단(60분 요청 중8분), 대기 선택 저장, 요청 수락/거절·양쪽 활동 완료,60분 단일/분할 세계 상태·활동 시간 일치, 전체 JSON 이어 진행 동등성, 손상 저장 거부.
- 3명 NPC+플레이어 하루 자동 생활: 실제 수업390분, 학습274분, 수면421분 등 기록. 테스트에서만 명시적 응답 정책으로1건 확인했다. Windows/Node22.18 단회 짧은 검사 약0.9초였으며, 대표100명 성능/개선율/장기 안정성 측정은 아니다.
- 실제 브라우저3명: 이름 입력→생활 시작→수동 공부→실제 도서관 이동/완료→방침40/30/20/10 적용→자동1시간→실제 요약→슬롯 저장→새로고침/복원→방침 유지. 시뮬레이터 제어·플레이어 새 세계 후 종료 시 실제 시각 불변.390px 넘침·pageerror 없음.
- 기존 관찰 계약, 배치 제외 AI(`AI_SKIP_BATCH=1`), 상호작용/효과, 시간·달력, 통합 세계10/50/100명 각각10분, 자동 검증/기능 레지스트리 검사 통과. 새 player-autolife 시나리오도 실제 실행한다. 기존 모든 브라우저/장기 검사를 반복한 결과가 아니다.
- 타입 검사·변경 코드 ESLint·Vite 빌드/정적 배포 참조 검사가 통과했다. 기존 큰 청크와 다른 공통 CSS의 `.animate-*` 문법 경고는 남아 있으며 이번 범위에서 타 게임을 수정하지 않는다.
- NPC100명+플레이어360일, 대표100명 하루/7일 목표,10년 누적 저장·게임 밸런스는 **미실행/미검증**이다. 공통 정책에 따라 기존30일/9일 결과를 다시 실행하거나 새 플레이어 검증으로 표시하지 않았다. 장기 검증은 짧은 실제 플레이 계약이 마련된 현재 상태를 기준으로 별도 계획해야 한다.

주요 API: `createPlayerCharacter`, `createPlayerLife`, `setPolicy`, `setMode`, `act`, `interrupt`, `resume`, `respond`, `requestInteraction`, `baseline/summarize`, `save`; 플레이 세션의 `playerCommand`, `advanceUntil`, `advanceToActionEnd`. 향후 사건 정의별 선택 어댑터·세부 보고와 장기 성능 검증을 이 경계에 연결한다.
