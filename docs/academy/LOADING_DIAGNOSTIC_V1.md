# 브라우저 연결·초기 로딩 진단 (2026-10-27)

## 연결 실패 원인

샌드박스 내 Node HTTP 요청은 `EACCES connect 127.0.0.1`로 즉시 거부됐다. 제한 밖 요청에서도 샌드박스 서버5200/5201은 ETIMEDOUT. 제한 밖에서 로컬 전용 서버5202/5203을 실행하자 HTTP200과 Codex 브라우저 접근이 정상화됐다. 따라서 이전 브라우저 연결 실패는 앱이 모든 요청을 무한 처리한 증거가 아니며 실행 환경 경계 문제로 분류한다. 방화벽이나 외부 공개 바인딩을 변경하지 않았다.

## 별도의 실제 성능 문제

같은 PC/Node22.18.0, 빌드가 실행되지 않는 상태의 단일 측정:

| 대상 | 실측 |
| --- | --- |
| 미리보기 HTML 2회 | 88.8 / 11.2ms |
| 공통 진입 JS 2회 | 37.0 / 35.5ms |
| 아카데미 JS 2회 | 98.2 / 95.5ms |
| 공통 진입 JS 해제 크기 | 1,094,211bytes |
| 아카데미 JS 해제 크기 | 2,624,420bytes |
| 준비 fixture 번들 Node import | 391.7ms |
| 25NPC+플레이어 초기화 | 1,945.5ms |
| 100NPC+플레이어 초기화 | 10,613.9ms |

서버 전송은 gzip으로 응답한다. 위 bytes는 fetch가 압축 해제한 본문이며 wire 크기가 아니다. HTTP시간은 브라우저 파싱/렌더링 시간이 아니다. Node fixture import 또한 브라우저 초기 로딩 시간의 대체 지표가 아니다. 인구별 평균/최악값,100NPC AI 시간 진행이나 오래된 세이브 로딩을 측정한 것이 아니다. 100명 신규 세계 생성의 지연은 실제로 확인된 문제다.

25명 초기화의 짧은 CPU 프로파일에서 structuredClone이 최상위 self cost였다(약241ms). 호출 경로는 초기 일과 조회/계획 검증, 일상 후보·경로 탐색, 욕구 조회, 초기 도메인 알림/관찰 등으로 분산된다. 이 표본만으로100명10.6초 전체의 원인을 한 함수로 확정하지 않는다.

## 실제 브라우저

빌드 미리보기에서 새 게임 자질 생성→D반 평가→생활 진입 정상. 입력+AX반환 왕복은 각각 약0.54/0.47/1.03초였으나 자동화 왕복을 포함하므로 정밀 프레임/엔진 성능 수치로 사용하지 않는다. 비주얼→텍스트→비주얼 왕복 후08:00 유지.1280×720 화면/활동 시트 캡처, Escape 닫기 확인. 기존 사용자 저장 슬롯을 덮어쓰지 않았다.

## 개선 방향과 이번 범위

1. 샌드박스 연결 오류부터 판별해 브라우저 재시도 낭비 방지: 적용/정상 접근 확인.
2. 초기화의 반복 스냅샷 복사·읽기 경로와 NPC 단위 등록 후 재구축을 계측해 증분/배치 초기화 검토: 미적용.
3. 공통 진입의 다른 게임 정적 import 및 아카데미 개발 도구/도감 화면을 지연 로딩해 초기 JS 부담 감소: 미적용.
4. 초기화 작업에 로딩 진행 피드백/입력 양보가 필요하나, 연출만 바꿔 실제 계산이 줄었다고 보고하지 않는다.

큰 엔진 구조 변경이나 장기 시뮬레이션을 이번 진단에서 수행하지 않았다. 개선 후에는 같은 시드·인구의 세계 스냅샷/초기 결정·저장 계약과 측정값을 비교해야 한다.
