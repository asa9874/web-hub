## 디자인·입력 계약

`components/GameInterface.css`: 잉크색 배경/청회색 패널·오래된 금색 선택/초록 회복/붉은 경고, 고운 폰트의 기존 체계, 명확한 제목/보조 문구·버튼 상태를 재사용한다. 외부 UI 라이브러리나 신규 이미지 없음. 배경은 기존 대련장 자산, 없으면 동일 크기 단색을 유지한다.

- 고정 HUD/전체 문서 스크롤 금지·패널별 스크롤 유지. 팝업 포커스/ESC/복귀는 기존 dialog를 사용한다. 전투 중 닫기는 제공하지 않고 자동 종료를 선택할 수 있다.
- 전투: 상단 배경/최근4로그/양측 정보는 유지하고 행동 목록만 내부 스크롤. 가능한 행동을 검술/마법/방어/전술로 구분하고 미지원 행동은 하단에 이유와 함께 접어 둔다. 자신의 자원은 숫자, 상대 숨은 수치는 정성적으로 표시한다.
- 사전 전투 방식은 직접/자동. 직접은 전체 전투 동안 팝업, 선택하면 정확히 다음 라운드까지 진행한다. 자동은 별도 팝업 없이 완료한다. 팝업에서 자동으로 바꿀 수도 있다. 결과는 기존 기록/전투 로그에 남는다.
- 지도: 실제 이동 엣지만 선으로 표현. 공간 포함 관계로 통로를 생성하지 않는다. 드래그6px 이상은 노드 선택을 일으키지 않는다. 휠/확대·축소/지역/검색/개별 방/내 위치·키보드 선택 지원. 연결/현재 위치·출입 제한을 색+문구로 구분한다. 선택 시 실제 경로·도착 시각 접근을 다시 검사한다. 전체 보기에서는 노드가 작으므로 확대/검색/상세 패널을 사용한다.
- 과목: 학점/권장 학년/난도/평가·선수 과목/교수/장소/정원/선발을 공통 구조로 표시한다. 시간표는 실제 확정 강의만 칠하며 빈 칸을 가짜 일정으로 채우지 않는다. 모바일의 주간 표는 그 칸 안에서 가로/세로 스크롤한다.
- 주변 영향력:0~100회색,101~200다음 색 등100점 간격, 동점ID 안정 정렬. 계산식은 기존 영향력 엔진이며 전투력으로 바꾸지 않는다.
- 모션은150~160ms 입력/등장 위주이며 reduced-motion과 키보드 포커스를 지원한다.

## 공통 실행 API

### 자동 생활 기본·직접 행동 일시 개입 (2026-10-25 후속)

- 일반 플레이의 수동 조작/자동 생활 전환 버튼과 일시정지 버튼, 중복 상단 `생활·행동` 페이지를 제거했다. 오른쪽 생활 패널을 계속 사용하며1180px 이하에서는 HUD의 `행동` 버튼으로 같은 패널을 연다. 전체 페이지 스크롤 대신 기존 패널 내부 스크롤을 유지한다.
- `PlayerLifeSave.directControl?`은 직접 선택한 행동/이동/공동 활동/전투의 일시적 제어권이다. 기본 `mode=automatic`을 바꾸지 않으며 실제 완료 후 일정/생활 AI로 복귀한다. 동의·중요 선택 중에는 완료로 꾸미거나 강제 진행하지 않는다. 일반 세션에서 구형 영구 manual 저장은 자동 기본 정책으로 옮기되 진행 중 행동·동의·이동은 보존한다. 개발자용 저수준 manual API와 전투의 직접 턴 선택은 별개로 유지한다.
- 행동·이동·대화/공동 활동은 기존 공통 세션이 필요한 시각까지 자동 진행한다. 소지품 양도/선물도 실제 제안 뒤1분 진행한다. `확인하고 계속`은 중단된 직접 행동/요청의 남은 시간으로 이어져 시간 버튼을 다시 누를 필요가 없다. 메뉴/캐릭터 열기는 진행 중 요청을 취소하지 않는다. 숨김/언마운트 안전 취소와 중요 선택 중단은 유지한다. 무제한 실시간 배경 자동 재생을 추가한 것은 아니다.
- HP0 회복 오류: 기존 전투 자원 적분은 하한0에서 양의 소수 누적량도 매번0으로 버려, 많은 이벤트로 시간이 잘게 나뉘면 회복하지 못했다. 하한에서 음의 초과분, 상한에서 양의 초과분만 버리도록 수정했다. 기존 회복률(휴식 HP2/시간)은 유지하며1분×30회도 실제 HP1을 회복한다. 현장 회복 버튼은 HP가 최대 미만이면 제공한다.
- `test-academy-player-auto.mjs`: 실제 회복/분 단위 경계·직접 활동/이동/공동 요청 후 자동 복귀·이전 직접 활동 해제·구형 manual/진행 중 저장 복원. `test-academy-player-auto-browser.mjs`: 제거된 버튼/탭, 직접 행동의 시간 진행/자동 복귀, 실제0→1HP 회복,1024/390/가로 화면의 행동 서랍. 기존 플레이어·인물 행동 핵심 브라우저도 현행 흐름으로 검사한다.
- 이번 자동 선택은 등록된 플레이 제어/전투 영향에 맞춘 Standard17개(관련 계약·타입·빌드·단기 시나리오) 통과. NPC 행동 어댑터는 play 분류에 명시 등록해 알 수 없는 파일로 전체 검사를 선택하던 문제를 없앴다. 이전 플레이어 검사의 영구 수동 가정은 자동 복귀 계약으로 바꾸고, 동의 검사는 실제 대기 만남을 준비하도록 수정했다. 원본 `test-results/academy-player-auto/{contracts.log,player.log,browser.json,regression/report.json}`. 장기 실행/성능 재측정 없음.

### 인물 상세 통합 행동 (2026-10-25 후속)

- 일반 플레이의 `전투·판정` 메뉴를 제거했다. 좌측 `나의 상태`에 공통 전투 엔진의 HP/SP/MP를 표시한다. 구형 미연결 저장은 명시적 연결 버튼을 유지하며 렌더링은 자원을 생성하지 않는다.
- 현재 상황/주변 인물의 공통 캐릭터 상세 상단에 `NpcActionPanel`을 배치했다. 잡담·공동 공부/훈련/식사·대련·실전 공격을 빠른 버튼으로, 나머지 상호작용/보유 정보/문화/약속/상세 대화를 접이식 검색 메뉴로 제공한다. 생활·기숙사·사회생활 화면의 중복 개시 버튼은 제거하고 응답/기록/약속 확인은 유지했다.
- `systems/npcActions.ts`의 `getNpcActions`/`executeNpcAction`이 유일한 플레이용 NPC 개시 목록·실행 어댑터다. 기존 상호작용 카탈로그와 대화 options를 재사용하며 실제 장소·이동·접촉/쿨다운·동의를 검사한다. 상세를 열어둔 사이 상대가 이동해도 실행 직전에 다시 검사한다. 타인의 숨은 지식으로 공유 주제를 만들지 않는다.
- `getRequestAvailability`와 전투 `getStartAvailability`는 RNG/자원/요청 상태를 쓰지 않는 조회 API다. 실제 요청/전투 시작은 기존 엔진이 다시 검증한다. 직접/자동 전투 설정과 동의 후 시간 진행은 기존 세션에 위임한다.
- 직접 참여한 최근 전투/라운드 로그는 `나의 사건 기록`의 `PlayerCombatHistory`에서 확인한다. 개발용 공통 판정·전투 관찰/실험은 설정집에 유지한다.
- 신규 파일: 위 엔진 어댑터, `NpcActionPanel.tsx`, `PlayerResources.tsx`, `PlayerCombatHistory.tsx`, `test-academy-npc-actions{,-browser}.mjs`. 기존 UI·공통 CSS와 상호작용/전투의 조회 계약을 최소 수정했다. 저장 형식·전투 규칙·시계·시뮬레이션 정밀도는 변경하지 않았다.
- 이번 검증: 자동 선택 Extended **47/47** 신규 실행(관련 headless/타입/빌드/짧은 통합 시나리오, 재사용0), 신규 NPC 행동 브라우저·기존 전투 브라우저·대화 브라우저 통과. 후속 기능 노트41시스템/353항목 검증과 변경 컴포넌트 ESLint 통과. 기존 브라우저는 삭제된 메뉴/시간 버튼 대신 자원 HUD·개발 판정·자동 대화 완료 흐름을 검사하도록 갱신했다. Vite는 기존 큰 청크 경고를 유지하며 산출물38개 프로젝트/185개 로컬 참조 검사를 통과했다. 원본 `test-results/academy-npc-actions/regression/report.json`, `browser.json`, `contracts.json`.30일/7일 성능 재실행 없음. 이전 성능 한계는 아래 기록대로 남는다.

`PlaySession.performAction` / `moveAndArrive` / `settleInteraction` / `combatTurn` / `resolveCombat`를 추가했다. 기존 행동·이동·동의·시간 엔진에 위임한다. NPC별 세계 시계를 추가하지 않는다. 자동 전투는 실제 마지막 라운드까지만 진행한다. 자동 행동도 중요 선택/세계 중단/사용자 일시정지에서 멈춘다. 시간 경계에서0분 진행했을 때 반복하던 잠재 무한 루프도 차단했다.

`PlaySave.combatMode?`는 구형 저장에서 직접 전투가 기본이며 저장·복원을 지원한다. 프레임/렌더가 세계 상태를 변경하지 않는다. 생활/기숙사 행동과 직접/공동 대화, 동의 후 실행을 연결했다. 중요한 사건 확인 후 남은 시간 재개는 기존 수동 확인을 유지한다.

## 실측 최적화와 미달 목표

Windows/Node22.18.0, seed `ux-perf-v1`,100NPC가 등록·활성화된 현재 통합 세계의19시 구간. 생성 제외 엔진 측정, 브라우저 응답 측정 아님. 기존LOD 그대로(종료 시0단계83명/2단계17명);100명 전원 정밀0단계 실행이라는 뜻은 아니다. 표본은 전후 각1회, 평균/p95 또는 모든 시나리오 성능으로 일반화하지 않는다.

- 인게임60분: **5,043ms → 3,593ms**. 전체 최종 저장SHA256 동일, AI판단838/기억109/세계사건5/완료활동69 모두 동일. 관계 변화는 이 구간0건으로 관계 다수 부하 검증이 아니다.
- 정적 출입 계층 목록만 캐시하고 실제 인물/시간별 허가는 계속 검사한다.
- immutable 인물 스냅샷·카탈로그·출발/도착·분·방식·정적 추정 여부가 같은 경로만 제한적으로 재사용한다(인물당64개). 일반 mutable 이동 권한의 실제 시작은 다시 계산한다. 같은 분 권한/상태/위치 변경 시 캐시 무효화, 카탈로그 교체 시 별도 캐시, 시간창도 키에 포함한다.
- 시간 조건을 무시한 **정적 출발 추정**만 Dijkstra 최선 라벨을 줄였다. 실제 시각 의존 탐색의 복수 도착 라벨은 유지한다. 이동 배율도 같은 탐색 안에서 한 번 계산한다.
- 욕구의 완료 근거 검사는 전체 일정 객체의 깊은 복사 대신 필요한ID/활동/상태만 분리한 읽기 API를 사용한다. 기존 getHistory 편집 가능한 복사 계약은 유지한다.
- UI 진행 배치의 상한을60→240분으로 확장하되 실제 이벤트 경계는 모두 기존 시계가 처리하며 중단을 존중한다. 이것을 엔진 시간 개선으로 합산하지 않았다.
- 실제7일 요청은30초 벽시계 안전 한도에서 종료. 마지막 **완료 체크포인트480분/25.051초**, 다음 구간은 완료 여부 미확인.7일 전체 완료/평균/1초 목표를 달성했다고 보고하지 않는다. 원본: `weekly-performance/{progress,timeout}.json`.
- CPU표본은 structuredClone/출입 조건/경로/GC가 주요 비용이었다. 전역 motivation.save/load 백업, 관계 변경의 전역 refresh와 매 시각의 전체욕구/목표 순회·빈번한 AI재판단은 남아 있다. 이를 대규모COW/dirty 예약 구조로 전환하려면 원자적 롤백·알림 순서·결정성 보존 설계가 필요하다. 데이터 보존량을 줄이거나 기능을 끄는 조치는 하지 않았다.
