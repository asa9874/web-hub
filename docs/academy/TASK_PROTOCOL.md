# TASK_PROTOCOL — 구현과 검증

## 기본 절차

1. PROJECT_CONTEXT → 관련 시스템 계약/타입/심볼을 확인한다. 전체 프로젝트·긴 누적 README를 처음부터 읽지 않는다.
2. 새 아이디어 노트의 의도·핵심 요구와 구현 방법을 구분하고 **이미 충족 / 수정 / 신규 / 연동 / 선행 필요 / 후속 분리 가능**으로 분류한다. 루트 AGENTS의 자율 판단·우선순위에 따라 방법을 선택하고 중복·불필요 항목은 근거를 남긴다. 후속 분리나 비용을 이유로 필수 기능을 생략하지 않는다.
3. 연결된 기능 단위로 실제 세계 실행까지 구현한다(예: 모델·조회 → 전달·효과 → 저장·UI → 검증). 오래 걸릴 작업은 핵심 기능부터 완성하고 필요한 최소 보완을 포함한다. 최소한의 정확한 변경을 우선하며 단계마다 같은 문맥을 재분석하거나 전체 테스트를 반복하지 않는다.
4. 변경된 불변식·호출부·저장 구조·성능 영향을 근거로 아래 검증을 선택한다. 게임별 AGENTS의 장기 플레이·성능 목표를 적용하고 실제 연산 비용과 UI 응답성을 구분한다. 요구된 핵심 시나리오는 마지막에 누락 여부를 확인한다.
5. 실제 구현, 아이디어 노트 대비 변경·개선과 주요 설계 판단, 성능 개선·문제, 검사 결과, 미완료·미검증·후속 제안을 간결하게 기록한다. 기능 현황과 실제 증거를 갱신한다.

## 검증 단계

| 단계 | 목적 / 사용 시점 | 선택 기준 |
| --- | --- | --- |
| FAST | 국소 구현·수정 | 관련 단위/짧은 계약 검사, 필요한 타입·정적 검사 |
| INTEGRATION | 시스템 경계 변경 | 관련 엔진끼리 최소 시나리오, 저장·결정성 등 변경 불변식 |
| REGRESSION | 핵심 엔진/다중 시스템·기능 완료 | 영향을 받는 주요 불변식과 호환성. 전체 게임 회귀와 동일하지 않음 |
| STRESS | 장기 누적·성능 회귀·릴리스 목적 | 먼저 작은 재현 통과 후 NPC 수·기간·시드·종료 조건 명시. 30/360/720/1440일은 매번 실행할 기본값 아님 |

루트 AGENTS의 빌드 기준은 유지한다: UI/게임 코드 변경은 해당 검사와 빌드, 문서만은 diff/경로 검사. 개발 도구만 바꾸면 그 도구의 테스트를 우선한다. 브라우저는 실제 입력·표시 확인이 필요한 변경 경로에만 쓴다. 전체 CI와 기존 테스트를 삭제/축소하지 않는다.

### 명령 선택 예

- 대사/설명: 해당 콘텐츠 검사, 필요 시 화면 확인. NPC 장기 실행 제외.
- 기억 조회: `test:academy-memory` → 전달/AI/저장 영향을 확인해 관련 검사 추가.
- 대화·약속: `test:academy-conversations`(의미/공통 실제 실행/선택/정보/약속/저장·100명1시간 단기 진단), UI는 위 계약의 저장 fixture로 `test:academy-conversations-browser`. 대화가 없는 구형 저장·비밀 투영·일과/효과 중복을 확인한다.30일/360일은 기본 검사가 아니다.
- 세계 스케줄러: 시간·이동·일과·결정성·저장 검사, 누적 위험이 있으면 STRESS 검토.
- 학사·수강신청: `test:academy-academics`(실제 수업·선발·저장·소규모7일 분할), UI는 `test:academy-academics-browser`. 중앙 일과/효과/플레이어 계약 변경은 직접 영향 검사를 추가한다. 학년 전체/100NPC 장기는 별도 목적을 확인하며 기존30일 결과로 대체하지 않는다.
- 문화·생활양식: `test:academy-culture`(14문화/24관습/24사건, 실제 활동·기억/선호·구형/저장·분할·100NPC1시간 단기 진단), UI는 `test:academy-culture-browser`. 대화/AI/세계 이벤트의 직접 영향 검사를 추가하며30/360일은 목적을 명시한 후 별도 검증한다.
- 세계관·종족·출신: `test:academy-world-lore`로 정적 참조·멱등 시드·독립 난수·구형/신규 저장을 확인한다. 생성/조직/장소 변경은 직접 관련 검사, UI는 `test:academy-world-lore-browser`. 정적 카탈로그만으로 장기 시뮬레이션을 반복하지 않는다.
- 플레이 레이아웃: 고정 뷰포트·패널 내부 스크롤·메뉴/시간 조작/현 시각의 상단 한 줄·핵심 조작 위계를 유지한다. `test:academy-play-layout-browser`로 문서 스크롤/겹침·모바일·팝업·설정집 복구를 확인한다.
- 기숙사·일상생활: `test:academy-daily-life` → 장소/공통 스냅샷/세계 이벤트/통합 세계/플레이 저장의 직접 영향 검사를 선택한다. `diagnose:academy-daily-life`는10명 하루 및 시간별 동등성·100명 전체AI1시간만 측정하며 빌드/검사와 동시에 실행하지 않는다.30/360일은 기본 검사가 아니다. UI는 `test:academy-daily-life-browser`의 실제 저장 fixture로 격리/귀가/배정/모바일을 확인한다.
- 플레이 조작·팝업 UX: `node scripts/test-academy-play-experience.mjs` → `node scripts/test-academy-play-experience-browser.mjs`. 실제 저장 fixture의 공동훈련 요청·수락/거절·중첩 설명/주소/시각 유지·방침 슬라이더·공통 NPC 상세를 확인한다. 배경 화풍/경로는 `PLAY_EXPERIENCE_V1.md`.
- CSS: 빌드, 필요 시 해당 팝업·반응형 경로 확인.
- 기존 `test:academy-ai` 기본 명령에는 10·50·100명 각 7일 실행이 포함된다. 짧은 연동 목적이면 기존 `AI_SKIP_BATCH=1` 옵션을 명시하고 생략 범위를 보고한다. 일과/욕구 테스트를 이름만 보고 FAST로 가정하지 않는다.

### 짧은 성능 진단

- LOD 변경은 `test:academy-lod`(정책·실제 이동·중요 사건·약속·저장·분할 진행)부터 실행하고 영향에 따라 기존 AI/세계 이벤트/상호작용/기억 검사를 선택한다. 화면 변경은 `test:academy-lod-browser`를 사용한다. `diagnose:academy-lod`는 신선한 세계의 100명 전체 AI 등록 상태에서 정밀 정책과 LOD 정책을 각각 측정한다. LOD1~3은 미시적 선택이 다르므로 이전 전체 정밀 결과와의 바이트 일치를 요구하거나 같은 행동 수라고 보고하지 않는다.
- LOD 벤치마크 기본은 5개 시나리오 각1시간·2회, 최대 명시적8시간이다. 검사/빌드와 동시에 측정하지 않는다. 8시간도 경고를 넘으면 30/360일 반복 대신 남은 병목과 미검증 범위를 기록한다. 개별화되지 않은 집계 인구를 활성 AI 수에 더하지 않는다.

- 목표·경고값은 게임별 AGENTS의 v1.1 표를 따른다. 먼저 `node scripts/diagnose-academy-performance.mjs --minutes 60 --runs 2 --profile`로 100명 전체 AI의 짧은 4개 시나리오를 측정한다. 이 도구는 엔진 단독·새 세계 구간이며 UI 응답, 8시간/하루/7일, 오래된 저장이나 선택 중단 성능을 증명하지 않는다.
- 원본 결과/프로파일/실패 로그는 `test-results/academy-performance/`에 보존한다. 프로파일 실행은 평균·최대 응답 집계에서 제외한다. 실패한 시나리오만 `--scenarios <id> --resume`으로 재실행할 수 있으며 이 옵션은 해시로 확인한 기존 엔진 번들을 재사용한다. 코드 변경 후 측정은 새 번들을 만들어야 한다.
- 최적화 전후에는 `--directory <경로> --snapshots`로 결과/통합 상태를 분리 보존하고 해시·실제 행동/사건 카운터를 비교한다. `--step-minutes 1`은 분할 시간 비교용이다. 기본 최대60분은 유지하고, 명시적 `--extended`만 최대8시간을 허용한다. [최적화 v1](PERFORMANCE_OPTIMIZATION_V1.md)의 캐시 변경 시 `test:academy-read-snapshots`와 직접 영향 검사를 우선한다.
- 느린 짧은 측정이 확인되면 9일·30일을 반복하지 않는다. 예약 경계·변화 없는 NPC 재판단·일과 반복·활동 구간 적분·읽기/경로 캐시·중복 기억/관계/효과·화면 갱신을 증거로 분석한다. 단순 하루 반복을 넘어서는 7일 전용 경로도 검토하되 구조 최적화와 LOD는 후속 작업으로 분리한다.
- 허용 가능한 추상화·캐시 무효화·중간 일정/이동/약속/전투/사고/관계/기억·임의 NPC의 중요 사건 참여·동일 난수 기회·선택 중단을 설계에 명시한다. 날짜만 바꾸거나 근거 없는 결과 생성·사건 누락·시스템 비활성화로 목표를 통과 처리하지 않는다. 진단 결과는 [PERFORMANCE_DIAGNOSTIC_V1_1](PERFORMANCE_DIAGNOSTIC_V1_1.md) 참고.

## 기억 검증 보조 도구 (기존 테스트는 그대로 유지)

공통 자동 선택은 `npm run validate:changed`(계획만) → 이유·실행 비용 확인 → `npm run validate:changed -- --run` 순서다. Quick/Standard/Extended/Full은 FAST/INTEGRATION/REGRESSION/선택적 STRESS·UI의 검사 선택에 대응하며, 고정된 장기 실행을 강제하지 않는다. 중앙 시계·저장·효과·공통 모델은 Extended로 승격하고 분석 실패는 보수적 기본 검사로 전환한다. 상세 CLI·실패 재현·정확한 내용 지문 재사용·미구현/미실행 표기는 [VALIDATION_V1](VALIDATION_V1.md)을 따른다. 아래 기억 프리셋은 호환성을 위해 그대로 유지한다.

```powershell
npm run check:academy -- --tier fast
npm run check:academy -- --tier integration --run
npm run check:academy -- --tier regression --run
npm run check:academy -- --tier stress --count 100 --days 30 --run
```

- 기본은 **계획 출력만** 한다. 현재 프리셋은 기억 변경용이며 모든 명세를 자동 포괄하지 않는다.
- FAST=기억 계약, INTEGRATION=기억+상호작용, REGRESSION=앞 두 검사+배치 제외 AI. 시간/장소/일과/욕구/브라우저/타입/빌드는 변경 영향에 따라 별도로 추가한다.
- STRESS는 수량·기간을 모두 명시해야 한다. 기존 기억 테스트의 일 단위 진행·시드 `memory-month`·검증 의미를 그대로 사용한다. 장기 분 단위 왕복 검사는 별도 선택이다.
- 상속된 장기 실행 환경변수를 정리한다. 원본 스크립트를 직접 실행하면 기존 동작은 그대로다.
- 원본 stdout/stderr와 실행 시간/HEAD/dirty 상태/명령/결과는 `test-results/academy-check/`에 남긴다. 콘솔은 요약과 실패 꼬리만 표시한다. 실패 시 자동 재시도하지 않는다.
- 전체 빌드는 `.build-projects`를 정리하므로 장기 결과를 그곳에만 보존하지 않는다. 보조 도구는 성공한 STRESS 결과를 별도 실행 폴더로 복사한다. 장기 테스트와 빌드를 동시에 실행하지 않는다(공유 산출물·측정 간섭).

## 반복과 출력 억제

- 통합 세계 실행기 변경: `npm run test:academy-world-simulation`(명령/저장/분할 시간/10·50·100명 단기). UI 변경은 `npm run test:academy-world-simulation-browser`를 해당 로컬 Vite에 연결한다. 장기 스트레스가 아니며 기존 엔진 전체 검사를 매번 요구하지 않는다.
- 관찰 플레이 변경: `npm run test:academy-play`와 `npm run test:academy-play-browser`(해당 로컬 Vite URL)를 우선한다. 3명 실제 세션·공개 투영·시간·이동·저장/기록/격리를 검증하며 100명 장기 검사가 아니다.

- 파일명 → 심볼/참조 → 필요한 범위 순서로 읽는다. 이미 읽은 변경 없는 파일을 재출력하지 않는다.
- 출력은 첫 오류·관련 스택·결과 경로 위주로 제한한다. 전체 원본은 로그에 보존한다.
- 새 코드/환경 변화/실패/검증 누락 없이 통과 검사를 반복하지 않는다. 실패는 최소 재현부터 수정하고 해당 검사부터 재실행한다.
- 짧은 검사부터 현저히 느리거나 장기 실행·반복 수정이 과도하면 루트 AGENTS의 재검토 절차를 적용한다. 현재 결과를 보존하고 원인을 확인한 뒤 작은 재현·저위험 개선을 우선한다. 원인 미확인 장기 실행을 계속하거나 기능을 꺼서 성능 목표를 통과 처리하지 않는다.
- 대기 중에는 유용한 독립 작업을 수행한다. 진행 변화 없는 짧은 폴링·반복 분석을 줄이고, 진행 보고는 새 사실·불확실성·다음 확인만 간결히 전한다.
- 장기 결과 재사용은 코드/설정/시드/환경/검사 범위와 후속 수정 영향을 확인한 후 판단한다. 결과를 재사용해도 이번 실행으로 표기하지 않는다.
- 토큰 수, 실행 시간, 계정 한도는 별도 지표다. 측정 없이 절감률·성능 병목을 확정하지 않는다.

## 세션 인계 (미완료일 때만 짧게 남기기)

```text
목표 / 기준 HEAD / 기존 사용자 변경:
완료 단계 / 미완료 단계:
최근 수정 경로:
마지막 검사 명령·환경·결과·로그:
알려진 문제 / 다음 심볼·작업 위치:
```

다음 세션은 이 인계와 실제 git 상태·관련 코드를 함께 확인한다. 모든 세션에서 전체 분석을 반복하거나 요약만 믿고 코드 확인을 생략하지 않는다.

- 플레이어 생활 변경: `npm run test:academy-player`(3명 NPC 하루·실제 이동/성장·동의·분할 시간/저장/중단)와 필요 시 `test:academy-player-browser`를 사용한다. 기존 관찰 계약도 보존한다. 중앙 시계/AI/일과/상호작용 변경은 해당 단기 계약을 함께 실행하고, 100명360일은 별도 목적/비용을 확인한 STRESS다.

## 로컬 브라우저 연결 진단

- localhost 연결 실패 시 UI를 반복 실행하기 전에 동일 주소의 HTTP 오류 원인(EACCES/거부/시간 초과)을 확인한다. 샌드박스 경계가 원인이면 승인된 로컬 전용 서버 실행으로 구분 검증한다. 연결 실패를 앱 로딩 성능으로 단정하거나 방화벽·외부 바인딩을 임의 변경하지 않는다.
