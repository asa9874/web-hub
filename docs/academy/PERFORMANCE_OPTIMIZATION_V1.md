# 실측 병목 기반 성능 최적화 v1

2026-10-23. 읽기 복사와 테스트 UI 진행 비용을 개선했다. **1시간0.3초·8시간1초·7일3초 목표는 달성한 것으로 보고하지 않는다.** 초기 진단은 [v1.1 보고서](PERFORMANCE_DIAGNOSTIC_V1_1.md), 이번 실제 비교 증거는 [performance-optimization-v1.json](performance-optimization-v1.json)이다.

## 변경 내용

- `systems/locationWorld.ts`: 인물별 불변·분리된 `getCharacterReadSnapshot`을 추가했다. 처음 읽을 때만 깊은 복사/동결하고 해당 인물의 변경 전까지 재사용한다. 이동 시작/경유/도착/취소·배치·등록·인물 변경은 관찰자 알림이 트랜잭션으로 지연되더라도 즉시 캐시를 무효화한다. 상태를 소급 수정하거나 캐시를 저장 파일에 넣지 않는다.
- `npcAi`, `npcMemory`, `motivationEngine`, `npcSchedules`, `interactions`, `worldEvents`의 읽기 경로를 전환했다. 편집·효과 트랜잭션·일과의 로컬 위치 수정에는 기존 mutable copy API를 유지한다. 공개 `getCharacter`, `getCharacters`, `getCharacterLocation`, AI `getPerception`의 편집 가능한 분리 복사 계약을 보존한다.
- `components/WorldEvents.tsx`: 게임1분당 무조건1프레임을 기다리던 방식을 벽시계 예산에 따른 배치/화면 양보로 바꿨다. 호출당 목표 약12ms, 묶음 약24ms를 기준으로1~60게임분을 조절한다. 이는 하드 실시간 지연 보장이 아니며 실제 의미 있는 경계는 계속 기존 세계 시계가 모두 처리한다. 닫기 후 중단 정책도 유지한다.
- LOD·새 행동 규칙·전체 트랜잭션 재작성은 하지 않았다. AI·기억·관계·상호작용·세계 이벤트를 끄거나 평가 기회를 삭제하지 않았다.

## 같은 실행 조건의 전후 측정

Windows / Core Ultra7 258V / 논리 CPU8 / Node v22.18.0. 시드와100명의 초기 데이터를 고정했다. 모두 생도이며 학년·전공·성장 유형은 혼합했다. 생성·초기 연결·저장 직렬화는 엔진 타이머 밖이며 각1시간 구간을 전후 각각 독립 프로세스2회 실행했다. 아래는 새 세계의 짧은 구간이지 실제 주간 측정이 아니다. 평균과 관측 최대는2개 표본이며 p95·최악 지연을 보장하지 않는다.

교류 구간의 실제 상호작용 완료18건·관계 효과36건·생성 기억607건, 시험 안내와 세계 이벤트의 실제 새 사건 수 및 모든 AI 판단 수가 전후 동일했다. 시험 안내 측정은 미구현 시험 점수/행사를 실행했다는 뜻이 아니다.

- 수업 구간의 복사 API 호출: `getCharacter`44,947→400회, `getCharacterLocation`24,275→825회. 대신 읽기 스냅샷67,997회를 재사용했다. **조회 자체를 없앤 것이 아니라 조회마다 복사하던 비용을 줄인 것**이다. 캐시는 현재 인물별 최신 버전만 보유하며 오래된 저장/수년 메모리 성능을 입증한 것은 아니다.
- 실제8시간 수업일 구간도 전후 각1회 실행: **10.200→5.248초**, 전체 AI와 전체 저장 결과 동일. 각 프로세스에는15/30초 예산을 설정했고9일·30일을 반복하지 않았다. 8시간 경고2초를 여전히 초과한다.
- 같은 새 엔진에서 UI 진행 방식만 전후 각각2회 비교: 브라우저 평균 **1.535→0.644초**, 이후 관측 최대0.690초. headless Chromium, 1440×1000, 실제 버튼 클릭부터 완료 후 다음 프레임까지다. 수업100명 스냅샷·AI 판단525회·전체 최종 저장이 동일하다. 최적화 전의 이번 UI 기준선도 이미 읽기 캐시를 적용한 상태이며, 초기 진단의2.546초를 새로 실행한 값으로 사용하지 않았다.
- UI 양보 횟수·시간 진행 표시 로그의 분할은 달라질 수 있다. 실제 도메인 사건·행동/이동·욕구·관계·기억·이벤트 예약을 건너뛰지 않는다. UI의 프레임 대기 감소와 엔진의 복사 비용 감소를 별도로 측정했다.

## 정합성 검증

- 변경 전 엔진을 별도 번들로 보존했다.4개 시나리오의100명·60분 전후 전체 통합 저장과 카운터가 동일했다(SHA-256 일치). 저장에는 실제 인물·이동·일과/활동·욕구/목표·관계·AI/RNG 관련 상태·상호작용·효과·기억/정보·세계 이벤트/예약/DAG가 포함된다.
- 같은4개 시나리오에서 최적화 후1분씩60회와60분 일괄 진행의 전체 저장이 동일했다. 실제8시간 전후 및 UI 배치 전후도 전체 저장 해시가 일치했다. 이 범위의 동등성이 모든 가능한 게임 상태의 형식적 증명인 것은 아니다.
- 새 캐시 계약 검사: 중첩 수정 거부, 기존 편집 getter·저장 격리, 인물별 무효화, 지연된 커밋 전 읽기, 롤백 복원, 배치·이동/경유/취소/도착, 과거 스냅샷 불변성 통과. 처음에는 일과의 로컬 위치 수정까지 읽기 API로 바꾼 오류가 검출돼, 해당 지점은 기존 편집 가능한 복사를 유지하도록 수정했다.
- 장소, 기억, 상호작용/효과, AI 규칙·저장·분할 시간(대량 배치 명시적 생략), 세계 이벤트 계약 검사 통과. 공개 AI 인지 조회가 여전히 편집 가능한 분리 복사인지도 추가 검증했다.
- 기존 세계 이벤트 브라우저 경로의 팝업·그래프·키보드·줌·모바일·시간 진행·JSON 복원·원본 격리 통과. 전체 게임 E2E는 실행하지 않았다.
- 변경 엔진/UI ESLint·전체 TypeScript·루트 Vite 생산 빌드(24.88초)·dist 검증(38프로젝트/181참조) 통과. 변경 없는 타 게임 번들은 재빌드하지 않았으며 기존 큰 청크 경고는 남아 있다.

## 남은 병목·미완료

- 1시간 목표0.3초는 전 시나리오 미달이고, 교류 구간은 경고1초도 초과한다. 실제8시간은5.248초로 목표1초/경고2초에 미달한다. 하루·7일·오래된 저장·10년 데이터는 이번에 미측정이며 선형 환산으로 결과를 만들지 않는다.
- 최적화 후 교류 CPU 프로파일에서도 `structuredClone` 자체 약44%, `motivationEngine.save` 자체 약6.5%가 남았다. 목표/욕구 조회와 효과 적용 전의 전역 백업을 다음 대상으로 삼되, 소유권·원자적 롤백·증거와 알림 순서를 보존하는 설계가 필요하다. 기존 전체 백업을 임의로 제거하지 않았다.
- 예약된/dirty 인물만 처리하는 추가 개선, 읽기 문맥·경로 캐시 확장, 장기 이력 비용과 LOD는 후속 범위다. 지역 비활성화를 이유로 중요한 행동·정보·사건을 생략하는 정책은 추가하지 않았다.
- 플레이어 중요 선택 경계의 중단/재개 프로토콜은 기존 미구현 상태다. 이번 UI 배치가 이를 새로 구현했다고 보고하지 않는다. 해당 프로토콜과 실제 캠페인 응답성을 검증하기 전 생산 게임의7일 진행 목표 달성을 선언하지 않는다.
