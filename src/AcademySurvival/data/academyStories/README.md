# 아카데미 사건망 v1 — 부분 구현

기존 개인50/교차12의 ID를 재사용하고 신규 일상30개를 추가한다. 총92개 **콘텐츠 정의**이며 전체92개 실행 완료가 아니다. 기존42개 실행 경로/20개 의존 보류에 신규16개 연결/14개 보류를 더한다. 연결된58개 전부의 모든 분기를 실증했다는 뜻도 아니다.

## 단일 실행 권위

`index.ts`는 기존 WorldEventDefinition을 사용한다. 별도 스토리 시계·NPC·관계·기억·선택 엔진은 없다. 기존 상호작용의 수락/거절/수행 완료와 실제 도메인 사건을 기다린다. 연구 제안은 연구 성과가 아니며, 소음 조정은 징계/방 재배정이 아니다. 미구현 원인·제작·배달·공연 결과를 만들지 않는다.

`roots.ts`의15개 주제는 개발자용 설계다. 플레이어가 아는 사실이나 도달한 결말로 공개하지 않는다. 세레나의 공식 설정/인물15명/기본 능력은 변경하지 않았다.

## 후속 기회

`EventFollowUpRule.consequence`가 있을 때 실제 종료 원인에 `consequences`를 저장한다. 해금/지연/변경/우회는 명시적 다음 평가 시각에 공통 EventQueue로 처리한다. 조건을 충족한 뒤에만 실제 후속 인스턴스와 DAG 간선을 만든다. 대기는 만료되거나 같은 참가자 집합의 실제 차단 사건에 의해 취소될 수 있다. 완료된 사건을 소급 삭제하지 않는다.

- `delayMinutes`: 최소 대기. `windowMinutes`: 그 뒤 기회 유효 기간. `retryMinutes`: 조건 재평가 간격.
- `activationConditions`: 현재 참가자·관계·상태를 다시 검사한다. 기존 장소·이동·수락·일정 조건을 우회하지 않는다.
- `modify.outcomeWeights`: 기존 결과 후보의 상대 가중치만 변경한다. 조건 미충족 결과를 새로 허용하지 않는다.
- `redirectDefinitionId`: 다른 정의로 기회를 전환한다. 원래 정의를 발생한 사건으로 만들지 않는다.
- `statuses`: 완료 외 실제 실패/만료 등에도 명시적으로 기회를 만들 수 있다. 미발생 대기 사건은 인과 원인으로 사용할 수 없다.
- 후속 선택은 RNG를 재추첨하지 않는다. 인스턴스 결과·기회 키·예약이 기존 저장에 포함된다. 정의별32개 규칙과 기존 세계 사건/예약/연쇄/일일 생성 예산을 유지한다.

기존 `event` 조건에 `outcomeIds/minAgeMinutes/maxAgeMinutes`를 추가했다. 개인별 선행 결과를 확인한다. `source_signal`은 실제 도메인 ID·종류·주체·정의·결과를 검증한다. 개발자 요청으로 제목만 클릭해 전조나 실험 원인을 생성할 수 없다. `academic_exam_soon`은 실제 확정 수강 분반/요일/미실시 평가를 확인한다.

## 공개·저장·보존

일상 사건은 restricted이며 기존 기억·지식 투영을 따른다. 공개 `getInstances()`에서는 미래 기회와 결과 가중치를 제거한다. 개발자 전용 사건망 관찰은 읽기만 수행한다. 일반 UI의 기존 이벤트 창/수락/거절은 그대로 재사용한다.

통합 세계 이벤트 저장의 선택 필드이므로 구형 저장에 없어도 복원된다. 예약 중 저장/복원과 손상 참조 거부를 검사한다. 원인/후속/차단자가 참조되는 동안 보존하며 기존4000개 사건·4000개 예약 한도를 늘리지 않았다. 저중요도 기록을 무제한 축적하는 별도 저장소가 아니다. 새로운 정기 트리거의 구형 저장 예약 보충 마이그레이션은 이번 범위 밖이며 기존 저장의 예약 목록을 임의 재작성하지 않는다. 새 회차에서는 전체 카탈로그가 예약된다.
