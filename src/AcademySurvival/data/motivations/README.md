# NPC 욕구·목표 v1

설정집 **욕구·목표 → 테스트** (`?view=catalog&kind=motivation`, `?view=motivation-tester`). 일과표는 해야 할 일, 욕구는 현재 필요한 것, 목표는 미래 동기다. 이 엔진은 행동 후보를 만들지만 최고 점수를 선택하거나 실제 행동을 실행하지 않는다.

## 조사 및 기존 구조

공통 Character, 시드 RNG, 도감의 실제 특성/기프트·성향/도덕/카르마·조직/직급·관계 그래프·장소/이동·절대 분 시계·일과표 실행기를 재사용했다. 기존의 기프트가 선천 능력이며 별도의 은총 시스템을 새로 만들지 않는다. 영향력 v1 공식과 원본 캐릭터 능력은 바꾸지 않는다.

실제 캠페인 전체 저장소는 아직 없다. 기존 저장 수단은 시간 저장 형식과 메모리 세계 스냅샷이다. 이번에 버전이 있는 욕구·목표 저장 형식과 일과 실행 스냅샷, 이를 함께 담는 샌드박스 JSON 어댑터를 추가했다. 브라우저 저장소나 실제 회차에 테스트 결과를 자동 등록하지 않는다.

## 욕구 카탈로그와 민감도

| ID | 욕구 | 기본/시간 | 분류 |
| --- | --- | ---: | --- |
| hunger | 허기 | +5 | 신체 |
| fatigue | 피로 | +3 | 신체 |
| sleepiness | 수면 욕구 | +4 | 신체 |
| social | 사회적 욕구 | +2 | 사회 |
| recreation | 오락 욕구 | +2 | 심리 |
| growth | 성장 욕구 | +1 | 심리 |
| safety | 안전 욕구 | 0 | 신체/상황 |
| recognition | 인정 욕구 | 0 | 사회/개인차 |
| autonomy | 자유 욕구 | 0 | 심리/활동 |
| curiosity | 호기심 | +0.5 | 심리/활동 |

높을수록 충족이 필요한 상태다. 기본 표시 경계는0~24 낮음,25~49 보통,50~74 높음,75~89 매우 높음,90~100 긴급이며 정의별로 수정할 수 있다. 긴급도는 이 값과 별도로 욕구별 중요도·민감도·현재 위험·활성 목표 관련성을 가중하고0~100으로 제한한다. 성장 욕구90과 수면 욕구90의 점수가 같지는 않다. 수치100에 사망·영구 손상을 임의로 연결하지 않는다.

초기 수치는 명시적 시드+캐릭터ID에서10~35로 생성한다. 개인 민감도는 시드0.75~1.25에 실제 성향·특성·역할·VIT/INT를 반영해0.5~1.5로 제한한다. 사교가/은둔자, 탐구자/야심가/자유추구자/경쟁주의자 등의 실제 ID, 강인한 체질·복습 습관·수면 회복 특성의 실제 ID를 검증한다. 개발 변경 허용 범위는 설정의0.25~2.5다. 상태 이상은 민감도에 영구 각인하지 않고 현재 변화율에서 적용한다.

## 변화 계산과 결정론

```text
시간당 변화율 = 기본 + 실제 활동 추가량 + 이동 추가량 + 상황 추가량
상태 보정 = 양수 증가에 배율, 음수 회복에는 역배율 및 별도 추가량
분당 누적 단위 변화 = round(보정 변화율 × 개인 민감도 × 1,000,000)
누적 단위 = clamp(이전 단위 + 시간당 변화의 정수 분자 × 경과 분, 0, 100 × 60 × 1,000,000)
표시 값 = round(누적 단위 / (60 × 1,000,000))
```

누적 단위는 시간당 변화의 정수 분자를 사용하고 분모에 60을 둔다. 매번 표시 값을 다시 적분하지 않는다. 같은 활동 구간에서1분60회와60분1회가 정확히 일치한다. 정밀도 단위는 저장 버전 계약의 일부다. 값을 바꾸려면 저장 마이그레이션/버전을 함께 변경한다.

취침은 피로/수면 욕구, 식사는 허기, 훈련은 성장 욕구, 연구/독서는 호기심, 휴식은 피로와 오락 욕구에 영향을 준다. 실제 수행 상태가 `active/late`인 시간만 집계한다. 식당 입장·수업 이동·시작 전 대기는 식사/학습 효과가 아니다. 자유시간은 자율성 압박만 낮춘다. 아직 대화·오락 활동을 실행하는 AI가 없으므로 같은 장소의 친구나 자유시간만으로 사회 욕구를 임의로 낮추지 않는다.

걷기/달리기/탑승의 피로 추가량은 각각+2/+7/+1이며 순간이동은0이다. 실제 이동 방식이 기준이고 이동 중 예정 활동 효과는 적용하지 않는다. 위험도·공포·불면·탈진·골절, 의무 활동과 야심/자유 추구 성향은 설정에 따라 별도 보정한다. 동일 상태 정의를 여러 부위가 보유해도 그 변화율 배율을 무제한 중복하지 않는다.

시계가 각 예약 시각으로 이동하기 **전** `beforeStep(from,to)`에서 이전 활동·위치 문맥으로 적분한다. 이후 이동 우선0, 일과 우선10, 욕구·목표 우선20에서 상태를 갱신한다. 마지막 남은 구간도 공통 시계가 전달한다. 실제 활동 전환·경유점·도착·상태 변경을 빠뜨리지 않는다. 일과표에 욕구 수치를 하드코딩하지 않는다.

## 목표55종·생성

12분류(학업/성장/전투/사회적 관계/권력·명예/경제/탐험/생존·안전/개인적 행복/조직·충성/복수·갈등/비밀·탐구), 단기·중기·장기 세 기간이다. `index.ts`의 각 항목에 개별 이름·서술·조건·관련 행동·욕구·역할·선호 성향·공개 범위가 있다. 목표 목록은 아래에 별도 정리한다.

장기1~2, 중기1~2, 단기1~3개를 독립 시드 스트림으로 뽑는다. 전공, 성향, 도덕/카르마, 실제 마법 분야 기프트, 실제 능력·숙련도, 직무·소속과 기존 관계를 참고한다. 이미 충족한 목표나 역할/근거가 없는 목표는 초기 추첨에서 제외한다. 채무·누명처럼 과거 사실이 필요한 항목은 실제 근거 없이는 생성하지 않는다. 생성 결과에 존재하지 않는 인물/기관/능력을 끼워 넣지 않는다.

고정 인물과 플레이어의 공식 목표는 자동 확정하지 않는다. 세레나의 기존 소개·목표 문장을 새로운 목표ID로 임의 변환하지 않으며 현재는 공식 미설정으로 표시한다. 공통 엔진과 타입은 모든 kind에 같고, 명시적 초기 목표나 테스트 수동 목표를 제공할 수 있다.

학업과 평온, 야망과 휴식 같은 심리적 모순을 오류 처리하지 않는다. 필요한 논리적 배타 그룹을 정의할 수 있지만 선악·성향을 이유로 모든 모순을 금지하지 않는다.

## 조건·진행·완료·실패

- 조건은 실제 능력치,0~9 숙련도, 조직/직급/유효 칭호, 상대에 대한 방향성 관계, 실제 정지 방문, 완료 활동 횟수, 실제 수행 누적 분, 현재 욕구, 상태 보유/연속 유지, 외부 사실을 지원한다.
- AND/OR/NOT은 `met/unmet/unsupported` 삼중값으로 계산한다. NOT 미구현을 참으로 오해하지 않는다. 외부 시험·자산·발견·사건 시스템이 없으면 판정 보류 사유를 보여 준다.
- 활동 시간/횟수 목표는 목표 생성 당시의 근거 기준값을 보관해 이전 학습 시간을 새 목표에 소급하지 않는다. 상태 유지 목표는 현재 연속 구간만 세고 상태가 해제되면 연결되지 않는다.
- 진행도는0~100 표시 정보다. 수동으로100을 넣어도 실제 조건이 충족되지 않으면 완료 API가 거부한다. 완료 기록은 이후 소속을 잃었다고 자동 취소하지 않는다.
- 실제 조건 충족 시 완료, 실제 실패 조건·기한 초과 또는 명시적 사건 결과 API로 실패한다. 경비 직급을 잃으면 해당 의무 목표가 실패하는 실제 조건도 포함했다. 당일 목표는 생성 당일 자정에 끝난다.
- 포기/일시정지/재개/삭제는 별도 API다. 중지·종료 목표는 후보를 만들지 않는다. 기한이 지난 일시정지 목표를 재개하면 다시 실패 판정할 수 있다.

변경 알림과 해당 조건에 연관된 시간 구간을 검사한다. 모든 목표를 매 프레임 평가하지 않는다. 목표의 시간 조건/기한과 욕구 긴급 경계는 공통 시계에 다음 판정 시각을 제안한다. 활동 근거의 합계는 유지하고 완료 발생 건 중복 방지 캐시는 기존 일과의35일 이력 범위로 제한한다.

## API와 후보

```ts
const motivation = createMotivationEngine(schedules, {
  seed: 'campaign/motivation',
  relationships: graph,
  initial: batch.motivations,
});
motivation.getCharacterNeeds(id);
motivation.getNeedUrgency(id, 'fatigue');
motivation.getCriticalNeeds(id);
motivation.getCharacterGoals(id);
motivation.getActiveGoals(id);
motivation.getGoalProgress(id, instanceId);
motivation.evaluateGoalCompletion(id, instanceId);
motivation.updateGoalProgress(id, instanceId, 70);
motivation.addGoal(id, definitionId, { targetCharacterId });
motivation.completeGoal(id, instanceId); // 실제 조건을 재검사
motivation.failGoal(id, instanceId, reason);
motivation.abandonGoal(id, instanceId);
motivation.pauseGoal(id, instanceId);
motivation.resumeGoal(id, instanceId);
motivation.generateNeedIntents(id);
motivation.generateGoalIntents(id);
motivation.getNpcMotivationContext(id, world.clock.getSnapshot());
motivation.advanceNeeds(previous, next); // 공통 세계 시간을 한 번 진행
```

`setNeed`, `setSensitivity`, `resetNeeds`, `setGoalPriority`, `removeGoal`, `recordExternalFact`, `save/load`, `getStatistics`도 제공한다. 과거 시각의 동기 문맥을 지어내지 않고 현재 세계 시각만 조회한다. 외부 사실 주입은 실제 사건 처리기가 권한을 갖고 호출할 접점이며 테스트 화면에서 그 의미를 명시한다.

후보는 욕구/목표의 출처ID·활동ID·동기0~100·이유·유효 대상ID·현재 경로 가능성(`scope: route-only`)을 담는다. 단순히 최고 점수 후보를 실행하지 않는다. 현재 이동 중/출입 거부/관련 장소 없음은 동기 점수와 분리해 표시한다. 직무에 맞는 활동·개인 장소 바인딩을 우선하며 마왕성 근무자의 식사 후보도 마계 식당을 사용한다. 활동 자체의 최종 승인과 새 시각의 출입 판정은 향후 행동 AI·기존 실행기에 남긴다.

## 저장·로드·격리

`MotivationSave`는 `motivation-v1`, 절대 분, 캐릭터별 정밀 누적값/민감도/목표/대상/진행/상태/기준 근거·방문·외부 사실·연속 상태 시작 시각을 저장한다. 캐릭터 정의에 매 틱 수치를 중복 저장하지 않고 모든 kind를 같은 캐릭터ID로 조회한다. 저장 시각과 세계 시각이 일치해야 한다.

- `load(undefined)`는 욕구·목표 필드가 없는 기존 저장용 안전 초기화다. 기존 고정 인물의 인생 목표를 추첨하지 않는다.
- 미래 버전, 중복/누락 인원, 잘못된 수치/누적값/목표/장소/인물/기관 참조는 거부한다. 잘못된 저장은 기존 내면 상태를 바꾸지 않는다. 같은 저장을 두 번 읽어도 목표가 중복 생성되지 않는다.
- 일과 `saveExecution/loadExecution`은 개인 계획, 실행/이력, 조기 이동의 보류 의도, 중단/재개 대기, 다음 예약과 집계를 직렬화한다. 세계 위치 스냅샷과 같은 시각에 복원한다.
- 샌드박스 JSON은 `motivation-sandbox-v1`에 세계·관계·일과 실행·내면 상태를 묶는다. 불러오기는 별도 런타임에서 검증한 뒤 전체 샌드박스를 교체한다. 조기 이동 도중 저장 후 이어 진행한 결과도 검증했다.
- 시간 **진행**은 실제 욕구와 목표 기한을 처리한다. 개발용 시간 **직접 설정/되감기**는 욕구·목표 값과 남은 기한을 보존하고 시간 기준/연속 유지 시작 시각을 옮긴다. 지나간 사건을 새로 만들어 내지 않는다. 실제 과거 세계 복원 기능은 아니다.
- 테스트는 진입 당시 세계를 깊게 복제한다. 시간·인물·위치·일과·관계·내면 상태가 원본과 분리된다. 초기화는 진입 스냅샷, 종료는 폐기다.

NPC 생성 v1.6은 기존 배치 결과에 `motivations`를 추가하고 `context.motivationTime`을 받는다. 기존 인물의 능력·이름 난수 스트림은 유지한다. 실제 세계에 붙일 때 인물 전체 등록 → 관계 반영 → 배치의 욕구·목표 상태 반영 순서를 사용한다. 미리보기는 실행 없이 생성된 상태만 보여 준다.

## UI

도감은 이름·분류·기간·우선순위의 작은 그리드이며 상세는 기존 공통 팝업이다. 욕구 기본 속도/임계/관련 활동, 목표의 실제 조건과 판정 보류를 읽을 수 있다. 공통 캐릭터 패널은 욕구 막대·민감도/긴급도·기간별 목표와 상태를 재사용한다.

일반 NPC 정보는 기본 비공개다. 공개 목표/욕구 또는 본인 플레이어 정보만 보여 주며 공통 DEBUG를 켜면 개발자 내면 정보를 볼 수 있다. 비밀 목표를 일반 인물 팝업에 무조건 노출하지 않는다. 독립 세계/미리보기에는 그 세계의 런타임/데이터를 넘겨 원본 세계의 동기 상태가 새어 나오지 않게 했다.

테스트는10/50/100명 생성, 시드, 욕구0/100/개별 변경·민감도·초기화, 실제 임시 활동, 목표 추가/삭제/수치/완료/실패/포기/정지/재개, 외부 근거 입력, 공통 상태창, 실제 통계·후보·로그, JSON 저장/로드,1분/1시간/6시간/1일/7일/직접 시각 설정을 제공한다. 후보 분포는 출처별 후보 수이며 여러 원인이 같은 활동을 제안할 수 있다. 자동 선택한 NPC 인원 분포로 오해하지 않는다.
