# 아카데미 일상생활·기숙사 v1

진입: `systems/dailyLife.ts`, `types/dailyLife.ts`, `docs/academy/DAILY_LIFE_V1.md`.

- `index.ts`: 기존 장소 카탈로그로 합쳐지는 공동생활관/교수·교직원 숙소104실·184침대와 실제 통행로, 공용 휴게실/학습실/세탁실/욕실/식당/정원, 수도 통학 주거지. 남녀 기숙사 기존 명칭과 정책은 보존하며 새 공동생활관에 성별/종족 제한을 만들지 않는다.
- `events.ts`:28개 생활 경험 정의. 실제 도메인 활동/도착/공동 활동 증거의 전용 신호만 세계 이벤트로 평가한다. 직접 강제 발생도 사실 조건이 없으면 거부한다. 원래 수행 효과를 중복 지급하지 않는다.
- `dailyLife`는 `AiSandboxSave`의 선택 필드다. 기존 저장에 없으면 자동 방 배정을 하지 않는다. 플레이/시뮬레이터의 ‘현재 세계에 거주 배정 연결’이 명시적으로 초기화하고 이후 전체 저장에 포함한다.
- 현재 위치는 `Character.location.currentLocationId`, 거주지 참조는 전용 `world.setHomeLocation`, 방/침대 점유는 생활 엔진의 배정 데이터다. 배정은 순간이동하지 않는다. 새 방까지 실제 경로와 입주 권한을 검증한 뒤 반영한다. 만실/잘못된 방은 기존 배정 유지. 방 부족은 pending이며 유효한 빈 침대를 임의 생성하지 않는다.
- 룸메이트의 원천은 같은 방의 활성 거주 배정이다. 사적인 관계 태그를 만들 수 있지만 기존 공개 관계에 비공개 거주 태그를 덧붙이거나 공개 범위를 바꾸지 않는다. 방 변경/퇴실은 감정/친구 관계를 지우지 않는다.
- 방문자는 방별 허가와08:00~22:00을 모두 충족해야 한다. 현재 체류와 새 입장은 기존 장소 엔진 정책을 따른다. 방은2침대+방문자 공간을 구분한다. 현재 인원은 점유 침대 수와 다르다.
- 기존 AI 습관/문화 취미/일과/욕구/효과를 재사용한다. 새 AI/세계 시간/위생 욕구/경제 엔진은 없다. 생활 후보는 기존 효용 평가·의무·긴급·실행 가능성 정책을 따른다. 조용함/정리 선호만 최소 개인차로 추가한다.
- 구간 집계는 실제 활동 전환에서만 정산한다. 현재 진행 구간은 읽기 시 합성하고 저장/조회로 세계를 진행하지 않는다. 일별14일·최근600로그·처리키4000개 상한. 일 단위 정리는 날짜 경계당 한 번, 초과 키는FIFO로 제거한다. 실제 활동 원본과 중요한 기억/사건의 보존 정책은 기존 엔진이 담당한다.
- 평범한 활동은 모든 NPC의 실제 기록/일별 통계에 남긴다. 새 세계 이벤트로의 승격은 일반 경험 종류별 대표1건/일, 의미 있는 룸메이트 경험은 개인별1건/일로 제한한다. ‘모든 도메인 사건을 세계 이벤트로 생성하지 않는다’는 기존 원칙과 중요 사건 예산을 보존한다. 원래 활동/상호작용의 기억·효과를 생략하지 않는다.
- NPC 일과표의 `residenceRevision`은 선택 필드다. 거주/생활 장소가 바뀐 일정만 새 실행 ID를 사용하며, 이미 시작한 옛 실행은 실제 시점에 중단 이력으로 남긴다. 기존 수업·근무 일정은 재생성하지 않는다.

검증: `test:academy-daily-life` → 직접 영향 장소/스냅샷/세계 이벤트/통합 세계/플레이·생활 계약. `test:academy-daily-life-browser`는 전용 계약이 만든 저장 fixture를 사용한다. `diagnose:academy-daily-life`는10명 하루/시간별 동등성 및100명 전체AI1시간만 실행한다.30/360일은 별도의STRESS다.

생활 기억은 기존 약속 사건을 재해석하지 않고 `DailyLifeExperienced`를 사용한다. `npcMemory`는 등록된 `daily-*` 주장만 허용하며 사소한 생활 경험을 중요한 약속과 같은 중요도로 취급하지 않는다.
