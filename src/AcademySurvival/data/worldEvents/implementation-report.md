## 구조 및 API

- 정의/인스턴스/도메인 사건을 분리한다. 시간·조건·확률·행동 파생·서사 트리거가 같은 상태/단계/효과 경로를 사용한다.
- 공통 절대 분 시계 priority29와 안정적인 최소 힙. 확률은 시드+기회 키이며 시간 분할이나 UI 프레임에 의존하지 않는다.
- `requestEvent`, `scheduleEvent`, `cancel`, `interrupt`, `evaluateOpportunity`, `evaluateCondition`, `relate`, `getIntents`, `bindInteraction`, `getInstances/getRelations`, `getAppliedEffects`, `save/load`.
- 단계 진입/종료·실제 이동/출입·상호작용 성공을 검사한다. 결과는 기존 공통 효과 엔진의 안정적인 결과 ID로 한 번만 적용한다.
- 시간·순번의 DAG. 분기, 같은 참여자의 AND 합류, 참여자·날짜별 OR 기회, 차단/취소 기록, 깊이·반복·쿨다운·예약·생성·보존 예산을 제공한다.
- 기억은 공통 `WorldEventCompleted` 도메인 경로를 사용한다. 실제 참여자/목격자만 인지하고 비밀·출처를 유지한다. 도움 후보는 실제 보유 기억·관계·현재 인지 가능성을 확인한다.
- 통합 저장은 선택 필드로 확장했다. 기존 저장의 기본 실행은 보존하며 테스트에서 명시적으로 세계 이벤트를 켤 수 있다. 활성 단계/예약과 DAG 무결성을 검사하고 과거 외부 상호작용 이력 정리와 종료 사건 보존을 구분한다.

- 최종 통합 저장·복원 후 이벤트 저장이 원본과 동일했다. 매일 세계 시간·유효 위치·DAG 진단·인스턴스 한도를 검사했다.

## 제한·후속 범위

- 정식 전투 피해·시험 성적·경제/인벤토리 시스템을 새로 만들지 않았다. 부상은 명시적 사고의 타박상이며 해당 시스템 전체를 구현한 것은 아니다.
- 현재 참여자 규칙은1~2명이다. 다자간 역할/장기 협력·플레이어 개입은 후속 계획이다.
- 저중요도·연결 없는 오래된 기록은60일 후 정리하고, 연결된 사건을 보존하는 대신 예산 소진 시 새 생성에 제한을 둔다. 무한 역사 저장/디스크 아카이브는 미구현이다.
- 그래프는100노드의 부분 SVG다. 대규모 전용 가상 그래프/Worker·영구 캠페인 저장은 미구현이다.
- 장기 heap 수치가 기록되더라도 단위 fixture·복원 clone을 포함한 최종 값이며 피크 또는 전용 누수 프로파일이 아니다. 기록 한도와 참조 정합성 검사와 구분한다.
- v2/v3는 기능 노트의 계획으로만 등록한다.
