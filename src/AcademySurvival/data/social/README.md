# 직급·신분 / 칭호 / 요소 영향력 인계

## 콘텐츠

직급·신분 **200종**, 칭호 **200종**이다. 각 항목에 개별 인게임 설명과 시스템 설명, 조건, 영향력과 분야를 작성했다. 공유 헬퍼는 스키마와 조건 키만 구성하고 문장을 생성하지 않는다.

| 직급 분류 | 수 | 칭호 분류 | 수 |
| --- | ---: | --- | ---: |
| 왕실·귀족 | 30 | 학업·성장 | 25 |
| 아카데미·교육 | 30 | 전투·무용 | 30 |
| 군사·기사단 | 25 | 마법·연구 | 25 |
| 종교·성직 | 20 | 선행·영웅 | 25 |
| 마법·연구 | 25 | 범죄·악명 | 25 |
| 길드·상업 | 20 | 사회·인간관계 | 20 |
| 법적 신분·범죄 | 20 | 기묘한 행적 | 20 |
| 특수 조직·세계관 | 30 | 전설·초월·신화 | 30 |

직급은 권한의 크기뿐 아니라 의무·제한과 종료 절차도 기록했다. 장학생·피후견인·무국적자·청강생처럼 통치권이 없는 지위도 포함한다. 칭호는 공적 직책과 구분하며, 문에 사과한 소소한 일화부터 세계 법칙 복원까지 대비를 두었다. 악명은 선악의 평가 점수가 아니며, 높은 영향력의 칭호가 동일 수준의 기프트를 보장하지 않는다.

## 파일과 추가 방법

- `types/impact.ts`, `data/impactConfig.ts`, `systems/impact.ts`: 버전이 있는 영향력 메타데이터·11분야·9등급·검증·기프트 변환.
- `data/traitImpact.ts`: 기존 **405개 특성 ID에 대한 개별 잠정 평가값**. 희귀도나 효과량으로 계산하지 않는다. 분야만 계열별 사전을 공유하며 미등록 ID는 NaN으로 검증 실패한다. 진화 경로의 값은 모두 상위가 높도록 검토했다.
- `types/social.ts`, `types/slots.ts`: 정의·보유 기록·공통 랜덤 슬롯 타입.
- `positions*.ts`, `titles*.ts`: 16개 콘텐츠 파일. 각 항목은 안정적인 `position-*` 또는 `title-*` ID로 참조한다. 새 항목은 해당 분류에 작성하고 `index.ts`에 등록한다.
- `config.ts`: 분류·획득 유형·소속 유형·실제 소속 ID·배타 슬롯. 이름 변경으로 참조 ID를 바꾸지 않는다.
- `index.ts`: 정식 데이터와 조건부 승진·졸업·임명·퇴임 등 관계. 자동 실행하지 않는다.
- `systems/socialRules.ts`: 소속별 충돌, 대표 변경/대체, 보유 출처와 읽기 전용 랜덤 후보 풀.
- `systems/socialValidation.ts`: 필수값·영향력·중복·참조·배타·관계 순환·보유 기록 검사.
- `systems/characterImpactSources.ts`: 미래 계산기에 전달할 소스 목록만 구성한다.
- `components/SocialCatalog.tsx`, `ImpactFilters.tsx`, `ImpactBadge.tsx`, `CharacterSocialPanel.tsx`: 새 도감과 공통 상태창.

## 영향력 스키마와 마이그레이션

특성·기프트·직급·칭호가 모두 `impact: ImpactMetadata`를 사용한다. 값은 `baseImpact`, 분야는 `domains`, 버전은 `impact-1000-v1`이다. 기존 기프트의 숫자 `impact`를 메타데이터로 변경했으며 모든 사용처를 갱신했다. 최상위 필드 이름을 중복 유지해 값이 어긋나는 구조는 만들지 않았다.

기프트 원본 작성 함수의 숫자 인자는 **명시적으로 legacy-100**이다. 기존 403개 원본의 값과 효과를 보존하기 위해 작성 경계에서 버전이 있는 변환을 수행한다. 숫자 88은880으로, 기존99는990으로 변환한다. 새 평가를 직접 작성하려면 숫자 대신 `makeImpact(value, domains)`를 전달한다. 미래 신규 작성에서는 이 명시적 메타데이터 방식을 권장한다.

`migrateGiftImpact()`는 `legacy-100` 입력만×10한다. 이미 `impact-1000-v1`인 값9는9로 유지하며 반복 호출도 동일하다. 값이100이하라는 이유로 버전을 추측하지 않는다. 잘못된 범위나 버전은 검증 실패한다. 정규화된 데이터가 저장될 경우에도 버전을 보존해야 한다. 레지스트리가 다시 값을 증폭시키지 않는다.

분포는 변환 후 실제 설정을 검토했다. 기프트의 기존 세 최상위 값 중950은 새 구간의 전설급,980·990은 세계급이 된다. 과거 이름을 유지하려고 임의로 값을 끌어올리지 않았다. 영향력 필터와 목록/상세·정렬도 모두0~1000을 사용한다.

| 등급 | 특성405 | 기프트403 | 직급200 | 칭호200 |
| --- | ---: | ---: | ---: | ---: |
| 미미 0–99 | 176 | 34 | 13 | 30 |
| 소규모 100–249 | 192 | 65 | 56 | 49 |
| 지역급 250–449 | 29 | 174 | 76 | 56 |
| 세력급 450–649 | 7 | 94 | 34 | 27 |
| 국가급 650–799 | 0 | 23 | 16 | 11 |
| 대륙급 800–899 | 1 | 7 | 4 | 12 |
| 전설급 900–969 | 0 | 4 | 1 | 11 |
| 세계급 970–999 | 0 | 2 | 0 | 3 |
| 규격 외 1000 | 0 | 0 | 0 | 1 |

1000인 ‘척도가 멈춘 이름’은 비교 척도 적용 불가를 기록하는 단일 특수 칭호이며 무한 전투력이나 무조건 성공을 의미하지 않는다. 위 평가와 분포는 잠정 밸런스 메타데이터다.

## 직급·칭호 보유 계약

모든 Character가 `CharacterSocialIdentity`를 공통으로 확장한다. `positions: PositionHolding[]`, `titles: TitleHolding[]`, `primaryPositionId?`, `primaryTitleId?`를 보유한다. `kind`에 따른 차등 보정·개수 상한은 없다. 같은 직급을 여러 소속에서 보유할 수 있어 단순 ID 배열 대신 정의 ID+소속 ID를 기록한다.

직급의 배타성은 **같은 소속 ID와 배타 직위 슬롯**으로만 판단한다. 같은 본교의1학년/3학년은 충돌하지만 다른 아카데미의 학년은 공존한다. 황태자+학생+전과는 공존한다. 요구된 정책대로 같은 국가의 국왕/왕세자는 동일 최고 통치·계승 슬롯에서 충돌한다. 이는 현실의 직위 일반론이 아니라 이번 세계관의 잠정 캐릭터 보유 규칙이다. 다른 국가·영지의 작위는 별도 소속 ID로 공존한다. 실제 보유 시 조직 유형도 일치해야 한다.

칭호는 정의 ID와 함께 `fact`(확인/외부 주장·낙인/다툼), `visibility`(공개/일부/비밀), `recognizedBy`, `state`(유효/박탈/무효)를 기록한다. 연쇄살인마의 실제 범행과 누명, 아직 알려지지 않은 범행을 같은 필드 하나로 축약하지 않는다. 획득했다고 모든 인물이 즉시 알지는 않는다. 공개 설정 변경도 사실 여부를 바꾸지 않는다.

칭호 박탈은 가능하다고 정의된 항목만 `revoked`로 바꾸고 기록을 남긴다. 잘못된 기록의 무효화는 별도 상태다. `removePosition()`/`changeTitleState()`는 대표가 사라지면 남은 유효 목록의 첫 항목을 대체로 고른다. 영향력 최대 항목을 자동 선택하지 않는다. `setRepresentative()`는 실제 유효 보유 항목만 허용하며 표시를 바꿔도 전체 출처 목록은 같다.

템플릿의 `social.fixed`와 `social.randomSlots`도 같은 보유 구조·공통 `RandomContentSlot`을 쓴다. 후보는 조건·소속·배타·중복을 검사해 가중치만 정규화하고 실제 추첨하지 않는다. 미리보기는 `?`로 표시한다. 세레나의 사회적 고정 정보는 용사/본교1학년, 새벽의 희망/선택받은 자/아카데미에 입학한 자다. 대표는 용사와 새벽의 희망이다.

공통 상태창의 DEBUG 대표 변경·박탈/제거 테스트는 패널 내부 임시 값이다. 원본 템플릿/레코드는 그대로 두고 새로고침 시 복원한다. 호출자가 `onSocialChange`를 제공하면 변경된 공통 구조를 돌려줄 수 있다. 실제 임명·박탈 조건을 판정하는 사건 엔진은 이번에 만들지 않았다.

## 미래 최종 영향력 계산기 연결

`characterImpactSources(character)`는 특성·기프트·모든 유효 직급/칭호의 정의·메타데이터·소속·획득 사건·칭호의 사실/공개 상태를 전달한다. **점수·합계·계수·최종 공식은 반환하지 않는다.** `socialSources()`도 대표가 아닌 전체 유효 보유 요소를 사용한다. 현재 권한·의무·반응 태그는 사건 실행기용 참조이며, 자동 스탯 효과나 소문 전파를 실행하지 않는다.

용사·선택받은 자·세 기프트는 `prophecy-selection` 출처 태그와 선택적 보유 `sourceEventId`를 연결한다. 미래 계산기가 같은 사건을 과대평가하지 않도록 참고할 식별자이며 현재 중복 평가 계산을 수행하지 않는다. 향후 재산·세력·인맥 등은 새 입력 소스로 추가하고 별도 계산기에서 버전·공식·중복 정책을 선택하면 된다. 콘텐츠 효과 엔진은 영향력 메타데이터를 읽지 않는다.


사회 요소 검사는 200/200수량, 405/403영향력,9등급 경계,403개 변환 형식과 대표 변환 사례·반복 안전성, 진화값, 소속별 배타, 대표 대체·이력 보존, 임시 슬롯, 검색/범위/등급/분야/유형/공개 필터,잘못된 데이터·순환 검출과 효과 독립성을 다룬다. 기존 테스트와 CI는 삭제하지 않고 새 필드 형식·수량에 필요한 기대값을 갱신했다.

브라우저 검사는 직급/칭호 목록·필터·상세, 특성 트리와 영향력 정렬 목록, 변환된 기프트,대표 변경/박탈/제거/원본 복원/상세 연결,390px의8탭 배치에 한정한다. React 렌더 대기를 보완한 뒤 미완료 구간만 재검증했다. 전체 게임 E2E나 실제 정치·회차·소문 엔진은 작업 범위 밖이다.
