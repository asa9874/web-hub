# NPC 기억·정보 시스템 v1

## 소유권과 모델

`types/memory.ts`는 세계 사실(WorldFact), 구조화 주장(InformationClaim), 인물별 기억(NpcMemory), 전달 계보(InformationHop), 실제 대화 전달 결과(InformationDelivery)를 분리한다. `systems/npcMemory.ts`의 `createNpcMemoryEngine(motivation, graph, effects, interactions, options)`가 공통 세계·시간·위치·일과·관계·성향·목표와 연결한다. UI나 NPC별 별도 시계를 구현하지 않는다.

원본 세계 사건의 승패·발생 시각은 변하지 않는다. 소문은 같은 주제의 별도 claim ID이며 다른 승자·심각도·시각·확신도를 가질 수 있다. 직접/목격/전해 들음/추론을 구분하고 전달자·시각·방법·기억 ID의 계보를 보존한다. 추론은 자기 보유 기억을 근거로 명시적으로 등록하는 어댑터이며 복잡한 추론 AI가 아니다.

## 관찰과 중요도

행동 결과 엔진의 `subscribeDomainEvents`는 커밋 성공 뒤 실제 사건을 전달한다. 실패한 트랜잭션의 사건은 관찰되지 않는다. 상호작용 완료/거절/중단, 일반 활동 완료, 상태 적용, 실제 성장, 목표 완료를 선택적으로 기억한다. 공동 활동 완료는 일반 활동 완료와 중복 저장하지 않는다.

참여자는 직접 경험을 기록한다. 목격자는 **사건 알림 당시** 실제 같은 장소에 정지해 있으며 수면 중이 아닌 인물만 후보가 된다. 공개 사건만 목격할 수 있고, 주의 확률(일상8%·상호작용65%)과 최대24명 정책을 시드로 적용한다. 위치·일정 처리 순서가 같은 시각의 관찰 상태를 결정한다. 정보 대화와 진지한 대화, 개인 성장/목표 등 비공개 사건은 주변에 전파하지 않는다. 의식 상태를 나타내는 별도 공통 런타임 API는 아직 없으며 `canPerceive` 주입 지점으로 확장한다. 존재하지 않는 기절 상태 ID를 가정하지 않았다.

중요도는 사건 종류, 직접성, 관련 인물 감정, 경쟁 성향, 활성 목표와 비밀성으로 계산한다. 감정은 승리/패배/갈등 결과에 따라 별도로 기록한다. 이 중요도는 영향력·전투력·관계 수치를 변경하지 않는다.

과거 사건을 현재 위치로 다시 관찰하지 않는다. `recordMemoryFromEvent`는 현재 시각의 새 사건만 허용한다. 개발자 `replayObservedEvent`는 저장된 당시 참여자·목격자만 대상으로 하며 동일 기억 ID는 중복 생성하지 않는다. 초기 연결 때 과거 효과 로그를 모든 NPC에게 소급 배포하지 않는다.

## 망각과 회상

`config`는 `data/memory/index.ts`의 버전 규칙이다. 선명도100을 기준으로 `max(1,18-중요도×0.13-|감정|×0.035-min(4,회상수×0.2))`/일 감소한다. 확신도는 같은 감소량의 직접 경험15%·다른 출처50%로 감소한다. 마지막 강화 시각에서 정수 일수 계산을 하므로 UI 열람·분할 시간 진행 때문에 누적 반올림 차이가 생기지 않는다.

선명도50 이상 활성,20~49 흐릿함,20 미만 잊힘이다. 직접 경험의 주장은 망각으로 거짓말이 되지 않는다. 일반 검색/공유는 잊힌 기억을 제외한다. 회상은 실제 호출 때 확신도+4·중요도+2, 선명도 기준을 재설정한다. 직접 기억과 모순되는 소문의 회상은 낮은 확신 상한을 유지한다. 명시적 `forgetMemory`는 추가 회상을 차단한다. 단순 조회/AI 점수 계산은 회상 처리하지 않으며 XP·관계·목표 보상을 재적용하지 않는다.

## 실제 정보 대화

상호작용 카탈로그에 정보 공유/소문 전달/비밀 전달/정보 질문/정보 확인 요청5종을 추가해 기존18종과 함께23종을 사용한다. 동일한 동의·위치·실행기·15분 대화를 거친다. 요청만으로 정보가 전달되지 않는다. 완료 사건을 받은 뒤 보유 정보, 신뢰·친밀, 확신도, 중요도, 비밀, 신중/비밀/사교 성향, 장소 위험, 전달 경로를 평가한다.

수락 후에도 공유 보류/보유 정보 없음이 정상 결과일 수 있다. 비밀은 신뢰60 미만이면 전달하지 않으며 신중한 인물은 중요도75 이상 비밀을 보호한다. 거절/보류 때문에 자동 관계 벌점을 주지 않는다. 정보 확인 응답은 발언자의 지식이며 객관적 진실을 보증하는 조사 결과가 아니다. 없는 원거리 소통 수단을 가정하지 않는다.

전해 들은 확신도는 수신자→전달자 관계, 전달 단계, 의심 성향으로 계산한다. 확신75 이상 직접/목격 기억과 모순되면 소문 확신도를25 이하로 제한한다. 믿음 목록에는 모순 주장이 같이 남을 수 있고, 가장 높은 확신을 우선한다. 직접 경험과 소문이 같아진 것으로 정규화하지 않는다.

소문 전달은22% 확률로 승자 교환·심각도 과장·시점 오차·불확실성 과장 중 제한된 변화를 만든다. 제3의 새 사건이나 무관한 승자를 만들지 않는다. 개발자 강제 왜곡은 샌드박스 전용이다. 전달 계보는 최대8명이며 되돌아오는 순환 전달은 막는다. 비밀 보유자 목록은 실제 활성 기억에서 조회하고 전역 공개 상태로 바꾸지 않는다.

## 검색과 AI

소유자별 기억 집합과 인물/장소/주제/활동 인덱스를 유지한다. 관련 목표의 대상·추천 활동도 검색할 수 있다. AI의 `getNpcKnowledgeContext` 경로는 자기 관련 기억만 읽고 점수를 최대±12 보정한다. 패배를 기억하는 경쟁자는 재대련/훈련·도움 요청에 가산, 신중한 인물은 회피/대련 감점, 긍정/부정 경험은 교류·화해 등에 제한적으로 반영한다. 인지 범위 밖 상대 위치를 기억이 전지적으로 제공하지 않으며 의무/긴급/지속/접근 가능성 정책은 유지한다.

공유 후보는 숨겨야 할 비밀만 상위에 있어도 공유 가능한 공개 정보를 찾고 기존 사회적 욕구와 같은 효용 체계로 비교한다. NPC가 기억을 가졌다는 이유로 행동·목표 완료를 강제하지 않는다. 기존 관계 변화는 기존 효과 엔진만 처리한다.

## 공통 API

- `recordMemoryFromEvent`, `getCharacterMemories`, `getMemoriesAboutCharacter/Location`, `getMemoriesByCategory`, `getRelevantMemories({targetCharacterId,locationId,topicKey,activityId,goalId,limit})`.
- `recallMemory`, `forgetMemory`, `getKnownClaims`, `getBeliefAboutTopic`, `getMemoryClaim`(소유자 검사).
- `learnInformation`: 실제 저장된 관찰 자격 또는 자기 보유 활성 추론 근거(중복 없는 최대16개)가 필요하다. 다른 NPC에게 들었다는 기록은 실제 전달 경로로 만든다.
- `shareInformation(source,target,claimId,mode)`: 조건을 검사한 실제 정보 상호작용 요청. 질문/확인은 상호작용 요청의 topicKey를 사용한다.
- `evaluateInformationSharing/Trust`, `getNpcKnowledgeContext`, `getActionMemoryBias`, `getInformationCandidates`.
- `advanceMemoryDecay(from,to)`는 공통 세계 시계를 진행한다. 다른 엔진을 건너뛰는 별도 시간 누적기가 아니다.
- `inspectWorldFacts`, `getSecretHolders`, `getDeliveries`, `getDiagnostics`, `getStatistics`, `save/load/connect`는 개발자·게임 조합용 API다.

## 보존·저장·성능

인물당128개, 그중 중요 기억 상위32개를 우선 보호한다. 남은 공간은 잊힌/낮은 중요도/오래된 기억부터 정리한다. 모든 기억이 중요해도 무한 보존하지 않고 초과 정리 건수를 별도로 기록한다. 주장은40,000개·사실20,000개·14일 관찰 중복 키60,000개·전달 표시 이력2,000개로 제한한다. 전달 계보는 원본 인물/시각을 자체 보존하므로 중간 기억이 정리돼도 들은 정보가 목격으로 변하지 않는다. 표시 이력의 오래된 claim ID는 정리될 수 있다. 보유 소문이 참조하는 원본 사실은 같이 보존한다. 정리된 소문과 같은 사건 ID를 가진 원본 사실이 아직 참조된다면 삭제하지 않는다.

망각 조회는 마지막 강화 시각 기준의 지연 계산이고 보존 정리는 일일 예약에서 실행한다. 공통 시계는 각 이벤트에서 모든 참가자의 processAt을 호출하므로 정리 실행기는 자신의 예약 시각도 검사한다. 필요 이상으로 모든 기억을 매분 순회하지 않는다. 상호작용 후보 검사에서는 한 번의 조회 동안 같은 캐릭터 사본을 재사용하고, 욕구 후보의 동일 목적지 경로를 조회 단위로 공유한다. 이동 중 사용되지 않는 경로는 계산하지 않는다. 보상을 보존하는 결과 원장도 가장 빠른 만료 시각 이전에는 전수 순회하지 않는다. 읽기 캐시는 조회가 끝나면 폐기해 이후 상태 변경을 가리지 않는다.

기존 결과 키/사건은14일 정책을 유지한다. 100명 장기 실행을 위해 사건 키 용량만 설정값180,000개로 확장했다. 저장 형식·기존 보상 규칙을 축소하지 않는다.

`npc-memory-v1`에는 시드·시각·기억·주장·관찰 당시 대상·출처/추론 근거·비밀·강화 시각·처리 키·전달 이력·진단·누적 통계를 저장한다. 모든 참조/범위/계보/중복/용량/시각을 검사한 뒤 상태를 교체하고 인덱스를 재구축한다. `ai-sandbox-v1.knowledge`는 선택 필드로, 이전 저장은 빈 기억에서 시작한다. 실제 캠페인 저장 슬롯은 기존과 같이 아직 없고 통합 런타임 JSON 저장 어댑터를 제공한다.

직접 시각 설정은 중간 생활을 실행하지 않는다. 미래 설정에서는 망각을 계산한다. 개발자 과거 seek는 미래 지식을 남기지 않도록 기억 저장소를 비우며 과거 세계 복원은 전체 JSON/초기화로 수행한다. 테스트 화면은 과거 직접 설정을 거부하고 이를 안내한다.

## 도감과 테스트

설정집21번째 탭 `NPC 기억·정보`의 간결한 카드·공통 팝업·[테스트]를 사용한다. 테스트는 실제 세계·기억·상호작용·AI 엔진의 깊은 복제본에서 실행한다. 인물10/50/100 생성, 수동 가정 기억(정식 세계 사실 아님), 당시 관찰 기록 재생, 실제 정보 대화/보류, 강제 소문 왜곡, 같은 주제 모순 입력, 비밀, 회상/망각, AI 점수, 시간, JSON 저장/복원·초기화·종료 폐기를 지원한다. 공통 캐릭터 패널의 기억은 개발자 모드에서만 열람한다. 보통 게임 UI는 비밀을 무조건 표시하지 않는다.

검증 명령은 `test:academy-memory`, `test:academy-memory-browser`. 장기 실측은 `MEMORY_BATCH=1 MEMORY_COUNT=100 MEMORY_DAYS=30`이며 시간/메모리/저장량과 실제 지식 통계를 출력한다. 상세 결과는 [구현 보고](implementation-report.md)와 verification.json에 기록한다. 관련 기존 검사는 변경 범위에 맞춰 수행하며 전체 게임 브라우저 회귀는 반복하지 않는다.

복잡한 자연어/LLM 사고·평판/조직 정보망·의도적 거짓말·만남 예약·고급 진실 조사·장기 성격 변화는 후속 범위이며 기능 노트 v2/v3에 제안으로 구분한다.

최종100명30일 실측: 누적 기억253,801개, 보유12,800개, 정보 전달1,418회, 왜곡16회, 엔진 오류0건. 통합 실행/복원약150분·통합 JSON약90.7MB로 연산·저장 최적화는 후속 과제다. 중요한 기억의 초과 정리1,180건도 포함하며 무제한 보존으로 표현하지 않는다. [전체 검증과 성능 범위](implementation-report.md), [원시 집계](verification.json).
