# 행동 결과·효과 v1

`types/actionEffects.ts`의 판별 유니언과 `systems/actionEffects.ts`의 순수 미리보기/공통 적용 엔진. 초기 실행 조합은 `AiProvider`, 격리 저장은 `systems/aiSandbox.ts`. 이전 도감의 EffectDefinition/고유 효과 정의를 대체하거나 모든 SPECIAL_RULE을 자동 실행하지 않는다.

## API·효과

`createActionEffectsEngine(motivation, relationships, {seed,autoConnect})`:

- `resolveActionOutcome(characterId,activityId,minutes,sourceId,target?,targetId?)`: 완료 성장 효과 목록 생성. 이 API만 호출해서 보상이 지급되지는 않는다.
- `previewActionEffects(outcome)` / `validateActionEffects(outcome)`: 실제 원본을 변경하지 않고 변경 전/후·오류 계산.
- `applyActionEffects(outcome)`: `applied | already_applied | failed`, 변경 목록과 진단을 반환한다.
- `getGrowth`, `getActionOutcome`, `getCharacterActionHistory`, `getHistory`, `getEvents`, `getStatistics`, `registerCustomHandler`, `recordDomainEvent`, `save/load/connect`.

욕구 변화, 능력치 XP, 숙련도 XP, 방향성 관계, 표시 목표 진행도, 상태 적용/제거, 카르마/도덕, 등록된 순수 전용 처리기를 지원한다. 실제 자원 시스템이 없어 resource_delta는 명시적 미지원이다. 전용 처리기는 타입 안전 효과 목록을 반환하고 깊이/개수 제한을 적용한다. 조건은 필요 수치·상태·장소와 AND/OR/NOT. 알 수 없는 대상·정의·타입·조건은 실패한다.

효과는 임시 사본에서 계산·검증한 뒤 커밋한다. `domainTransaction`이 위치/관계/욕구 구독자 알림을 커밋 뒤로 미룬다. 커밋 중 오류면 관련 세계·관계·내면·성장·원장을 복구한다. 구독자의 **커밋 후** 오류는 observer 진단으로 반환하며 이미 반영된 결과를 재실행하지 않는다. 전용 처리기는 외부 부작용을 만들지 않는 순수 함수여야 한다. 트랜잭션은 동기식이며 중첩/async 사용을 허용하지 않는다.

## 성장·중복 효과 방지

버전 `action-effects-v1`의 **임시 런타임 성장 규칙**은 `config.ts`에 둔다. 기존 숙련도 카탈로그의 XP 임계값 null은 유지한다. 캐릭터의 잔여 XP는 별도 GrowthState로 저장하며 조건 충족 시 실제 Character.stats/proficiencyRanks를 변경한다. 특성 자동 진화는 없다.

능력치 다음 포인트 XP는 `ceil(30 + 현재값×0.6)`, 숙련도 0→9는 `[60,100,150,220,320,500,750,1100,1600]`. 신규 성장은 능력치200·경지9에서 멈추며 기존 고수치를 강제로 낮추지 않는다. 모든 kind에 동일한 규칙을 적용한다.

기본 시간당 성장 프로필 × 실제 완료 시간(보상 계산 최대3시간) × 피로 계수 × 성장 유형 × 학습 특성 × 장소 × 관련 능력치 × 지도 동료 × 시드 ±10%. 숙련 XP는 `1 + 경지×0.35`로 추가 감쇠한다. 지도 보정은 같은 장소의 2경지 이상 높은 공동 활동 동료에 한정한다. 기존 생성 metadata에만 있던 성장 유형은 선택적 generationGrowthType으로 공통 캐릭터에 보존하며 이전/고정 인물은 기본값1이다.

식사·취침·휴식·활동 중 피로는 기존 욕구 엔진이 실제 수행 시간만 적분한다. 완료 시 다시 회복시키지 않는다. 일반 활동의 완료 관찰과 공동 활동 결과는 분리하고 `ai/interaction/` 완료는 일반 보상에서 제외한다. 중단은 사건만 남기고 전체 완료 XP를 지급하지 않는다.

관계는 기존 5지표와 방향성 그래프를 사용한다. 방향별·지표별 하루 절대 변화량12 제한과 양의 변화에 친밀도 감쇠를 적용한다. 거절에는 자동 감정 벌점을 주지 않는다. 목표 진행도 변경은 증거를 대신하지 않으며 실제 능력/소속/관계/실행 근거로 재판정한다.

## 멱등성·사건·저장

결과 ID와 JSON 지문을 저장한다. 같은 ID/같은 내용은 already_applied, 다른 내용은 오류다. 처음 처리하는 결과는 현재 세계 시각만 허용한다. 원장은14일·최대30,000키, 도메인 사건 중복 키는180,000개로 제한한다. 보존 기간 이전의 새 결과는 거부하며 용량 초과도 명시적 오류다. 결과/사건 표시 이력은1,500/5,000개로 제한하고 누적 통계와 분리한다. 과거 재실행은 새로운 결과 ID만 만드는 대신 전체 세계 스냅샷 복원으로 수행해야 한다.

17종 타입 안전 사건은 실제 활동 시작/완료/중단, 상호작용 제안/수락/거절/완료/중단/실패, 관계/능력/경지/목표/상태/결과 변경을 기록한다. 발생 시각·인물·장소를 검증하고 고유 키로 중복 기록을 막는다. 세계 이벤트 발동/분기/랜덤 사건 생성은 없다.

`action-effects-v1` 저장에는 성장 잔여 XP, 적용 결과 지문/시각, 이력, 사건과 중복 키, 관계 일일 예산, 관찰한 활동, RNG 시드, 누적 통계가 포함된다. AI 통합 스냅샷으로 실제 위치·관계·욕구·목표·활동과 **같이** 저장한다. 결과 원장만 따로 복원하면서 세계를 되돌리는 것은 지원하지 않는다. 사용자 전용 custom 핸들러는 복원 전에 동일 ID로 재등록해야 한다.

설정집 `행동 결과·효과`/테스트와 캐릭터 개발자 상세에서 확인한다. NPC 내부 정보는 일반 UI에 무조건 공개하지 않는다. 실제 캠페인 저장 슬롯·장기 성장 밸런스·정식 전투/자원·세계 사건/기억 엔진은 후속 범위다.

기억 시스템 v1 이후 실제 사건을 `subscribeDomainEvents`로 커밋 뒤 전달한다. 만료 전 원장 전수 순회를 피하되 동일14일 정책과 결과 중복 검사는 유지한다.
