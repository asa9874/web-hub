# 상태 도감 — 콘텐츠·적용 계약

## 현재 데이터

| 분류 | 정의 수 |
| --- | ---: |
| 신체·부상 | 25 |
| 질병·생리 | 20 |
| 정신·감정 | 25 |
| 마법·저주·축복 | 30 |
| 변이·신체 개조 | 20 |
| 사회·환경 | 15 |
| 특수·초상현상 | 15 |
| **합계** | **150** |

150종의 고유 인게임 설명과 효과에서 생성하는 시스템 설명이 있다. 별도로 **38개 단계 설명**을 작성했다. 단계가 있는 16종은 부상·골절·화상·숙취·탈수·행복·공포·분노·침묵 저주·석화·마력 폭주·토끼 변이·흡혈종 변성·의체 손상·영혼 침식·존재 희박화다. 단계 명칭을 일률적인 희귀도로 통일하지 않았다. 좌우 부위와 단계는 상태 정의 수에 더하지 않는다.

독립된 개념인 열린 상처/출혈/과다출혈/순환성 쇼크는 원인·진행·처치와 효과가 다르다. 모든 상처가 출혈이나 절단으로 이어지는 것은 아니다. 행복과 슬픔은 공존하며, 변이·보호 붕대·의체에는 이점과 부담을 함께 담았다. 낭만적·기묘한 상태는 이름의 꽃잎, 색으로 새는 거짓, 한 박자 늦은 발자국, 문들의 기시감 등으로 분산했다. 정신 상태는 자율 행동의 **가중치 정의**로 표현하며 선택과 관계를 강제하지 않는다.

## 파일과 ID

- `types/status.ts`: 구체적 타입. `unknown` 규칙 없음. 안정적인 `status-*` ID와 정의 내부 단계 ID, 별도 `StatusInstance`.
- `config.ts`: 7대분류·세부 분류·극성·지속 방식·12부위·팔→손/다리→발/머리→얼굴의 관계.
- `define.ts`: 작성 헬퍼와 효과 설명. 구조와 기본값만 공유하며 인게임 문장·발생/회복/단계 설명은 각 콘텐츠에 직접 작성한다.
- `injury.ts` 등 7파일: 정의 원본. `labels.ts`는 표시용 대상 이름이며 효과 키를 변경하지 않는다.
- `index.ts`: 조건부 상태 경로. 일반적인 해제 경로는 각 정의에 작성한 회복 조건으로 구성한다. 영구/특수 상태는 자동 해제 경로를 만들지 않는다.
- `systems/statusValidation.ts`: 데이터·참조·단계·지속·중첩·효과·순환 검사.
- `systems/statusApplication.ts`: DEBUG와 미래 시스템에서 재사용할 순수 함수. 실제 사건/치료/시술/자동 시간 엔진이 아니다.

## 조건·단계·변화

발생, 회복, 악화와 변화 경로는 기존 `Condition` AST와 설명을 가진다. 현재 조건은 주로 고유한 flag ID다. 미래 사건 엔진이 사실을 확인한 후 해당 플래그를 제공해야 한다. 문구가 표시됐다는 이유만으로 조건을 참으로 처리하지 않는다.

단계 효과는 **기본 효과에 더하는 보정**이며 기본/단계 효과 ID를 분리한다. 다음 단계는 같은 정의 안의 ID를 참조한다. DEBUG의 수동 단계 변경은 조건 검사 없이 개발자가 상태를 재현하는 도구이지 실제 성장·악화 판정이 아니다.

상태 간 화살표는 사건 후보 참조다. 상처→절단은 회복 불가 손상과 별도 사건, 절단→기계화 팔/다리는 동의·적합성·시술 완료가 필요하다. 부위 유지 경로는 양쪽이 허용하는 부위에서만 사용할 수 있다. `body:clear` 경로의 목적지가 부위를 요구한다면 사건이 부위를 새로 지정해야 한다. 경로를 누르는 동작은 기록 이동만 하며 테스트 인스턴스를 변환하지 않는다.

현재 상태 간 경로는 순환 없는 그래프다. 향후 의도된 회복 루프를 넣으려면 해당 변의 `loop.id`와 `loop.reason`을 명시해야 한다. 검증기는 표시 없는 순환을 거부한다.

지속 방식은 시간/행동/치료/사건/조건/영구/특수다. `hours`는 시간형에만 있으며 임시 밸런스안이다. 남은 시간은 인스턴스에 복사하지만 **자동 감소하지 않는다**. 영구는 자연 소실이 없다는 뜻이며 별도 제거·교체 사건까지 불가능하다는 뜻은 아니다.

## 적용·충돌·중첩

`makeInstance`→`applyStatus`가 유효한 단계·부위·중첩을 검사한다. 변경은 `applyStatus(current,next,instanceId)`를 쓰며 오류 시 원본을 그대로 반환한다. 같은 상태는 캐릭터 또는 동일 부위마다 하나다. 단계 변경에 새 인스턴스를 추가하지 않는다. 독성 중독은 최대 3중첩으로 효과를 중첩마다 적용하며 재적용으로 남은 시간을 초기화하지 않는다.

- 생체 상태는 상실/의체 부위에 추가할 수 없다. 왼팔 상실은 왼손 기능까지 막고 오른손에는 영향이 없다.
- 절단·의체 같은 구조 변경은 덮이는 부위의 기존 생체 손상/상실 기록을 교체한다. 환지통이나 감정 등 독립된 상태는 남긴다. 이것은 임시 캐릭터의 일관성 검사이며 실제 시술 성공을 판정하지 않는다.
- 의체 손상에는 해당 부위 또는 상위 부위의 실제 의체 인스턴스가 필요하다. 손상된 의체를 다른 부위로 옮겨 손상 기록만 남기는 변경은 거부한다.
- DEBUG에서 의체 제거 시 의존하는 의체 손상도 제거한다. 제거는 임시 기록 삭제이며 원래 조직이 재생됐다는 뜻이 아니다. 미래 본게임은 장비·해부학 원장과 시술 사건을 별도로 연결해야 한다.
- 배타 그룹은 범위·우선순위·명시적 교체 허용을 사용한다. 같은 우선순위의 혹한/열기 노출은 함께 붙일 수 없다. 마력 봉인은 더 높은 우선순위로 마력 폭주를 교체하며 역방향 재적용은 거부한다.
- 실제 적용 엔진은 미래 사건의 원인 검증과 세부 해부학적 접합·시술·장비 조건을 추가해야 한다. DEBUG는 개발자가 고른 유효 인스턴스를 일시적으로 배치하는 도구다.

## 효과 재사용과 실행 범위

수치 효과는 기존 `Effect`를 재사용한다. 기존 `resolveEffects`의 입력 타입만 `id/effects` 구조로 넓혀, 특성·기프트 처리 동작은 그대로 유지한다. `resolveStatuses`는 동일 인스턴스 ID를 중복 계산하지 않는다. 기본/단계 효과와 중첩별 소스 ID를 분리해 필요한 보정이 소실되거나 두 번 들어가지 않도록 한다.

전신 공통 효과와 **부위별 효과 버킷**을 분리한다. 왼팔의 정밀 조작 불이익을 모든 오른손 행동에 자동 적용하면 안 된다. 미래 판정기가 필요한 부위·판정 종류에 맞는 버킷만 선택해야 한다. 정의된 기본 능력치 키는 STR 등 공용 ID를 쓴다. 기프트/특성과 독립된 인스턴스 소스로 함께 계산할 수 있으며 숙련도나 특성 단계를 바꾸지 않는다.

추가 효과는 행동 금지/허용, 부위 기능 제한, 자원 변화율, 고유 상태 규칙이다. `actionAvailability`는 명시한 행동과 필요한 부위를 검사하며 **금지가 허용보다 우선**한다. 금지 없음은 장비·자원·성공 조건 충족을 뜻하지 않는다. 자원 변화율·고유 규칙은 실행기에 전달할 정의만 표시하며 현재 자원을 감소시키거나 세계를 변경하지 않는다. 특수 규칙의 키·트리거·연산·대상·제약을 원본 DEBUG에서 확인한다.

관련 이벤트는 기존 21개 예정 이벤트 중 태그가 실제 일치하는 정의만 연결하며 `planned` 상태를 유지한다.

## UI·검증·이어받기

`/web-hub/games/academy-survival/?view=catalog&kind=status`로 접속한다. `&item=status-rabbit-form`으로 특정 기록, `&debug=1`로 임시 테스트를 연다. 이름 검색/대분류/세부 분류/성격/영구 여부/단계 여부는 URL에 저장되고 목록은 한국어 이름순이다. 임시 캐릭터는 브라우저 저장소에 저장하지 않는다.

```powershell
npm ci
npm run dev
npm run test:academy-status
npm run test:academy
npm run test:academy-knowledge
npm run build
# 상태 화면 입력/배치를 실제 확인할 때만:
$env:ACADEMY_TEST_URL='http://127.0.0.1:5178/web-hub'
npm run test:academy-status-browser
```

테스트는 150정의/38단계, 분류 수량, 고유 문장, 데이터 유효성, 12부위 참조, 부위 상하 관계, 생체/의체 충돌, 중첩·우선순위 교체, 단계/부위 변경, 전신·부위 계산 분리, 중복 적용, 행동 금지, 예정 이벤트와 순환 검출을 다룬다. 브라우저 검사는 이번 상태 화면의 필터/이름순/검색/빈 결과/URL 복원/관계 링크/DEBUG 조작/390px 배치 및 기존 네 탭 진입으로 한정한다. 다른 게임 전체 E2E는 영향 범위 밖이어서 반복하지 않는다. 기존 테스트·CI를 유지하며 상태 데이터 검사를 CI에 추가한다.

### 이번 구현 검증 결과

- 상태 데이터·적용 단위 검사 통과. 기존 특성/기프트 검사와 능력치/숙련도 검사도 공통 효과 입력 타입 및 설정집 통합의 영향 범위로 확인해 통과했다.
- TypeScript·Academy ESLint 통과. 상태 화면 브라우저 시나리오 전체 통과. 최종 한국어 효과 문구와 모바일 5탭 줄바꿈은 변경한 구간만 추가 확인했다.
- `npm run build` 통과. 38개 프로젝트·39개 OG 페이지·181개 로컬 HTML/CSS 참조 검증 통과. 기존 공통 CSS `.animate-*` 구문 경고와 번들 크기 경고가 남는다. Academy 페이지 청크도 콘텐츠 추가 후 약 517KB(압축 약 193KB)로 크기 경고 대상이며, 해당 페이지는 기존처럼 지연 로딩한다.
- 새로운 패키지나 외부 서비스 없음. 서버·DB·영구 저장·시간/사건 실행 엔진 없음. 다른 게임의 전체 E2E와 배포는 이번 범위에서 수행하지 않았다.
