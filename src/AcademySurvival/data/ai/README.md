# NPC 자율 행동 AI v1

설정집 `NPC 자율 행동 AI → 테스트`, `?view=catalog&kind=ai`, `?view=ai-tester`.

## 모듈과 책임

- `types/npcAi.ts`: AI 상태·후보·점수·실패·판단·공동 활동·저장 모델.
- `data/ai/config.ts`: 버전, 점수 가중치, 동기 감쇠, 최소 유지/전환 격차, 실패 대기, 활동 시간, 실제 특성·성향 ID 선호, 개인 습관.
- `systems/npcAi.ts`: 인지→후보 병합→실행 가능성→효용→의무/긴급→지속→선택→실행 및 제한 재계획.
- `systems/aiSandbox.ts`: 시간·위치·관계·일과 실행·욕구/목표·AI의 깊은 스냅샷/복원.
- `systems/npcSchedules.ts`: 별도 자율 의도를 일과와 같은 실제 이동/활동 실행 흐름으로 처리. 정의는 변조하지 않는다.
- `data/schedules/index.ts`: 실제 공동 대화·함께 공부·연습 대련을 추가해19활동. 전투 결과는 생성하지 않는다.
- `data/motivations/index.ts`: 공동 활동의 실제 수행 시간에 대한 사회·성장·피로 변화율. AI 안에서는 욕구를 직접 수정하지 않는다.
- `AiProvider`, `aiHooks`, `CharacterAiPanel`, `AiCatalog`, `AiTester`: 공통 세계 연결, 상세 상태창, 도감·격리 테스트.
- `scripts/test-academy-ai.mjs`, `test-academy-ai-browser.mjs`: 순수 엔진·결정론·공동 활동·복원·대량 실행 및 핵심 UI 검사.

## 선택과 실행

동일 활동·장소·상대는 하나의 후보가 된다. 같은 출처는 최대 동기만 남기고, 가장 높은 동기 + 두 번째×0.2 + 세 번째×0.1을 기반으로 한다. 설정의 선호·습관·관계·유지 보너스, 이동·위험·전환·최근 실패 비용을 더해0~100으로 제한한다. 점수 구성과 거부 이유는 디버거에 표시한다.

일과·욕구·활성 목표·현재 장소 활동·주변 아는 상대·신체/안전 긴급 상황을 읽는다. 욕구·목표 의도는 기존 동기 엔진에서 받는다. 경로는 실제 이동 엔진을 사용하고 도착 시각 출입·장소 활동 태그·수용량·상태의 BLOCK_ACTION을 검사한다. 의무 일정과 긴급 신체/안전 필요는 일반 점수보다 우선한다. 불가능한 후보는 선택하지 않는다.

최고 점수 근처5점 이내의 후보에서 인물/시드/판단 순번 난수를 사용한다.15분 기본 판단 주기·활동 종료·도착·상태 변화·일정 경계에 재평가하며 매 프레임/매분 모든 NPC를 판단하지 않는다. 기본 최소15분과 활동별 `minHoldByActivity`(대화10분·함께 공부20분 등)·전환 격차9점·유지 보너스8점과 활동의 중단 가능 여부를 고려한다. 이미 같은 긴급 행동을 수행 중이면 이동/활동을 재시작하지 않는다. 같은 시각의 재계획은4회로 제한하고 다음 분으로 넘긴다. 최근 실패는60분 대기와 비용을 남긴다. 직접 상태 변경 시 관련 실패 대기를 해제한다.

선택은 기존 일과 실행기의 `startAutonomousActivity`로 전달한다. 실제 이동은 장소 엔진이 수행하고 도착 후 기존 활동 기록이 시작된다. AI는 위치나 욕구를 중복 저장하지 않는다. 정상 일과를 선택하면 자율 의도를 해제하고 기본 실행기로 복귀한다. 의무 일정 이탈 사유와 복귀 가능성은 별도로 기록하며 실제 지각·미수행은 기존 일과 이력에서 조회한다. 성적·평판 결과를 지어내지 않는다.

실제 도감에 `성실함`/`게으름`이라는 정확한 성향은 없으므로 새 ID를 만들어 붙이지 않는다. 실제 원칙주의·완벽주의·쾌락주의·경쟁·사교·탐구·신중·충동 성향과 학습 복습/수면 회복 특성을 사용한다. 기본 의무 정책을 쾌락 선호 하나로 무시하지 않는다.

## 인지와 공동 활동

본인의 시간·상태·일과·목표와 현재 장소의 인물·이미 아는 관계만 판단에 사용한다. 원격 목표 상대를 동기 엔진이 제안하더라도 현재 인지 범위 밖이면 후보에서 제외한다. 전체 세계를 조회하는 디버거와 AI 인지는 별도다. 플레이어의 수동 수락 UI는 아직 없으며 AI 없는 플레이어에게 자동 공동 활동을 강제하지 않는다.

같은 장소에서 요청→수락/거절→양쪽 활동→종료를 처리한다. 상대가 의무·근무·수면·다른 공동 활동·긴급 욕구를 수행하거나, 강한 반감/두려움이 있으면 거절한다. 감정은 방향별로 읽는다. 참여자 부재·활동 변경·긴급 상황·의무 일정이면 양쪽 활동을 중단한다. 거절된 요청은 재시도 대기 후 다른 후보를 고려한다. 일반 자유시간에 사회적 욕구가 충족된다고 가정하지 않는다. AI는 사회적 욕구 의도를 구체적인 인지 범위 내 대화 후보에 연결하고, 공동 시간에만 욕구 엔진이 사회적 욕구 등을 줄인다. 감정 변화·대화문·대련 승패는 구현하지 않는다.

## API와 시간

```ts
const ai = createNpcAiEngine(motivation, { seed, relationships: graph });
ai.getState(id);
ai.getCandidates(id); // 조회는 실행하지 않음
ai.getPerception(id);
ai.evaluate(id); // 명시적 재평가
ai.evaluate(id, candidateId); // 디버그 강제 선택도 출입·의무·긴급을 우회하지 않음
ai.getJointActivities();
ai.getLogs();
ai.getStatistics();
ai.save(); ai.load(save);
```

시간 참가자 순서는 이동0 → 일과10 → 욕구20 → AI30이다. 욕구의 beforeStep은 구간 시작 활동을 적분하고 이후 사건을 처리한다. 하나의 세계 시계만 진행하며 AI가 NPC별로 시계를 늘리지 않는다.6시간 한 번과1분360회의 세계·욕구·AI 결과를 비교한다. UI의 큰 진행은60분 단위로 화면에 양보하며 초기화/종료 시 작업을 중단한다.

## 저장·격리

`npc-ai-v1`: 시드, 절대 분, 인물별 습관·판단 순번·현재 행동·다음 예약·실패·결정·이탈 기록·공동 활동. 위치·욕구는 원래 세계/동기 스냅샷에서만 저장한다. `ai-sandbox-v1`은 세계·관계·일과 실행·동기·AI를 함께 저장하고 같은 시각에 복원한다. 실행 도중 복원한 뒤 계속 진행한 결과를 비교한다. 원본 소스 상태는 수정하지 않는다. 잘못된 버전/시각/인물/활동/대상/습관 참조를 거부한다. 실제 캠페인 영구 저장소는 아직 없고 기존 런타임 저장 계약 위의 어댑터다.

## UI와 검증 범위

- NPC10/50/100명 생성, 기존 인물 선택, 실제 위치·활동, 후보 전체/점수 구성/실행 불가 이유.
- 욕구 변경·목표 추가/정지와 재평가, 유효 후보 강제 선택, 공동 활동/이탈/출결 조회.
-1분/1시간/6시간/1일/7일·직접 시간 설정, 실제 장소별 인원, NPC/유형별 최근100개 로그.
- 깊은 복제·초기화·종료 폐기·JSON 저장/복원,390px 배치.
- 단위 검사는 의무와 긴급 정책, 닫힌 장소, 원격 상대 미인지, 실제 공동 대화/거절, 최소 유지, 기존 특성 선호, 저장 이어 진행과 시간 단위 일치를 포함한다.
- 기본 검사는10/50/100명 각각7일이다. 개발 중 마지막 수정이 대량 분포에 영향을 주지 않는 경계 검증일 때 `AI_SKIP_BATCH=1`, 특정 수량의 재검증에는 `AI_BATCH_COUNT=100`을 사용할 수 있다. 기본 검사나 CI를 축소하지 않는다.

실측 결과는 `verification.json`에 기록한다. 이탈 수는 인물별 최근50개, 실패는 최근16개, 공동 활동 통계는 최근500건의 보유 기록 기준이다. 판단 횟수는 누적이며 로그는 최근1500건이다. 전체 게임의 장시간 E2E는 변경 범위 밖이므로 로컬에서 반복하지 않았다.

## 남은 범위

기억/정보·소문, 실제 대화 내용, 감정 변화, 전투 승패, 관계 진행/연애, 장기 계획·학업 성적·재산 사건은 후속 단계다. 역할별 성향 선호와 행동 시간의 밸런스는 초기값이며, 고급 경로 예약/혼잡 회피와 공간 수용량 보장은 기존 이동 엔진을 확장해야 한다. 공동 활동의 수락은 v1 규칙 판정이고 정교한 상대 협상 AI는 아니다. 실제 캠페인의 정보 공개·영구 저장은 별도 어댑터가 필요하다.

## 상호작용·결과 v1 연결 이후

새 AiProvider는 공통 상호작용 엔진을 주입한다. 이 경우 위 초기 3종 공동 활동 실행/통계를 독립 실행하지 않고 18종 카탈로그·수락·공유 인스턴스·실제 결과에 위임한다. 새 누적 상호작용/효과 실측은 ../interactions/verification.json에 별도로 기록한다. 기존 verification.json은 이 연결 이전의 AI 검사 결과다. 샌드박스 저장에 interactions/outcomes 쌍을 추가하며 내부 성장 시드와 중복 원장도 복원한다. AI를 멈춘 수동 테스트의 경과한 판단 예약은 저장 시 현재 시각으로 정규화해 재개한다. 상세 대화·정식 전투/부상·정보/기억은 여전히 후속 범위다.


## 기억·정보 v1 연결 이후

`NpcAiEngine`의 선택적 `knowledge` 어댑터가 소유자별 관련 기억을 조회해 효용을 최대±12 보정한다. 23종 상호작용 중 정보 대화5종은 지식 엔진이 보유 정보와 공유 조건을 검사해 후보로 제공한다. 후보 조회만으로 회상·관계 변화·보상을 실행하지 않는다. 인지 범위와 의무/긴급·활동 지속 정책을 유지한다.

이동 행동이 기존 정책상 반드시 유지되는 구간에는 비싼 후보 조회만 생략한다. 판단 횟수·예약·실제 선택은 바꾸지 않으며 최적화 켜기/끄기의 동일 스냅샷과 분할 시간 진행을 단위 테스트로 비교한다. 새 통합 결과는 `../memory/verification.json`, 모델·제한은 `../memory/README.md`에 기록한다. 위 AI 초기 검사 기록과 구분한다.
