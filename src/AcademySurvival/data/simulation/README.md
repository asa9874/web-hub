# NPC LOD·지역 활성화 v1 계약

진입: `systems/npcSimulation.ts`, 공통 타입 `types/simulation.ts`. 실제 AiProvider와 통합 샌드박스 양쪽에 연결한다. 관찰 화면은 상단 **시뮬레이션** (`?view=simulation`)이며 실제 상태를 복제한다. 영구 캠페인 슬롯이 생겼다는 뜻은 아니다.

## 권위와 정밀도

- 캐릭터·위치·이동: 기존 LocationWorld. 활동: 기존 Schedule. 욕구·목표·효과·관계·기억·세계 사건: 각각 기존 엔진. 관리자는 ID/정밀도/중요도/지역/명령만 보유한다.
- 0: 기존 Utility AI. 1: 실제 기본 일과·이동·욕구·목표·명시적 사건을 유지하며 일반 재판단 간격을60분으로 늘리고 무목적 주변 교류/정보 전달 후보 수집을 생략한다. 일과 경계·도착·실패·요청·긴급 필요에서는 다시 판단한다.
- 2: 목표·긴급·사건 후보와 필수 일과·명시적 임시 일정, 이미 진행 중인 활동을 처리한다. 일반 재판단 간격360분. 3: 일반 Utility 판단과 새로운 일상 일과를 실행하지 않되 이미 시작한 활동, 명시적 임시 일정, 실제 예약 이동·사건·공통 효과는 유지한다.
- 아카데미 직무(학생/교수/경비/교직원) 또는 현재 아카데미 내부 인물은 최소1, 다른 지속·주요 인물은 최소2. 중요도는 정밀도와 별개다. 기존 고유 NPC는 모두 영속이며 자동 삭제/재생성을 하지 않는다.
- 진행 중 이동·공동 상호작용·활성/대기 세계 사건은0으로 보호한다. 미래 예약 사건은 원래 큐에 남고 실제 시작 시 참여자만0으로 활성화한다. 일반 자율 활동은 기존 종료/중단 규칙을 사용하며 강등만으로 취소하지 않는다. LOD2/3에서 동순위 이상 명시적 필수 약속은 기존 자율 활동에 가려지지 않는다.

## 활성 영역

- 기본 지역은 아카데미/제국 수도/마왕성의 실제 장소 루트다. 깊은 루트가 우선하며 장소의 포함 관계와 이동 그래프를 섞지 않는다. 국가 전체를 근거리로 처리하지 않는다.
- 플레이어 현 위치와 이동 중인 실제 다음 구간의 양 끝에서 도보 연결의 기본 시간·지형으로 활성 반경5분/해제 반경10분을 계산한다. 이는 **연산 정밀도 범위**이며 출입 허가나 NPC 지식을 부여하지 않는다. AGI/상태·시간별 출입/실제 이동 시간은 기존 이동 엔진이 최종 검사한다.
- 반경 계산은 플레이어 구간/정책 기준으로 캐시한다. 최소30분 유지. 명시적 지역 활성화는 중요 사건을 삭제하지 않으며 정밀 인원 수를 임의로 잘라내지 않는다.
- 이동은 실제 그래프를 따른다. 제국-마계 사이에 없는 통로, 엘프 숲/외부 마을을 새로 만들지 않았다. 개발자 강제 배치는 별도 표시된다.

## 주민·기억·상태

- 인구는 명시적 데이터이며 초기 세계 인구를 임의로 확정하지 않는다. 개발 UI의10,000명은 샌드박스 집계다. 집계 수를 NPC 객체/AI 활성 수/실제 현재 인원과 합산하지 않는다.
- 주민은 `materializeResident(regionId, slot, factory)`가 기존 생성기를 호출하는 명시적 시점에만 개별화한다. ID는 지역/슬롯에서 안정적으로 결정되고, 생성 시드도 별도 키로 분리한다. 같은 슬롯은 이미 이동한 인물도 원래 ID로 반환한다. 다른 장소에 복제하지 않는다.
- 세계 사건/공동 상호작용에 참여한 background 인물은 persistent로 승격한다. 개별화된 이름·관계·목표·기억은 모두 유지한다. 무명 인구를 위해 상세 객체를 만들지 않으므로 휴면 삭제기가 필요하지 않다.
- 수행하지 않은 식사/교류/전투·소문·학사 성과를 사후 생성하지 않는다. 공통 욕구 적분과 목표 평가/기억 망각은 계속 연결된다. 휴면 NPC에게 가상의 식사로 욕구를 회복시키지 않는다. 재활성화 때 위치나 수치를 임의 복원하지 않는다.

## 결정성·저장

- `AiSandboxSave.simulation?`에 정책·인물·지역·주민 슬롯·핀·전환500건·개발 명령200건을 저장한다. 캐시와 복제 캐릭터를 중복 저장하지 않는다. 필드 없는 구형 저장은 기존 동작이며 `enableLod:true`에서 기존 NPC를 영속 분류해 정책을 초기화한다.
- 동일 정책/명령/시드에서 시간 분할과 일괄 결과가 일치해야 한다. 큐의 내부 힙 배열 순서만 정규화해서 비교한다. 정밀도 정책이 다르면 사소한 행동·대화 이력이 달라도 정상이며 확정된 사건/약속/이동/효과의 정합성은 유지한다.
- UI 조회는 난수를 소비하지 않는다. 시간 직접 설정은 기존 엔진의 seek 계약(이동/활동 재설정)을 따르며 LOD 유예·전환 시각도 새 기준으로 옮긴다. 저장 복원과 임의 시간 seek는 다르다.

## 통합 세계 실행·관찰 계약

- `systems/worldSimulation.ts`는 기존 엔진의 수명·시간 진행·명령을 조정한다. `createFreshAiSandbox`/`createAiSandbox`와 같은 엔진을 사용하며 복제 위치/욕구 상태나 두 번째 시계를 만들지 않는다. 엔진별 예약 큐가 진실의 원천이다.
- 순서는 이동0 → LOD5 → 일과10 → 욕구20 → 상호작용25 → 효과26 → 기억28 → 세계 사건29 → AI30. 동순위 명시 ID는 안정 정렬한다. `beforeStep`에서 직전 활동의 경과를 적분하며 같은 시각 후속 작업을 고정점까지 처리한다. 256회 반복·전체 경계 한도 초과는 오류로 중단하고 정상 스냅샷 저장을 거부한다.
- `command`는 기존 공통 API에 위임하고 승인/거부·실제 시각을 최근500건 보존한다. 개발 명령은 세계 사건과 별도다. 강제 배치만 경로를 우회하며 일반 이동·활동·상호작용·효과는 실제 계약을 따른다. AI 일시정지는 판단만 멈추고 일과/이동/욕구를 동결하지 않는다.
- `snapshot`은 `world-simulation-v1`에 기존 `ai-sandbox-v1` 전체 상태·명령·다음 ID를 담는다. 기존 통합 저장도 받아들인다. 재생 속도/벽시계 타이머/진단 측정치는 세계 저장 데이터가 아니다. 영구 캠페인 슬롯 UI는 별도 미구현이다.
- `getStatistics`/`getLogs`/`diagnose`는 세계 사실이나 난수를 바꾸지 않는다. 로그는 보존 범위를 명시하고 인물·장소·유형·시각·사건으로 필터한다. 이동/일과 로그의 장소는 로그 발생 당시 저장하며 현재 위치에서 추측하지 않는다. 진단은 자동 복구하지 않는다.
- UI는 기존 샌드박스를 확장하며 렌더 구독을 조정기 하나로 제한한다. 최대4회/초 게시와 짧은 작업 구간 사이 브라우저 양보를 사용한다. 이는 엔진 계산량 감소나7일 성능 목표 달성을 의미하지 않는다. 개별 도감 테스트는 그대로 유지한다.
- 검증: `scripts/test-academy-world-simulation.mjs`, `scripts/test-academy-world-simulation-browser.mjs`. 실제 범위·한계: `docs/academy/WORLD_SIMULATION_V1.md`.

## 검증과 한계

`scripts/test-academy-lod.mjs`, `test-academy-lod-browser.mjs`, `diagnose-academy-lod.mjs`. 실제 측정·미검증 범위는 `docs/academy/SIMULATION_LOD_V1.md`.

- 일과/욕구 적분은 아직 모든 등록 인물에 대한 기존 처리다. 완전한 lazy 구간 적분이나 원거리 상태 언로드는 구현하지 않았다. 감소한 비용을 해당 최적화의 성과로 표시하지 않는다.
- 학사 월/수업은 있지만 성적·진급·졸업·선거·정식 전투/headless 전투·플레이어 선택 자동 중단은 선행 실행 계약이 없다. 이들을 임의 구현하거나 완료 처리하지 않는다.
- 100명30일/360일·10년 저장 누적·1,000명 실제 휴면 객체·대표 환경7일 목표는 미검증이다. 이전 전체 정밀 검증 기록을 새 LOD 정책의 장기 검증으로 재사용하지 않는다.
