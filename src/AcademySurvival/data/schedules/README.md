## 데이터와 실행 상태

`ScheduleEntry`의 하루 시각은 0~1439분 정수, 시작 포함·종료 제외다. 종료가 시작보다 작으면 다음 날까지 이어지며 같은 시각은 거부한다. `CharacterSchedule`은 템플릿·역할·교대조·개인 시간 차·장소 바인딩·개인 덮어쓰기·날짜 한정 임시 일정·취소 ID를 저장한다. 정의에는 수행 결과를 기록하지 않는다.

`ScheduleIntent`는 날짜별 절대 시작·종료, 실제 목적지, 우선순위, 의무/중단 여부를 갖는다. `ActivityExecution`과 이력은 별도 저장하며 `planned/traveling/active/late/completed/skipped/failed/interrupted/idle`을 구분한다. 인물이 없거나 장소·활동 참조가 잘못되면 거부하거나 명시적 실패 사유를 남긴다. 미설정 거주지와 활동 장소 태그 불일치는 순간이동으로 보정하지 않는다.

## 템플릿·개인화

학생 평일·휴일·방학·입학 준비·평가 대비, 교수 평일·휴일, 경비 주간·야간, 교직원 근무일·휴일, 마왕성 근무자, 일반 생활 기준의 13종이다. 정규 수업은 08:30~12:00, 13:00~16:00. 학생의 학년별 실제 교실 1~4학년을 사용한다. `classId`가 실제 교실 장소일 때만 우선한다.

역할 판정은 실제 관할 조직이 맞는 교수/경비/교직원 직급, 학적과 아카데미 소속, 마왕성·마왕군 소속 순서다. 복수 역할의 우선순위는 설정에서 관리한다. 경비는 안정적인 ID로 주야 교대조를 고르고 직접 지정할 수도 있다. 학생의 전공은 검술·마법 훈련·학습 장소와 연결하며 은둔 성향 등 기존 실제 ID를 선택 활동에만 참고한다. 지원하지 않는 직무는 일반 생활 기준과 진단으로 남긴다.

평일/주말과 공식 월별 학사 구분을 공통 달력으로 판단한다. 방학에는 수업을 제거하고 시험 월은 대비 학습을 추가한다. 구체적인 시험일을 지어내지 않는다. 동일 시드·인물의 시간 차는 ±8분이며 식사·자율 활동 등 선택 일정에만 적용한다. 수업·의무 근무 시각은 고정이다.

## 시간·이동 실행

`createGameClock.subscribeTimeline` 참가자들이 다음 예약 시각을 제안한다. 시계는 전체 진행 구간의 가장 이른 예약으로 이동하며 이동 엔진(우선0), 일정 조정기(우선10)를 차례로 호출한다. 전체 진행에 대한 최종 변경 알림과 React 갱신은 한 번이다. 인물별로 시계를 진행하지 않는다.

일정 실행기는 인물별 다음 확인 시각을 이진 힙에 예약한다. 시작·종료·미리 출발할 시각·이동 도착·다음 날 경계를 처리한다. 역할/인물의 계획은 전후 날짜 캐시를 사용하고 변경 시 무효화한다. 모든 NPC를 매 프레임 또는 매분 일괄 실행하지 않는다. 현재 위치, 활동 상태, 이동 상태는 각각 독립적이다.

예상 출발은 실제 그래프 경로 비용으로 계산한다. 정적 접근 추정은 출발 후보 시각을 찾는 용도뿐이며 실제 이동 허가에는 사용하지 않는다. 최종 요청과 각 구간 도착은 기존 시간·소속·신분·허가·상태·이동 속도 조건을 다시 검사한다. 목적지에 도착하기 전에는 활동을 시작하지 않는다. 접근 실패는 로그와 수행 실패로 남고 가능한 다른 활성 일정으로 돌아간다.

충돌 순서는 우선순위 내림차순 → 의무 여부 → 시작 시각 → 안정적인 일정 ID다. 이미 시작한 중단 불가능한 일정은 끝까지 유지한다. 더 높은 일정이 선택 가능한 활동을 중단할 수 있으며 이전 일정의 종료 전인 경우만 재개한다. 종료 전 미도착/미실행 의무 일정은 미수행으로 기록한다. 지각은 실제 시작 시각과 예정 시각의 차이이며 수업 지각과 전체 활동 지각을 분리 집계한다. 실행기 연결 전의 과거 지각을 지어내지 않는다.

한 번의 생활 시간 진행은 최대31일, 로그는 최근5,000건, 이력은35일이다. 제한 초과는 시간 변경 전 거부한다. 시계 자체의 일반 연도 범위는 바꾸지 않았다. 직접 설정/되감기/불러오기는 마지막 정상 도착 위치에서 이동을 취소하고 새 시점의 일과 및 집계를 시작한다. 달력만 표시하는 독립 시간 테스트기에는 일정 엔진이 붙지 않는다.

## 재사용 API

```ts
const runtime = createNpcScheduleEngine(world, {
  seed: 'campaign/schedules',
  plans: batch.schedules,
  relationships: graph,
  intentGate: (intent, character) => ({ approved: true }),
});
runtime.getCharacterSchedule(id, absoluteMinute);
runtime.getScheduleAtTime(id, absoluteMinute); // 충돌 우선순위로 정렬된 후보
runtime.getNextScheduleEntry(id);
runtime.getUpcomingActivities(id);
runtime.getCurrentActivity(id);
runtime.addTemporarySchedule(id, entry); // absoluteDay 또는 현재 날
runtime.updateScheduleEntry(id, entry); // 동일 ID 대체
runtime.cancelScheduleEntry(id, entryId);
runtime.interruptActivity(id);
runtime.resumeScheduleEntry(id, entryId);
runtime.advanceNpcSchedules(previousTime, nextTime);
runtime.getSocialContext(id); // 친구·신뢰·지인 조회, AI 판단 없음
```

순수 생성은 `generateScheduleForCharacter(character, {seed,bindings,shift})`, 날짜 계획은 `getCharacterSchedule(character, plan, minute)`, 충돌 비교는 `resolveScheduleConflicts(intents)`다. 같은 ID의 임시 일정은 해당 날짜의 기본 일정을 대체하며 중복 발생 건을 만들지 않는다. 임시 일정은 종료가 이미 지난 시점에 삽입할 수 없다. 취소 ID는 이후 반복에서도 제외하며 같은 ID를 저장하면 복원한다. 중단/재개는 현재 유효한 발생 건에만 적용한다.

미래 욕구·목표 시스템은 `intentGate`에서 의도를 승인/거절하고 임시 일정이나 개인 덮어쓰기를 넣을 수 있다. 그 시스템이 별도 의도를 결정하게 두며 이 실행기에 욕구·관계 AI를 하드코딩하지 않는다. 학습 경험치, 식사 회복, 수면 회복, 자율 대화, 연애·전투·이벤트 효과는 구현하지 않는다.

## 샌드박스와 UI

진입 당시 세계의 절대 분·모든 캐릭터·계획·관계를 깊게 복제한다. 별도 시계·이동 엔진·일정 엔진·그래프를 생성하고 게임 저장소를 사용하지 않는다. 초기화는 진입 스냅샷으로 복원하며 종료는 폐기한다. 원본 세계의 시계/위치를 변경하지 않는다.

- 10/50/100명 생성, 학생 또는 혼합/개별 직무, 시드 입력. 비생도는 기존 성인 생성기를 재사용한 뒤 개발 역할·조직·허가를 명시적으로 부여하고 기존 직급에 필요한 소속은 보존한다. 세레나는 고정 보유 복제본만 사용한다.
- 하루·일주일 날짜 조회, 실제 활동·다음 일정·이동 소요·예상 출발, 공통 캐릭터 팝업.
- 시작/종료/목적지/우선순위/의무/중단 편집, 삭제·취소, 임시 일정, 강제 중단·재개. 강제 배치는 명시적인 개발 도구뿐이다.
- 1분/10분/1시간/6시간/1일/7일 및 날짜 직접 설정, 실제 통계/장소별 정지 인원. 이동 중 인물은 정지 인원에 중복 포함하지 않는다.
- NPC/유형/중요도 로그 필터와100/300/1000건 표시 제한. 상단 게임 날짜는 샌드박스와 별개로 유지한다.
- 모바일 세로 배치, 간결한 인물 선택, 재사용 팝업 유지.

## 확장 지점과 남은 작업

현재 앱에는 실제 캠페인/회차 저장이 없다. 일과 정의와 계획은 직렬화 가능하지만 실행 이력·예약 큐의 영속 저장 어댑터는 후속 작업이다. 소규모 메모리 세계에서 바로 재사용할 수 있는 엔진은 구현되어 있다. 지각에 따른 성적·평판, 세부 시험 날짜, 수면/식사 욕구, 교수별 강의 배정, 순찰 경유 지점 순환, 지원되지 않는 직업 프로필, 임시 통행 재개·대기·자동 우회 판단, 자율 친구 방문은 별도 시스템에서 확장한다. 현재 순찰은 지정 지점으로 실제 이동한 뒤 해당 위치에서 근무한다.


최종 검증: `npm run build` 통과(TypeScript, Vite,38프로젝트,39OG페이지,181로컬 참조). 기존 `.animate-*` CSS 문법·큰 청크 경고가 남아 있다. 새 일정 파일 전체의 범위 한정 ESLint는 통과했다. 날짜 한정 동일-ID 대체와 지원 연도 끝의 주간 조회를 보완한 뒤 일과표 검사 및 TypeScript/Vite·산출물 검사를 다시 수행했다. 전체 게임 E2E와 기존 모든 도감 브라우저 스위트는 영향 범위를 넘어 반복하지 않았다.
