# NEON TRADER — 오늘도 청산당했습니다!
## Codex 구현 명세서 v1.0

> 목적: 기존 `web-hub` React 프로젝트에 독립적으로 진입 가능한 완성형 웹게임을 추가한다. **정적인 UI 목업이 아니라 시작→거래→정산→상환→다음 날→엔딩까지 실제 플레이 가능한 게임**을 만든다.

## 0. Codex 작업 지시 및 우선순위

1. 기존 저장소 구조, package.json, 라우팅, 공통 스타일, 에셋 구조, 빌드·테스트 스크립트, 다른 게임 진입 방식을 먼저 확인한다. 기존 기능·라우트·메타데이터·디자인을 손상하지 않는다.
2. 프로젝트가 이미 쓰는 기술을 우선 재사용한다. 새 패키지는 필요성과 크기를 검토하고 최소한으로 추가한다. `src/NeonTrader/`는 예시이며 기존 컨벤션에 맞춘다.
3. 이 문서의 **MVP 필수 항목**을 우선 실제 구현한다. 대규모 추가 기능보다 완성된 핵심 루프를 우선한다. 구현하지 않은 기능을 완료했다고 보고하지 않는다.
4. 이미지 생성 도구가 사용 가능하면 아래 아트 규격에 맞춰 캐릭터·배경·아이콘을 제작한다. 사용할 수 없으면 임시 픽셀아트/프로그래밍 방식으로 대체하되 후속 교체 가능한 에셋 구조로 만든다. 이미지 생성 가능 여부를 임의로 가정하지 않는다.
5. 오디오도 실제 재생 가능한 형태로 구현한다. 별도 음원 없이 Web Audio 합성으로 시작해도 된다. 브라우저 자동재생 정책을 준수한다.
6. 게임 내 모든 돈은 **가상 재화**이며 실제 금융 API 주문·입출금·현금 결제·도박 기능을 만들지 않는다.
7. 코드·UI의 주언어는 한국어, 엔진 식별자/파일명은 영어를 사용한다.
8. 각 마일스톤 완료 시 실행/빌드/테스트를 확인하고, 변경 파일·완료 항목·남은 항목을 짧게 보고한다. 막히면 실패 원인을 남기고 다음 가능한 작업을 진행한다.

## 1. 게임 콘셉트와 플레이 경험

- 타이틀: **NEON TRADER: 오늘도 청산당했습니다!** (임시, 상수로 관리)
- 장르: 고속 가상 코인 단타 시뮬레이션 + 아케이드 점수 + 코미디 캐릭터 리액션 + 30일 빚 상환 캠페인.
- 서사: 주식·코인으로 빚 1억 원을 만든 자칭 천재 미소녀 트레이더. 플레이어가 거래를 맡고, 소녀는 옆에서 전문가 행세·훈수·흥분·패닉을 반복한다. 30일 안에 빚을 갚는다.
- 톤: 밝고 귀여운 코미디, 손실과 청산 때 과장된 반응. 지나치게 우울하거나 잔혹하지 않게.
- 플레이어가 느껴야 할 감정: 시장 읽기→진입 결심→포지션 긴장→수익/손실 반전→즉시 청산→효과음/표정 피드백→재도전.
- 시장이 플레이어 포지션을 읽고 고의로 반대로 움직이는 조작은 **금지**. 같은 시드와 같은 입력 조건에서 가격 경로가 재현되어야 한다.

## 2. 필수 플레이 루프와 캠페인

### 2.1 기본 캠페인
- 시작 빚: 100,000,000 KRW / 시작 가용자산: 1,000,000 KRW / 제한: 30거래일. 값은 밸런스 설정으로 분리.
- 1거래일: 기본 4분(옵션 3~5분), 시장 1분봉을 게임 시간 2초로 압축하는 기본 속도. 속도는 설정 가능.
- 하루 흐름: **시장 브리핑(짧게) → 거래 → 마감(포지션 정리) → 결과 화면 → 빚 상환 선택 → 짧은 캐릭터 대사 → 다음 날**.
- 상환액은 현재 사용 가능한 현금 범위에서 선택한다. 상환하면 빚과 현금이 동시에 감소한다. 빚을 갚은 돈은 거래 계좌로 되돌릴 수 없다.
- 거래 수익만으로 시작자산 100배를 달성해야 하므로 난이도 검증이 필수. 기본 캠페인이 비현실적으로 어려우면 **시작 빚/기한/변동성/목표 금액**을 데이터 기반으로 튜닝한다. 1억 원은 서사 기본값이며 플레이 가능한 밸런스가 우선이다.
- 빚 0원 → 승리. 30일 종료 시 빚 > 0 → 실패. 가용 자산이 최소 주문 증거금보다 낮고 복구 수단이 없으면 파산 엔딩.
- 하루 종료 시 열린 포지션은 사전 안내 후 **시장가 강제 정산**. 수수료/슬리피지 반영. 타이머 10초 전 경고.
- 시작/중단/재시작/다음 날/설정/도움말/엔딩 화면이 실제 동작해야 한다.
- MVP에서는 캠페인 외에 자유 연습 모드를 추가해도 좋지만, 캠페인을 먼저 완성한다.

### 2.2 거래 조작
- 3개 가상 종목: `BTC`(상대적으로 안정적 추세), `ETH`(중간~높은 변동성, BTC와 연관), `NYAN`(뉴스·군중심리에 민감한 고변동 밈코인).
- 후속 확장 3개(`TECH`, `MOON`, `INDEX`)는 데이터 구조만 고려, MVP 필수 아님.
- 종목 탭 전환은 즉시 가능. **전체 종목 통틀어 열린 포지션은 하나**. 다른 종목에서 진입하려면 먼저 현재 포지션을 청산한다.
- 단방향 순포지션: 롱 / 숏 / 포지션 없음. MVP에서 포지션 추가·반전 주문보다 명확한 **진입/청산**을 우선한다. 반대 방향 진입은 '기존 포지션을 먼저 청산하세요' 안내.
- 주문 금액은 **증거금** 기준, 비율 프리셋 10/25/50/100%. 레버리지 1/5/10/20배. 주문 전 예상 명목금액·수수료·대략적 청산가격 표시.
- 단축키: A=롱, D=숏, Space=청산, Q/E=증거금 비율 조절, 1~4=레버리지, Tab 또는 지정키=종목 전환. 텍스트 입력 중에는 단축키 무시. 버튼도 동일 기능 제공. 모든 조작에 명확한 피드백.
- 수익/손실은 실제 **가격 변동 × 수량**에 따라 결정. 레버리지는 증거금 대비 명목 포지션 크기만 결정하며 손익에 중복 곱하지 않는다.
- 수수료: 명목금액의 0.04%/체결(초기 밸런스 값). 스프레드와 유동성에 따른 작은 슬리피지. 현금·사용 증거금·평가손익·총자산 구분.
- 유지증거금과 청산가격은 일관된 단순 격리마진 모델로 구현. 청산 조건을 테스트하고 UI에 명확히 표시. 음수 현금, 무한 증거금, 포지션 중복 등 금지.
- 급격한 가격 변동에서도 틱 단위로 청산 판정. 손익·수수료 반올림 오차를 최소화하고 통화 표시는 별도 포맷터 사용.

## 3. 시장 생성 엔진 — 핵심 품질 요구

### 3.1 시간과 데이터
- 시장 계산은 `requestAnimationFrame` 렌더링과 분리된 고정 timestep(예: 50ms game-time step)으로 수행. 시간 압축 비율을 명시하고 한 프레임 지연으로 가격이 달라지지 않도록 누적 시간 처리.
- 표시용 가격 업데이트 10~20Hz, 차트 OHLCV 캔들 2초/1개 기본. OHLC 불변식 `high >= max(open,close)`, `low <= min(open,close)` 필수.
- 각 종목의 시드 기반 PRNG 사용. 동일 seed + 동일 이벤트 순서 + 동일 설정 = 동일 가격 경로. UI에서 난수 사용으로 시장 시드가 변하지 않게 분리.
- 시장은 플레이어 포지션과 무관하게 진행. 포지션 진입 여부가 뉴스나 가격 경로를 바꾸면 안 된다.

### 3.2 가격 생성
- 로그 수익률 기반 확률적 모델. 시장 공통요인 + 종목 고유요인 + 상태별 drift + 주문 압력 + 뉴스 충격 + 변동성 군집을 합성.
- 시장 상태: BULL, BEAR, RANGE, VOLATILE, REVERSAL. 상태 지속성과 확률적 전이(마르코프/준마르코프)를 사용해 매 틱 무작위 상태 교체 방지.
- 상승장: 추세 지속/되돌림, 하락장: 반등과 재하락, 횡보장: 범위 중심 평균회귀, 변동성장: 큰 양방향 진폭, 전환장: 기존 추세 약화와 방향 전환.
- 변동성은 직전 절대수익률의 지수평활로 조정해 volatility clustering 구현. 극단값에는 안전한 가격 상하한 및 비정상 틱 방어.
- BTC와 ETH는 공통 시장 인자로 양의 상관이 발생하도록 하고 NYAN은 고유 뉴스 충격이 더 큼. 상관이 항상 1이 되지 않도록 개별 잡음 추가.
- 거래량은 변동성, 이벤트, 시장 상태와 연동. 가격만 급변하고 거래량이 전혀 반응하지 않는 현상 방지.
- 추세/횡보/돌파/가짜 돌파/반등/급락/뉴스 후 되돌림 등 **관찰 가능한 패턴**이 자연스럽게 발생해야 함. 미리 정해진 정답 방향을 강제하지 않는다.
- 차트 생성 품질을 여러 시드로 테스트: 가격 양수/유한, 캔들 불변식, 비정상 급등락 비율, 시장 상태 지속성, 종목 간 상관, 뉴스 반응, 장기 drift.

### 3.3 뉴스 이벤트
- 뉴스: 제목, 영향 종목, 긍정/부정 강도, 신뢰도, 시작/최대 충격/감쇠 시점, 시장 반응 확률.
- 종류: 일반 뉴스, 호재, 악재, 루머, 대형 속보. 예: 규제 검토, 기관 매입, 기술 이슈, 거래소 장애, 유명인 발언.
- 뉴스는 플레이어의 포지션과 무관하게 스케줄. 일부는 2~4초 예고 → 발표 → 여파. 전부 예고하면 쉬워지므로 일부 돌발 뉴스 유지.
- 악재 = 무조건 하락 아님. 기존 추세/선반영/신뢰도/잡음에 따라 반등 또는 무반응 가능.
- 좌상단 뉴스 티커, 대형 뉴스 때 짧은 8bit 알림 + 네온 플래시(광과민 옵션 준수) + 캐릭터 한마디.

## 4. 음악 — 게임의 대표 기능 (MVP 필수)

### 4.1 원칙
- **Adaptive Chiptune / Vertical Layering**: 매 상황마다 음악 파일을 통째로 교체하지 않는다. 동일 BPM·마디에 맞춘 음악 레이어를 믹싱한다.
- 권장 132 BPM, 4/4, 4~8마디 루프. 8bit 게임기 느낌의 pulse/square, triangle bass, noise percussion, 짧은 arpeggio. 현대적인 저역/리버브는 절제하여 가독성 유지.
- Base layer는 거의 항상 유지, 추가 layer만 짧게 crossfade(예: 150~400ms) 또는 다음 박자/마디에서 진입. 위상과 박자 어긋남 금지.
- `AudioContext` 공통 시계로 정확한 오디오 스케줄링. 화면 FPS와 분리. 최초 사용자 클릭 이후 시작(autoplay policy). 탭 비활성화/일시정지 시 정지·복귀 정책 구현.
- 오디오 파일 방식 또는 Web Audio 합성 방식 중 프로젝트 상황에 적합한 것을 선택. 외부 유료/라이선스 불명 에셋 사용 금지. Web Audio로 실제 들을 수 있는 짧은 작곡 루프 우선.

### 4.2 레이어 및 상태
| 상태 | 음악 | 캐릭터 |
|---|---|---|
| IDLE | 킥 + 심플한 triangle bass, 둥… 둥둥… | 전문가인 척, 여유 |
| POSITION | base + 16분 하이햇 + 아르페지오 | 집중 |
| PROFIT_SMALL | position + 밝은 pulse 멜로디 | 슬쩍 웃음 |
| PROFIT_BIG | 밝은 리드 + 드럼 필 + 상행 장식음 | 눈 반짝/흥분 |
| LOSS_SMALL | 밝은 리드 제거 + 불안정한 화음 | 식은땀 |
| LOSS_BIG | 저음 불협화음 + 긴장 펄스 | 멘탈 붕괴 |
| LIQUIDATION_DANGER | 짧은 경고 비프, 음악 덕킹 | 패닉 |
| LIQUIDATED | 짧은 정적(0.2~0.4초) + 8bit 실패 징글 | 영혼 이탈 |
| REALIZED_PROFIT | 짧은 성공 징글, 콤보 시 변주 | 도야가오 |

- 상태 결정은 **미실현 ROE(증거금 대비 손익률), 청산까지 남은 거리, 손익의 변화 속도**를 활용. 예시 임계값은 +5/+25/-5/-25% ROE, 위험은 청산거리로 우선 판정. 튜닝 가능하게 설정.
- 0% 부근 반복 전환을 막기 위해 히스테리시스, 최소 유지시간(예: 0.6초), 상태 우선순위(DANGER > BIG LOSS > ...), 전환 쿨다운 구현.
- 큰 수익 실현/청산 등 이벤트 SFX는 BGM 위에 믹스. 동시 효과음 수 제한 및 순간 피크 리미팅.
- 마스터/BGM/SFX 볼륨, 음소거, 첫 방문 사운드 온보딩, 접근성 설정 저장.

## 5. 캐릭터와 코미디 반응

### 5.1 성격
- 자칭 천재 투자 전문가, 실제로는 청산으로 빚을 만든 허당. 수익은 자기 덕, 손실은 플레이어 탓. 그러나 후반에는 가끔 진심으로 격려.
- 캐릭터는 **실제 거래를 강제로 실행하거나 시장 방향을 조작하지 않는다**. 발언은 코미디성 훈수이며 확정적 투자 신호가 아님.
- 기본 캐릭터 외형은 제작 전에 일관된 기준 시트(머리·눈·후드티·실루엣·표정)로 확정. MVP 예시: 은빛 연보라 머리, 보라 눈, 검정 오버핏 후드티.

### 5.2 상태와 대사
- IDLE: 도야가오 — "후후, 관망도 실력이지."
- ENTRY: 집중 — "이 타이밍… 나쁘지 않은데?"
- PROFIT_SMALL: 신남 — "봤지? 내 분석대로야!"
- PROFIT_BIG: 광기 — "팔지 마! 아니 팔아! 잠깐!!"
- LOSS_SMALL: 현실 부정 — "건강한 조정이야. 아마도."
- LOSS_BIG: 패닉 — "왜 안 돌아오는데에!!"
- LIQUIDATED: 영혼 이탈 — "……오늘 저녁은 물이야."
- STOP_LOSS: 아쉬움 — "살아남는 것도 실력이지…"
- REPAYMENT: 빚 감소에 따른 특별 대사.
- 짧은 대사 버블은 거래 UI를 가리지 않는다. 이벤트 우선순위, 중복 방지, 발화 쿨다운(예: 3~6초), 중요 이벤트 인터럽트 구현.
- 표정만 바꾸지 말고 깜빡임, 호흡, 미세 흔들림, 눈 반짝, 땀, 책상에 엎드리기 등 2~4프레임 픽셀 애니메이션을 단계적으로 추가.
- 캐릭터 캠은 좌하단, 작은 방/모니터 빛/컵라면/고지서가 보이는 장면. 자산 증가/빚 상환에 따른 소품 변화는 후속 단계.

## 6. 비주얼 스타일 가이드 — 강제 규칙

### 6.1 해상도, 픽셀 크기
- 내부 디자인 기준 해상도: **480×270 논리 픽셀(16:9)**, PC에서 3x~4x 정수 배율 권장. 단, 텍스트·차트는 가독성을 위해 별도 고해상도 렌더 계층 허용.
- 픽셀아트 캐릭터/아이콘/배경은 nearest-neighbor 확대(`image-rendering: pixelated`). 블러 리샘플링 금지.
- 8×8 픽셀 그리드를 기본 단위로 하고 UI 배치는 4px 또는 8px 스텝. 픽셀 외곽선 1~2 논리 픽셀. **픽셀 스타일은 8bit 느낌이지, 반드시 역사적 하드웨어 제한을 그대로 재현한다는 뜻은 아님.**
- 캐릭터 캠 기본 논리 영역 예시 120×90px. 표정이 읽히도록 얼굴 크기 확보.
- 차트는 실용성을 위해 선명한 캔들/축/숫자 표시를 우선. 전체 화면을 픽셀화해 숫자를 읽기 어렵게 만들지 않는다.

- 패널은 1~2px 픽셀 테두리, 작은 코너 컷, 절제된 외곽 네온 빛. 중요한 이벤트만 순간적으로 강한 강조.

### 6.3 레이아웃
- 상단 왼쪽: NEWS TICKER(속보·경제 뉴스). 상단 오른쪽: 종목 탭, 현재가, 캔들 차트.
- 왼쪽 중단: 총자산/가용자산, 주문 증거금, 레버리지, 롱·숏 버튼. **중복 기능 버튼 금지**.
- 왼쪽 하단: 미소녀 캠, 표정·대사, LIVE 느낌의 픽셀 프레임.
- 하단: 현재 포지션, 진입가/현재가/미실현 손익/ROE/청산가격, 실현 손익·콤보, 빚/남은 날짜.
- 상시 정보 우선순위: 가격→보유 포지션 위험→진입/청산 버튼→남은 시간→자산→뉴스. 큰 이펙트가 가격/청산 버튼을 가리지 않도록.
- 반응형: 데스크톱 1366×768 기준 우선, 1920×1080에서 보기 좋게. 작은 화면에서는 차트 우선 배치, 스크롤 가능한 보조 패널. 모바일은 플레이 가능 최소 UI 또는 명확한 데스크톱 권장 안내.

## 7. 다이내믹한 Game Feel — 필수 연출

1. **즉각적인 입력 피드백**: 버튼 누름 80~120ms 시각 반응, 주문 체결 사운드와 숫자 팝. 입력 지연 체감 없도록.
2. **가격 움직임**: 틱 간 보간으로 부드럽게 이동하되 실제 체결가는 엔진 가격을 사용. UI 보간값으로 손익 계산 금지.
3. **Profit Juice**: 수익 실현 시 작은 숫자 팝업/파티클/성공 칩튠. 큰 수익은 단계적 팡파르. 지나친 화면 흔들림은 제한.
4. **Loss Feedback**: 손실 구간 진입 시 패널 테두리/캐릭터 표정/음악이 점진적으로 어두워짐. 패닉 상태에서 경고 펄스.
5. **Near Liquidation**: 청산가격 접근 시 짧은 심장박동형 8bit 펄스, 청산가 강조, 캐릭터 식은땀. 무조건적인 풀스크린 플래시 금지.
6. **Big News**: 속보는 뉴스 티커의 글자 등장 효과, 한 번의 8bit 알림음, 차트 위 작은 이벤트 마커. 플레이어의 시야를 차단하는 모달 금지.
7. **Micro-pause**: 큰 수익/청산 때 100~200ms 시각적 히트스톱은 허용하되 **시장 시뮬레이션과 거래 타이머를 몰래 멈추지 않는다**. 실제 일시정지는 명시적으로.
8. **Combo**: 연속 수익 실현 시 점수 배율/텍스트/징글 상승. 현금 수익에 직접 배율 적용 금지. 최소 거래 증거금과 수수료 고려해 미세 거래 악용 방지.
9. **Rhythmic UI**: 네온 테두리와 소형 이퀄라이저는 음악 박자에 반응. 그래프 자체는 음악 때문에 흔들리지 않음.
10. **Silence Contrast**: 강제청산 때 짧은 정적 + 실패음 + 캐릭터 영혼 이탈. 과한 반복으로 피로감 유발하지 않게.
11. **Controlled Intensity**: 시장 횡보 구간에는 연출을 줄이고 큰 뉴스/포지션 진입/위기 순간에만 강도를 높여 대비를 만든다.
12. **Accessibility**: reduced-motion, 플래시 최소화, 볼륨 분리, 색각 대비, 키보드 포커스, 텍스트 크기, 소리 없이도 이벤트 인지 가능.

## 8. 점수, 콤보, 난이도
- 자산은 현실적인 매매 손익만 반영, 아케이드 점수는 별도 계산.
- 점수: 실현 수익률, 위험 대비 수익, 빠른 거래, 적절한 손절, 연속 수익에 보너스. 단순 거래 횟수 무한 파밍 금지.
- 콤보: 연속 수익 실현 3회/5회 등 구간에서 UI·음악 강조. 손실 실현 시 리셋 또는 감쇠. 0원에 가까운 이익으로 콤보 파밍 불가.
- FEVER는 **점수·연출만 강화**, 시장 가격이나 거래 손익 조작 금지.
- 난이도는 시장 변동성/뉴스 빈도/스프레드/시간압박으로 조절하되, 유저가 포지션 잡으면 반대로 움직이는 고무줄 보정 금지.
- 튜토리얼: 60~90초 안에 롱, 숏, 청산, 레버리지, 수수료, 빚 상환을 익히도록 실제 거래 연습. 언제든 스킵/다시보기.

## 9. 엔딩과 재플레이
- GOOD: 기한 내 빚 전액 상환.
- BAD: 기한 종료, 빚 잔액 있음(채권추심원 문 두드리는 코미디 연출).
- BANKRUPT: 더 이상 최소 주문을 낼 수 없음(컵라면/정적 연출).
- SPECIAL(후속): 상환 후 큰 자산 달성.
- 종료 결과에 최종 빚, 최고 자산, 총 수익, 최대 낙폭, 거래 수, 승률, 최대 콤보 표시.
- 시드와 결과 기록 저장. 새로운 시드로 재시작 가능. 추후 일일 챌린지/랭킹 확장 고려.

## 11. QA 및 검증 — 완료 조건

### 자동 테스트
- 같은 seed에서 같은 OHLCV/뉴스 결과 재현.
- 모든 가격 유한·양수, OHLC 불변식, 거래량 음수 없음.
- 진입→평가→청산 시 현금/증거금/수수료 정산 일치.
- 롱·숏 손익 부호, 레버리지 적용, 강제청산, 하루 마감 강제정산.
- 다른 종목 중복 포지션 금지, 증거금 초과 주문 거절, 중복 클릭 처리.
- 빚 상환 후 자산/빚 감소, 엔딩 조건, 30일 제한, 파산 조건.
- 오디오 상태 히스테리시스, 중요 이벤트 우선순위, mute/볼륨 설정.
- 게임 pause/resume 및 새로고침 저장 복원.

### 실제 플레이 검사
- 첫 실행 후 1분 이내 거래 시작 가능.
- 한 거래일을 끝내고 빚을 갚은 후 다음 날까지 끊김 없이 진행 가능.
- 롱/숏/청산이 버튼과 키보드 모두 작동.
- 포지션 없음→진입→수익→손실→청산 위험→청산/실현 시 음악과 표정이 동기화.
- 뉴스가 시장에 실제로 영향을 주고, 항상 정답 방향을 보장하지 않음.
- 1366×768, 1920×1080에서 차트·주문 버튼·캐릭터·포지션 정보가 겹치지 않음.
- 볼륨 0에서도 플레이 가능, reduced-motion 모드에서도 주요 정보 표시.
- 개발 서버 실행/타입체크/빌드/테스트 성공. 기존 web-hub 라우트 회귀 확인.
