# 잊혀진 마녀의 극장 — 개발용 프로토타입

## 실행

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 5173
```

게임: http://127.0.0.1:5173/web-hub/games/forgotten-witch/

프로젝트 목록의 게임 카테고리에도 등록되어 있다. 새로고침 및 직접 URL 접근을 위한 초기 HTML과 프로젝트 OG 이미지는 기존 `generate-og-pages.mjs`가 빌드 시 생성한다. 작업 브랜치는 `feat/forgotten-witch-theater`이고, 다른 PC에서 받는 절차와 Codex 인수인계는 [codex/README.md](codex/README.md)에 정리한다. 공개 Pages는 main 병합 및 별도 배포 후 갱신된다.

## 선택한 기술

React + TypeScript + Vite 구조를 유지하고, 이미 설치된 `phaser3` npm alias (Phaser 3.88.2)를 재사용한다. Phaser 4를 쓰는 기존 통합 게임은 변경하지 않는다. 게임 페이지와 엔진은 동적 import로 분리한다. Phaser는 렌더링, 카메라, 입력 이벤트, 로딩, 스케일 관리, 트윈을 맡는다. 단일 무대의 지형은 작은 결정론적 이동/충돌 모듈로 계산한다. coyote time, jump buffer, 다리의 조건부 충돌과 입력 잠금을 독립적으로 검증하기 쉬운 선택이다. 추가 엔진, 서버, DB, API 키는 필요 없다.

## 조작 및 진행

- A/D 또는 좌우 화살표: 이동. Space: 점프.
- F/J: 매직 미사일. Shift/K: 전방 순간이동(230px, 0.18초 무적, 0.85초 재사용). Q/L: 전신 방어 유지.
- E: 가까운 장치/NPC 조사. 상호작용은 바닥에 서 있을 때 가능하다.
- Enter/Space 또는 버튼: 출력 완료 후 다음 문장 → 종료. 출력 중에는 넘기거나 즉시 펼칠 수 없다. 대화창의 속도 슬라이더로 0.6–1.8배 조절한다.
- 마우스: 종이 다리를 오른쪽 점선에 드래그. 스냅 뒤에는 실제 충돌 지형이 생긴다.
- 조명 팝업: 세 판넬을 드래그하여 배열하고 `조명 켜기`를 누른다. 달 → 별 → 꽃. 채워진 칸으로 드래그하면 두 판넬을 교환한다. 클릭 선택/빈 칸 클릭으로도 배치 가능하다.
- Esc: 퍼즐 닫기 / 탐험 일시정지 / 일시정지 해제.
- 소리 버튼: 무료 CC0 효과음 및 로컬 합성 말소리 켜기/끄기. 최초 사용자 제스처 이후 활성화된다.

입구의 떠 있는 발판은 아래에서 통과해 위에 착지할 수 있다. 마지막 낮은 장애물은 옆면도 충돌한다. 바닥 틈에 떨어지면 안전한 지점으로 복귀한다. 전투의 3라이프와 마지막 테스트 위치는 세션 상태이며 영구 저장은 없다. 다리/조명 해결 및 대화 방문 상태는 공연 중 유지되며 재시작/새로고침하면 초기화된다.

첫 대화에서 단서를 얻고, 조명을 해결하면 커튼 트윈과 무대 조명이 실제로 변한다. 열린 커튼 안으로 걸어 들어가면 완료된다. 조명 해결 후 플로라에게 돌아가면 별도 마무리 대화도 제공한다.

퍼즐 상태:

- 다리 `IDLE → ACTIVE → DRAGGING → SOLVED`. 잘못 놓으면 `ACTIVE`, 닫으면 `IDLE`, 해결 상태는 유지.
- 조명 `CLOSED → OPEN → CHECKING → SOLVED`. 오답은 `OPEN`, 닫으면 `CLOSED`. 팝업 타이머는 언마운트 시 취소.
- 탐험/대화/무대 조작/조명/일시정지/완료 입력 상태를 분리한다. 잠긴 상태에서는 이동 물리를 진행하지 않는다. 다리 판정은 인형 본체만 사용하며 조종 막대는 시각 표현이다.
- React StrictMode/HMR에서 async import 취소를 확인하고, 언마운트 시 Phaser 및 Web Audio 인스턴스, DOM/입력 이벤트를 정리하며 페이지 스크롤을 복구한다.
- Canvas의 `data-theater`는 실제 플레이 자동 검증용 읽기 전용 스냅샷이다. 상태를 수정하거나 퍼즐을 우회하는 테스트 API는 없다.

초기 v0.1의 퍼즐 무대를 유지하면서 사용자 추가 요청으로 별도 테스트 전투/3라이프/런타임 재등장을 확장했다. 인벤토리, 영구 저장, 멀티플레이, 서버, 여러 챕터, 복잡한 퀘스트는 구현하지 않는다.

## 아트 및 현재 범위

### 몬스터 / 보스 / NPC 리허설 확장

`테스트 → 테스트 위치`를 열면 무대의 물리/전투가 멈춘다. 몬스터 전투에서 일반 20종 또는 보스 `막간의 지휘자`를 선택해 소환한다. 일반 몬스터는 두 마리, 보스는 한 마리다. 다른 후보 선택/재등장 시 라이프/투사체/몬스터를 초기화하고 선택 종류는 유지한다. NPC와 대화에서 플로라 또는 새 NPC 6명(루미, 세린, 노엘, 미라, 이리스, 포피)을 골라 소환한 뒤 E로 대화한다. 새 NPC 테스트는 플로라의 기존 퍼즐 방문 횟수를 바꾸지 않는다.

공격은 근접/돌진/도약/조준 투사체/부채꼴/바닥 파동/정면 방어로 분류하고, 같은 패턴 안에서도 이동 속도·체력·크기를 달리한다. 모든 공격에 준비/실행/회복 시간이 있다. 방어형은 정면 방어 중 미사일을 막지만 후방과 준비/회복에 약하다. 보스는 HP 36, 돌진 → 부채꼴 → 양방향 파동을 순환하고 HP 절반 아래에서 탄막/파동이 늘어난다. 하단 이름/HP 바는 실제 전투 상태를 표시한다. 보스 처치 시 남은 보스 투사체를 정리한다. 나중에 추가할 보스도 `castData`의 정의와 패턴 모델로 확장한다.

새 몬스터는 독립 골판지 이미지에 코드 기반 기울기/바운스/준비 눌림/도약/돌진을 적용한다. 별도 프레임 시트는 사용하지 않는다. 주인공의 회피는 전방 순간이동이며 회전하는 구르기 인형은 비활성 후보로 보존한다. 전신 쉴드에는 별도의 지형 뒤 막대를 연결한다. 이동 수치는 `config.ts`, 공격/체력 수치는 `castData.ts`, 판정은 `combatModel.ts`에서 조절한다.

새 NPC는 각각 기본/기쁨/걱정/분노/당황 초상화와 SD 골판지 인형을 갖는다. 스타일 기준은 기존 `witch-portrait.png` / `witch-puppet.png`이며 런타임 표정과 음색은 `dialogueModel.ts`의 같은 화자/감정 키를 사용한다. 실제 생성 프롬프트는 `codex/npc-image-prompts.json`, `codex/monster-image-prompts.json`, `codex/roll-image-prompts.json`에 있다. 이리스 인형은 모자/지팡이를 제외하고 소리굽쇠와 골판지 외곽선을 맞춘 v3를 사용하며 수정 프롬프트는 `codex/iris-puppet-correction.json`에 있다. 등장/설정/사용 여부는 모두 후보 단계다.

설정집의 사물은 `paper.ts`의 모든 14개 소품/배경 텍스처, 가져온 나무·타이틀 프레임·공용 UI 재질, 조명 텍스처 4개와 `rig.ts`에서 실제로 그린 막대 미리보기를 포함한다(총 22항목). 후보용 나무도 표시한다. 코드가 바뀌면 `npm run witch:export-props`로 같은 Canvas 코드의 PNG를 다시 추출해 커밋한다. 인물과 몬스터는 해당 카테고리, 컷씬은 일러스트레이션에서 확인한다. 음악 6항목은 제목/설명/영문 Suno 프롬프트만 제공하며, 아직 생성된 BGM이나 재생 기능은 없다.

사용자 제공 레퍼런스의 보라색 SD 마녀와 두꺼운 종이 단면을 참고했다. 다른 PC에서도 볼 수 있도록 [codex/reference.png](codex/reference.png)에 복사본을 포함한다. 인형 2종, 주인공 걷기/점프 포즈 2종, 애니메이션 초상화 2종, 나무 1종은 실제 built-in image_gen 생성 에셋이다. 생성 프롬프트/투명 이미지 정리 이력은 `public/witch-theater/ASSETS.md`에 있다. 참고 시트는 배경으로 사용하지 않는다. 나무, 바닥/발판/다리, NPC, 캐릭터, 커튼과 조명을 개별 배치한다. 종이 소품 및 UI 장식은 프로토타입의 완성된 코드 기반 소재이며 누락된 임시 이미지가 아니다.

주인공은 실제 idle/walk/jump 이미지로 전환하며, 회전/바운스/착지 눌림을 함께 사용한다. 몸체 기준 피벗과 포즈별 연결점을 적용해 좌우 반전 시 몸체와 막대 위치를 유지한다. 막대는 고정 길이 사각형이 아니라 실제 변환된 연결점에서 화면 위/아래 경계 바깥까지 매 프레임 계산한다. 나무/발판/다리/꽃/장치/캐릭터/문 판넬은 아래로, 달/별/커튼은 위로 연결한다. 바닥 판넬은 이미 화면 아래에 닿으며 자체 지지대도 등록되어 있다. 배경 종이, 조명 효과, 글자 및 대화 초상화는 조종하는 인형 소품이 아니다.

대화 인물은 주인공의 기존 그림체를 기준으로 만든 `witch-knee.png`와 `flora-knee.png` 및 감정 표정 8종을 사용한다. 두 인물 모두 무릎 위까지 보이는 별도 그림이며, 좌우 독립 레이어로 대화창 뒤에 서 있다. 감정은 차분함/기쁨/걱정/분노/당황이다. 기본 표정은 기존 knee 그림, 나머지 4감정×2인물은 `public/witch-theater/expressions/`에 별도 image_gen 원본을 포함한다. 여러 방향 인형 에셋은 후속 폴리싱 대상이다. 배경은 손으로 만든 판넬이 같은 무대 안에서 반복되는 표현이다. 플레이 시간 3–7분은 첫 플레이의 읽기/탐색을 포함한 목표이며 타이머로 강제하지 않는다. PC 키보드+마우스가 대상이고 터치 전용 이동 버튼은 제공하지 않는다.

타이틀은 실제 인디 게임 UI를 조사해 큰 이름/세로 메뉴/주인공과 종이 극장 프레임으로 구성한다. 테스트·소리·일러스트레이션·설정집·허브 이동을 제공한다. 참고한 화면 및 출처는 [codex/UI-REFERENCES.md](codex/UI-REFERENCES.md)에 있다. 폰트는 로컬 고운바탕 타이틀과 SUITE 읽기 UI를 사용한다. 표현 전용 `StageLife`는 먼지/별/발걸음/착지/시계꽃 반응을 보강한다.

## 검증

메인 메뉴의 `일러스트레이션`에서 컷씬 후보 20점(일반 17점, chibi 3점)을 볼 수 있다. 각 작품의 상세보기에는 원본 그림과 제목/짧은 설명/실제 image_gen 생성 프롬프트가 있다. 이 장면들의 이야기는 제안이며 현재 플레이의 확정된 사건이 아니다. 새 작품은 `illustrations.json`에 등록하고 `public/witch-theater/cutscenes/`에 이미지를 넣는다.

## 대화 / 감정 연출 수정

`dialogue.json`은 각 줄의 `speaker`, `emotion`, `segments`로 구성한다. `dialogueModel.ts`의 EMOTIONS가 감정별 기본 cps(초당 글자 수)/합성 말소리 pitch/gain/duration, SPEAKERS가 캐릭터별 이름/기준 주파수/파형을 관리한다. `sound.ts`의 짧은 Web Audio 말소리는 녹음 음성이나 TTS가 아니며 API 키가 필요 없다. 마녀는 낮은 triangle, 플로라는 높은 sine 계열 톤이다. 공백/문장부호에는 소리를 내지 않고 음량 꺼짐을 따른다. 노드는 발음 종료 시 연결을 정리한다.

각 segment의 선택 설정: `cps`(출력 속도), `pauseAfterMs`(뒤에 쉬는 시간), `color`(CSS 색), `size`(본문 대비 em 배율), `weight`(굵기). 마침표/물음표/말줄임표/쉼표에는 기본 휴지가 있다. 구간 속도와 사용자 0.6–1.8배를 함께 적용하며 속도를 바꾸어도 대사를 다시 출력하지 않는다. 출력 도중 버튼/Enter/Space는 다음으로 넘어가지 않으며 입력을 큐에 보관하지 않는다.

```json
{"speaker":"witch","emotion":"angry","segments":[
  {"text":"하. 지. 마. 세. 요.","cps":9,"pauseAfterMs":400,"color":"#8b2838","size":1.18,"weight":700},
  {"text":" 같은 대본만 읽는 것. 네 말을 해."}
]}
```

첫 대화 14줄에 모든 감정/느린 분노/빠른 당황/단서 색·크기 강조 예시가 포함되어 있다. 표정은 발화 감정을 따르고, 말을 마친 상대는 마지막 표정을 유지한다. 초상화 편집용 실제 생성 프롬프트는 `codex/expression-prompts.json`에 있다. 본문은 로컬 SUITE Variable 25px/1.75 행간, 화자/본문/조작 영역을 분리한 낡은 종이 UI이다.

## 테스트 / 전투 / 설정집

`극장에 들어가기`는 본공연 준비 중으로 비활성화되어 있다. `테스트`가 기존 플레이를 시작한다. HUD의 `테스트 위치`에서 이동·점프/다리/플로라/조명/전투로 즉시 이동한다. 마지막 선택 위치가 라이프 소진 시 재등장 위치이다. 퍼즐 해결 상태는 유지하고 전투 상태는 이동/재등장 때 초기화한다. 퍼즐까지 초기화하려면 테스트를 처음부터 시작한다.

- F/J: 매직 미사일. Shift/K: 전방 순간이동(230px, 0.18초 무적, 0.85초 재사용). Q/L: 전신 방어 유지.
- 전투 무대는 기존 문 너머 별도 소품실(x 5050–6100). 몬스터 두 마리는 걷기 → 공격 준비 → 박수 공격 → 회복 상태를 가지며 세 번 맞으면 쉰다. 원본 3자세와 코드 기울기/바운스를 함께 사용한다.
- 플레이어는 종이 하트 3개. 피격 후 잠시 무적이며 0이 되면 실제 이동/전투를 정지한다.
- 귀여운 X눈 마녀/GAME OVER → 양옆 커튼으로 게임 무대 전체 덮기 → 닫힌 동안 선택 시작점/몬스터/라이프 준비 → 렌더 프레임 확인 → 커튼 열기 → 입력 복귀. 이미지는 테스트 시작 전에 로딩된다. 저장은 세션 내 시작점뿐이며 영구 세이브 파일은 없다.
- `설정집`: 등장인물/에셋/몬스터/설정 카드, 여러 스탠딩·동작·감정 그림 탐색, 특징과 마녀의 노트. 전부 임시 설정이다. `codexData.ts`로 내용을 관리한다.

모듈: `combatModel.ts`(로직/상수), `CombatStage.ts`(인형/미사일), `GameOver.tsx`(커튼/재등장), `Lives.tsx`(종이 하트), `CodexBook.tsx`/`codexData.ts`(설정집). `StageRig.detach()`는 수명이 끝난 동적 소품의 막대를 제거한다.

효과음은 Kenney 공식 CC0 무료 배포 원본 9개를 포함했다. 출처/사용 파일/팩별 라이선스는 `public/witch-theater/audio/README.md`. 캐릭터 말소리와 먼 박수는 합성음을 유지한다. OGG는 사용자 제스처 후 Web Audio로 디코딩하며 언마운트에서 fetch/context를 정리한다.


## 로딩과 무대 전환 (2026-10-14)

첫 진입은 `StageMotion.tsx`의 종이 소극장 로딩 화면을 보여 준다. 기존 마녀/플로라/박수꾼 SD 이미지를 재사용하고 코드 막대를 바닥 뒤로 연결했다. 엔진·로컬 글꼴 준비 20%, Phaser 핵심 이미지 파일 진행률 65%, 로컬 효과음 9개 다운로드 15%로 실제 완료를 표시한다. 모든 준비 후 로딩 화면이 페이드아웃한다. AudioContext 생성/OGG 디코딩은 클릭 등 사용자 제스처 이후이다. 로딩 중 이탈도 요청을 취소하며 종료된 씬은 start를 재개하지 않는다. BGM 파일은 아직 없으며 로딩 대상으로 표시하지 않는다. 효과음 요청 실패/15초 제한에는 합성음으로 계속할 수 있다. 핵심 이미지 실패는 재시도 UI를 유지한다.

`useStageTransition.ts`는 닫기 → 가림 → 실제 작업 → 열기 순서를 관리한다. 테스트 시작, 갤러리/설정집 열기·닫기, 재시작, 테스트 순간이동·NPC/몬스터 소환, 허브 이동에 적용했다. 커튼은 각 51% 폭으로 틈 없이 무대 전체를 덮는다. 가려진 동안 대상 그림을 미리 디코딩하고 실제 월드를 바꾼다. 허브 이동은 커튼이 닫힌 뒤 라우팅하며 허브에서 별도 오프닝을 재생하지 않는다. 중복 요청을 막고 타이머/물리/키 상태를 정리한다.

대화·조명·일시정지·테스트 목록·완료창은 `MotionPanel`의 짧은 등장/퇴장 페이드로 연결한다. 퇴장 중 DOM은 inert이며 탐험 복귀에 180ms 입력 잠금을 둔다. 구역 이름 3초 등장, 완료 체크의 도장 반응, 메뉴 다이아몬드·토스트·대화 버튼 반응, 공격 반동, 90ms의 작은 피격 흔들림도 추가했다. `prefers-reduced-motion`에서는 로딩 인형/환경 흔들림/피격 카메라/구역 자막을 줄이거나 끄고 커튼 시간도 단축한다. UI는 기존 1280×720 논리 좌표계와 함께 스케일한다.

검증 명령: `npm run test:witch-motion`. 실제 지연 응답을 사용해 로딩/SD 3개/제스처 전 오디오 미생성/전체 커튼 가림/입력 잠금과 복귀/팝업 퇴장/순간이동/reduced-motion/언마운트 정리를 검사한다. 기존 `test:witch`, `test:witch-expansion`도 전환 종료를 기다린 뒤 실제 입력으로 진행한다. 새로운 그림이나 BGM은 이 작업에서 생성하지 않았다.


## 빠른 이동과 동작 폴리싱 (2026-10-14)

## 생동감 요소 / 함정 실험실 (2026-10-14)

`테스트 → 테스트 위치 → 생동감·함정 실험실`에서 각 기능으로 이동한다. 실험실은 기존 무대·소품실 뒤의 x6400–11000이다. 기존 첫 챕터의 퍼즐/완료 경로는 유지한다. 데이터는 livingData.ts, 상태/이동 환경은 livingModel.ts, 실제 소품은 LivingStage.ts가 담당한다.

## 최신 조작: 순간이동 회피 / 전신 쉴드 (2026-10-14)

구르기는 전방 순간이동으로 교체했다. Shift/K를 한 번 누르면230px 앞의 실제 위치로 즉시 이동하고0.18초 무적/0.85초 재사용 대기를 적용한다. 닫힌 커튼·비밀 통로·낮은 고체 장애물·맵 경계를 넘지 않는다. 바닥 틈에 도착하면 실제로 떨어지며 다리 퍼즐을 우회하지 않는다. 출발/도착 종이 마법 고리와 작은 조각, 인형의 짧은 사라짐/복귀를 코드로 렌더한다. 회전하는 구르기 PNG는 런타임에서 사용하지 않고 설정집의 비활성 후보로 보존한다.

Q/L을 누르는 동안 전신 마법 쉴드로 방어한다. 게이지100, 타격당25 소모, 같은 지속 접촉은0.22초 간격으로 처리하며 라이프를 보호하고 공격 방향으로 살짝 밀려난다. 마지막 타격까지 막고 게이지0이 되면0.9초 쉴드 파손. 키를 놓은 후1.4초 지나야 초당22 회복하며,25 이상에서 다시 방어 가능하다. 방어를 계속 누르면 회복하지 않는다. 방어 중 이동은25% 속도, 공격/점프/순간이동은 제한한다. 휴식/재등장/테스트 위치 변경은 게이지를 초기화한다. 모달/커튼/일시정지 중 모든 방어 시간을 정지한다.

걷기의 잦은 AI 프레임 교대를 중단하고 원본 걷기 인형 한 장으로 작은 기울기·1.6px 바운스·착지 보간을 적용했다. 다른 후보 그림은 삭제하지 않는다. DefenseStage.ts의 코드 기반 쉴드/마법 렌더링과 combatModel.ts의 DEFENSE 수치는 분리되어 있으며 새 AI 이미지는 만들지 않았다. 입력은 input.ts, 벽 판정은 model.translateActor, HUD 게이지는 ForgottenWitch.tsx/Expansion.css이다.

테스트 → 몬스터 전투에서 Q/L로 막고 밀림/파손을 확인하거나 이동·점프에서 Shift/K 마법 회피를 확인한다. 자동 검증은 npm run test:witch-defense. 순수 실제 피격/게이지/회복/벽/바닥틈 계약과 실제 키보드 이동/쉴드 타격/게이지/일시정지/막대를 검사한다. 기존 회귀의 구르기 계약도 순간이동으로 교체했다. 이전 기록의 구르기 설명은 당시 버전의 이력이며 현재 조작은 이 문단을 따른다.

## 오프닝 시퀀스 — 2026-10-14

`극장에 들어가기`는 이제 실제 오프닝을 시작한다. `테스트`는 기존 기능 리허설을 바로 실행한다. 오프닝은 단일 Phaser 인스턴스에 추가한 OpeningScene에서 진행하며, 종료 후 기존 TheaterScene의 첫 챕터로 돌아간다. 새 서버/의존성/API 키는 없다.

- 도서관: 3.5초 독서 후 A/D 이동, E로 책장/시계/책상 조사. 점프와 전투는 허용하지 않는다. 오른쪽 낡은 책에 E를 누르면 카메라 이동/책 집기 후 컷신으로 이어진다.
- 컷신: 책 3초 → 얼굴 2초 → 폭주 3초 → 화이트아웃 4초(첫 0.5초 정적) → 추락 30초 → 착지/기상 15초. 크레딧은 8초 왼쪽/16초 오른쪽 공중 지점을 지나치는 방식이다.
- 튜토리얼: A/D 양방향 입력과 Space로 낮은 단차를 건너면 오른쪽 거대한 문에 E 상호작용. 적/손상/낙사 없는 독립 공간이다. 조작 안내는 월드 좌표에 떠 있고 입력에 반응해 접히거나 사라진다.
- 문/챕터: 5초 밀기 + 4초 문 열기 + 7초 숲/제목 + 4초 인게임 구도 복귀. 세 독립 숲 레이어를 실제 첫 챕터에도 잠시 유지하면서 기존 무대 소품을 드러낸다.
- 컷신 건너뛰기는 현재 연출을 안전한 튜토리얼로 넘기며, 문/챕터에서는 첫 챕터로 진입한다. 탐색 구간은 건너뛰지 않는다. Esc로 정지/재개, 장면 테스트에서 12개 지점 직접 진입. 첫 챕터의 일시정지 메뉴에서 오프닝 다시보기.

오프닝 음악/환경음은 원본 로컬 합성으로 제작했으며 녹음된 피아노/현악 BGM으로 보고하지 않는다. 추락 Mesh는 WebGL에서 가장자리만 미세 변형하며 Canvas에서는 같은 일러스트의 기울기/스케일을 사용한다. 스토리/독백/제작명(asa9874)은 임시 설정이다. 생성 에셋은 저장소 안에 모두 포함하며 다른 PC에서 npm ci 후 바로 실행 가능하다.

검증: `npm run test:witch-opening`. 상태 계약과 실제 키 입력으로 전체 오프닝, 안전 단차, 문/챕터, 재시청, 스킵, 직접 진입, 오디오 정리를 확인한다. 기존 일곱 Witch 회귀도 유지한다.

## 대화 카메라 · 무대 동작 · 지나가며 읽는 NPC (2026-10-14)

일반 대화는 인형 무대 확대를 기본으로 하며 기존 초상화 UI도 선택할 수 있다. JSON에 대사와 무언 cue를 섞어 카메라 확대/이동/추적, 인형 이동/동작, 실제 소품/종이 파티클, 대화창 숨김/복귀를 지정한다. 출력 도중이나 동작 진행 중 입력은 예약되지 않는다. 접근형/상호작용형 종이 말풍선 NPC 3명을 추가했으며 읽는 동안 탐험을 계속할 수 있다.

주인공과 플로라/루미/세린/노엘/미라/이리스/포피에게 각 4자세, 총32동작을 생성했다(8개 투명 시트). 테스트 위치에서 선택 NPC 연출 리허설/말풍선 NPC/골판지 동작을 체험하고, 설정집 인물 상세의 화살표로 각 프레임도 확인한다. 모든 대사/설정은 임시 리허설이며 원본 에셋/프롬프트/코드는 Git에 포함한다.

조정 위치와 데이터 예시는 [대화 연출 인수인계](codex/DIALOGUE-DIRECTION.md). 자동 검증은 npm run test:witch-direction. 다른 PC에서는 같은 기능 브랜치를 git pull --ff-only 후 npm ci / npm run dev로 이어받는다.
