# Chapter 01 — 막이 오르지 않는 숲

## 이어서 작업하기

현재 브랜치 `feat/forgotten-witch-theater`에서 `git pull --ff-only`, `npm ci`, `npm run dev`.
게임은 `/web-hub/games/forgotten-witch/`에 있다. `극장에 들어가기`는 오프닝을 거쳐 챕터로 이어진다. `Chapter 01 · 이어하기`는 브라우저 저장을 복구하고 직접 진입한다. 기존 `테스트`는 원래의 다리/조명/전투/연출 테스트 무대를 유지한다.

챕터의 `무대 지도` → 지역 버튼은 진행 상태를 유지하는 개발용 직접 진입이다. `챕터 처음부터 다시하기`는 Chapter 01 저장만 초기화한다. 오프닝 다시보기는 진행을 지우지 않는다. 저장은 이 브라우저의 localStorage에 있고 다른 PC로 자동 동기화하지 않는다. Git에는 코드/에셋/프롬프트가 모두 들어간다.

## 파일

- `chapter/ChapterScene.ts`: 별도 Phaser 씬, 실제 인형/소품/충돌 발판, 장치, 컷신, 카메라, 저장, 생명주기.
- `chapter/model.ts`: 저장 버전/검증/복구, 6지역, 자유 순서 퀘스트, 꽃 플랫폼, 입력 이동, 접기 순서/배치 정답.
- `chapter/story.ts`: 밝은 코미디 대사와 8종 필수 사건의 실제 인형 연출 큐. 호러/반복/비극 설정을 추가하지 않는다.
- `chapter/ChapterOverlay.tsx` / `Chapter.css`: 1280×720 논리 HUD/지도/퍼즐/피날레/완료 UI. 기존 Dialogue의 타이핑·감정·소리를 재사용한다.
- `chapter/textures.ts`: 종이 꽃, 당근, 소품, 재료, 주방, 세 배경의 코드 기반 재질.
- `chapter/music.ts`: 지역별 멜로디와 피날레의 원본 Web Audio 합성 음악. 기존 CC0 종이/장치 효과음을 병용한다.
- `public/witch-theater/chapter/*-poses.png`: 먹물 토끼/몽실/꽥 셰프 각4동작의 실제 생성 원본. 개별 알파 프레임은 Phaser 메모리에서 추출한다.
- `codex/chapter-image-prompts.json`: built-in image_gen의 정확한 프롬프트 및 상대 참조 경로.
- `scripts/test-witch-chapter.mjs`: 순수 계약 + 실제 키보드/마우스 전체 플레이.

## 실제 진행

1. 입구에서 플로라와 만남. 공연 준비를 부탁받는다.
2. 세 에피소드는 어느 순서로 해도 된다. 큰 꽃 옆 통행은 접어서 열거나 점프로 우회할 수 있다. 지도 직접 진입도 제공한다.
3. 꽃: 첫 꽃 접기 → 둘째 꽃 펼치기/높이 조정 → 작은 발판에서 꽃 위로 점프하여 줄자 획득 → 세 꽃 높이/방향 배치. 꽃의 높이와 펼침 상태가 실제 충돌면에 반영된다.
4. 배우: 배경을 드래그하여 설치 → 창고의 당근을 E로 주워 소품 자리에 드래그 → 조명 반사판 방향. 각 단계에 과장된 인형 연기를 연결한다.
5. 주방: 종이3묶음 수집 → 왕관/검/상자 도면의 방향대로3번 접기 → 과자로 셰프 주의를 돌리는6초 동안 안전 선반에 드래그. 실패하면 셰프가 들키고 다시 도전한다. 게임 오버는 없다.
6. 준비가 완료되면 중앙 대극장에서 공연 시작. 검 소품 → 꽃 지지대 → 조명 → 커튼을 직접 조작한다. 배우 개그/종이 꽃가루/박수/따뜻한 피날레를 보여준다.
7. 출구의 플로라에게 작별 인사를 하면 꽃 선물과 문이 열린다. 문으로 이동/E → 배웅 → 챕터 종료.

대화 출력 중에는 다음 문장 입력을 받지 않는다. `장면 건너뛰기`는 대화/연출 세션 전체를 종료하고 해당 장면의 완료 상태를 적용한다. `Esc`는 대화 중 정지, 장치 중 닫기, 탐험 중 일시정지다. NPC 옆의 잡담 버튼과 작업 장치 버튼은 별도로 사용할 수 있다.

## 저장과 복구

키: `witch-theater-chapter-01-v1`. 완료 단계/재료/접기/소품/꽃 배치/작별 준비/플레이어 위치/잡담 횟수를 저장한다. 장치 조작과 대화 종료 즉시, 탐험2초마다, 씬 종료 시 저장한다. 손상된 데이터는 새 상태로 복구한다. 피날레 실행 직후 새로고침한 경우 `show=4`를 엔딩으로 복원해 진행 불가를 막는다. 컷신의 순간 위치나 출력 중 글자 수는 저장하지 않는다. 새로고침하면 탐험 가능한 상태에서 다시 시작한다.

## 연출 원칙과 남은 조정

모든 소품은 독립 이미지/충돌/상태를 가지며 화면 끝까지 연결된 막대를 뒤에 둔다. 후경/중경/인형/전경을 분리한다. Chapter 01에는 기존 StageLife의 미스터리 동작을 사용하지 않는다. 토끼/양/오리는 별도의 애니메이션 초상화 대신 새 골판지 표정/행동4프레임과 코드 변형을 사용한다. 초상화 보기에서는 원본 시트의 단일 칸을 보여준다. 배경/장치 재질은 실제 코드 기반 에셋이며 임시 누락 이미지는 아니다.

35–50분은 명세의 첫 플레이 목표다. 읽기/탐색/재시도를 포함하는 사람의 플레이타임은 자동 검사로 확정할 수 없다. 현재 버전은 전체 흐름과 필수 장치를 검증하는 개발 빌드이며, 강제 대기 시간을 넣어 분량을 늘리지 않는다. 실제 플레이 피드백을 받은 뒤 잡담/환경 상호작용/퍼즐 난도를 조정한다. 다음 챕터는 구현하지 않았다. 타 지역 전투 테스트는 그대로 남아 있으나 이 밝은 챕터에는 전투/사망을 넣지 않는다.

## 검증 실행

```powershell
npm run build
# 별도 터미널
npm run preview -- --host 127.0.0.1 --port 4174
# 검증 터미널
$env:WITCH_TEST_URL='http://127.0.0.1:4174/web-hub'
npm run test:witch-chapter
npm run test:witch
npm run test:witch-opening
npm run test:witch-direction
```

챕터 테스트는 게임 상태를 주입하지 않고 UI 지역 이동, 실제 재료 줍기, 키 입력 점프/착지, 드래그/방향 조작, 대화 진행을 이용한다. 반복 디버깅용 `WITCH_CHAPTER_FAST=1`은 실제 스킵 버튼을 사용하는 단축 검사이며 정규 최종 검사와 구분한다. 스크린샷은 무시된 `.build-projects/chapter-*.png`에 저장한다.
공연 도중 새로고침한 경우 진행 중인 장치를 HUD의 공연 장치 버튼으로 다시 열 수 있다. 피날레 이후는 출구의 작별 인사로 복구한다.
NPC 상태는 npcPhase의 idle/approach/dialogue/questActive/questComplete/finale로 구분한다. 잡담은 진행도/개별 퀘스트 완료/공연 이후에 별도 대사로 분기하고, 완료된 인형은 기쁨 포즈로 바뀐다.
플레이 저장은 동일한 브라우저와 동일한 주소(origin)에서 복구된다. 개발 서버 포트나 Pages 주소가 달라지면 별도 저장 공간을 사용한다. Git pull은 구현과 에셋을 이어받으며 플레이 세이브를 동기화하지 않는다.

최종 화면 보수: 대화 카메라는 인형 얼굴이 대화창 위에 보이도록 이동하고, 꽃 작업창의 꽃 선택 버튼은 해당 꽃으로 카메라를 옮긴다. 새로고침 때 배경과 조명도 저장 진행도에서 복원한다. 재플레이는 배경/조명/문/카메라/연출 상태를 모두 초기화한다. 작별 인사 전에는 닫힌 출구를 실제 충돌로 막으며 선물을 받은 뒤 문이 열린다. 허브로 나가는 커튼 전환 중에는 챕터 이동도 잠긴다.
